# DECISIONS

- `2026-03-27`: Added persistent state files so `coachlink-wechat-app` context survives session resets and compaction better.
- `2026-03-27`: Project ownership must come from `IDENTITY.md` plus state files, not stale transcript memory.
- `2026-03-27`: `weapp-devtools` automation for this project must use fixed port `9420`.
- `2026-03-27`: Durable requirements, blockers, and handoffs must be written to files instead of relying on chat history alone.
- `2026-03-27`: `today-training` 小程序页继续按 Web 端口径对齐，优先补齐状态摘要、轻任务配置、快速完成、整日打卡、宽限期态与计划完成后动作。
- `2026-03-27`: 训练执行页完成训练后，使用本地存储回传 `today-training` 的确认提示状态，用于在返回页强化“确认完成 / e1RM 校准”的意义。
- `2026-03-27`: 自建计划在 `today-training` 页保留移除入口，行为应只影响自建计划，不影响教练计划模式。
- `2026-03-28`: 小程序 `today-training` 链路避免使用 `toLocaleDateString` / `toLocaleString`，统一改为手写日期格式化，降低 WeChat JSCore 运行时白屏风险。
- `2026-03-28`: “一键完成训练”入口放在 `training-execution` 页底部，不放在 `today-training` 外层；执行页底部保持单主按钮，按状态在“返回今日安排继续轻任务 / 一键完成训练 / 完成训练”之间切换。
- `2026-03-28`: 学员侧个人中心不展示 `我的钱包`；钱包保持为教练侧能力，不再从学生侧“我”页暴露入口。
- `2026-03-28`: 学员侧 `动作库` 升级为双标签结构：`我的动作库` + `公共动作库`；公共动作库至少支持浏览、搜索、点赞、加入我的库。

- `2026-03-28`: 学员侧 `知识库` 首页按 Web 端思路重排为四层结构：搜索、场景急救箱、身体部位入口、知识体系，再补充书籍与文章列表。
- `2026-03-28`: 学员侧 `购物车` 在个人中心弱化处理，保留 `购买记录` 作为订单历史主入口；购物车页明确其职责是“待结算订阅清单”而非历史订单页。
- `2026-03-28`: `工具箱` 补齐 `场景急救箱` 与场景执行页，先沿用 Web 端现有的 4 个高频场景模板。
- `2026-03-29`: 在继续补 `知识库` 之前，学生侧更高优先级的缺口依次为：`订阅/支付/续费闭环`、`学员 onboarding / 档案完整度闭环`、`计划入口信息架构统一`。
- `2026-03-29`: 学员侧计划入口统一按 Web 端口径收口为 `全部计划 + 训练记录`：

  - `全部计划` 主入口固定到 `/me/plan-history/index`
  - `训练记录` 主入口固定到 `/me/training-history/index`
  - `生成计划成功`、`生成计划异步提交后查看`、`训练计划完成后查看` 等回流动作，优先指向 `全部计划`
  - `/training/plan/current` 暂时保留，但降级为次级快捷页，不再承担学生侧主信息架构
- `2026-03-29`: `streetlifting` 子包页面跳转统一使用注册路径本身，不再手写额外尾部 `/index`；例如 `index/calculator` 应跳 `/streetlifting/index/calculator`，否则工具箱和街健首页会出现“点击打不开”的路由不匹配问题。
- `2026-03-29`: 学员侧入口顺序调整为：
  - 底部导航第 3 个 tab 使用 `工具箱`
  - 个人中心九宫格中保留 `排行榜`，不再重复放 `工具箱`
  - `工具箱` 页面内容顺序固定为“工具列表在上，场景急救箱在下”
- `2026-03-29`: `寻找单杠` 页面在移动端优先遵循“省流量 + 首屏先看点位”的策略：
  - 不为“有图优先”做全量列表预拉取
  - 仅在当前页结果内做“有图优先”排序
  - 分析模块保留在前面，但压缩成紧凑摘要，不再使用大块图表首屏占位
  - 地图相关能力按需触发：仅在用户点击“定位我附近”时请求当前位置和 `map-pins` 数据
- `2026-03-29`: `寻找单杠` 的“贡献排行榜”按运营化思路落地：
  - 排行榜以“上传次数 + 点位信息详细程度”生成综合贡献分
  - 读取方式从“前端现场聚合”升级为“后端聚合表直查”，避免排行榜查询过慢
  - 新提交单杠位置要自动记录当前贡献者标识；编辑默认保留原贡献者，避免误改归属
  - 顶部分析不再删减为过少信息，而是恢复完整分析项并压缩为可展开卡片
- `2026-03-29`: 小程序 `寻找单杠` 在保留列表页为主入口的前提下，补一个独立的 `全国地图` 页面承接全量点位分布；地图模式不替代列表页筛选/分享流程，而是作为独立浏览视图从列表页跳转进入。
- `2026-03-29`: 小程序地图模式优先采用原生 `Map` 组件 + 前端轻聚合，而不是直接移植 Web 端天地图脚本；这样更稳、更省流量，也更符合小程序运行环境。
- `2026-03-29`: `发现教练` 首页标题下方不再展示 4 个快捷入口图标（`服务市场 / 排行榜 / 智能计划 / 我的教练`），页面头部保留标题与搜索筛选区，减少首屏噪音。
- `2026-03-29`: 学员侧 `发现教练` 页面继续收口为更泛化的 `发现` 页面：
  - 底部导航与页面标题统一使用 `发现`
  - `热门动作` 横滑卡片只展示紧凑摘要，不直接铺开长段动作说明
  - `E2E Coach xxxx` 视为测试数据，不应出现在学员发现页可见教练列表中
- `2026-03-29`: 学员侧 `我` 页头像/昵称不能只依赖登录时缓存的 `user`；需在页面显示时按 Web 端口径用实时 `profile` 数据回填，并在资料编辑保存后同步刷新本地缓存，避免头像缺失或显示旧资料。
- `2026-03-29`: 计划编辑器的补齐不能按“教练模板页/学员计划页/学员自建页”分别零散修补；应先迁入 Web 端共享编辑引擎，再让三条链路复用，避免继续出现三套能力分叉。
- `2026-03-29`: 计划编辑器迁移优先级固定为：
  - 先迁 `WeekCalendar`、`PlanDayCard`、`BasicInfoForm/OneRMConfigPanel`、`SmartImport/BatchActions` 等共享能力
  - 再补教练模板库列表的搜索/筛选/复制/删除/批量操作
  - 再补教练给学员导入模板时的 `模板选择 + 开始配置 + 覆盖/新阶段` 流程
  - 最后补问卷联动、反馈驱动 AI 调整、执行视图增强等高级能力
- `2026-03-29`: 小程序计划编辑器正式收口到共享工作台 `src/components/PlanEditorWorkbench`，后续教练模板库与学员自建计划不再各自维护独立编辑表单。

  - 支持 `STRENGTH / CARDIO / DIET / HABIT` 四类条目
  - 支持周历编排、训练日复制、加周/删周
  - 支持动作批量替换 / 删除 / 追加
  - 教练模板支持标签、适用人群、周训练频率、问卷联动
  - 学员自建计划支持 1RM 配置、文本智能导入、AI 草稿

  - 先选模板
  - 再选导入模式 `overwrite / new_instance`
  - 再配置 `startWeek / startDay`
  - 最后结合 1RM 创建或覆盖实例
