# CoachLink AI 回归测试指令（幂等版）

你是项目内的自动化测试代理。请按以下步骤执行，使用可用工具操作前端与后端，验证系统主链路。

## 目标
- 验证登录、注册、会话维持是否可用。
- 验证学员个人计划（student plan favorite）基础 CRUD。
- 验证教练计划模板（coach template）基础 CRUD。

## 强制约束（必须满足）
- 每一个测试都必须幂等：测试结束后数据库状态与测试前一致。
- 任何创建的数据都要记录 ID，并在 `finally` 或等价清理阶段删除。
- 如果单步失败，也必须继续执行清理逻辑。
- 禁止跳过清理，禁止遗留测试账号/测试计划/测试模板。

## 推荐执行顺序
1. 通过测试 seed 接口创建临时学员与教练账号。
2. 前端交互测试：
   - 学员登录；
   - 校验 `/api/auth/session` 返回有效用户；
   - 刷新页面后再次校验会话仍存在。
3. 后端接口/数据库测试（学员）：
   - 调用 `save-favorite` 创建；
   - 调用 `get-favorite` 查询；
   - 调用 `update-favorite` 更新；
   - 调用 `delete-favorite` 删除。
4. 后端接口/数据库测试（教练）：
   - 调用 `create-template` 创建；
   - 调用 `get-template` 查询；
   - 调用 `update-template` 更新；
   - 调用 `delete-template` 删除。
5. 执行总清理：
   - 删除上述可能残留的数据；
   - 调用 cleanup 接口删除 seed 生成的用户/订阅/计划实例。

## 验收标准
- 全部断言通过。
- 清理完成后数据库无新增脏数据。
- 输出执行日志，包含创建与清理的主键 ID 对照。
