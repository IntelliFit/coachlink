# 微信小程序编译稳定性总结（2026-03）

## 适用范围
- 项目：`coachlink-wechat-app`
- 构建链路：`Taro 4.x + weapp + 微信开发者工具`
- 主要脚本：
  - `scripts/dev-weapp-with-fixes.js`
  - `scripts/fix-weapp-wxml.js`
  - `scripts/fix-weapp-comp-path.js`
  - `scripts/copy-comp-to-subpackages.js`

## 背景问题
近期出现过以下典型症状：
- 页面可跳转但白屏（如教练端“教练概览”标题出现、内容为空）
- 终端/开发者工具反复出现 `ENOENT ... .wxss`
- `dev:weapp` 日志持续刷屏，修复脚本重复执行
- `Warning: source file not found: comp.wxss`

## 根因复盘
### 1) 修复脚本执行时机错误（高优先级）
历史脚本采用“固定间隔轮询（每几秒强制执行一次）”去重写 `dist`。  
这会和微信开发者工具 / Taro watch 的编译线程形成竞争，造成中间产物被读取时文件尚未落盘，从而触发 `ENOENT`。

### 2) `comp.wxss` 在某些构建轮次缺失
后处理脚本默认要求 `dist/comp.wxss` 一定存在，但实际部分轮次可能没有产出该文件，导致告警和链路不稳定。

### 3) 页面样式被“未使用类”优化后，目标 wxss 可能不稳定
当页面仅使用内联样式、SCSS 中类未在 TSX 中实际引用时，个别页面的样式产物存在被优化/不产出的风险。

## 已落地的稳定方案
### A. `dev:weapp` 只在“构建完成”后触发修复
文件：`scripts/dev-weapp-with-fixes.js`

做法：
- 监听构建输出关键词（如 `built in` / `编译完成`）
- 每次构建完成后防抖执行一次修复脚本
- 修复任务串行执行，避免并发重写 `dist`
- 取消固定时间间隔的全量重复修复

目标：
- 减少与编译线程竞争
- 减少 `ENOENT` 概率
- 降低日志噪音

### B. `copy-comp` 增加 fallback + 增量写入
文件：`scripts/copy-comp-to-subpackages.js`

做法：
- 若 `dist/comp.wxss` 不存在，自动生成 fallback 文件
- 复制前比较源文件与目标文件内容，内容一致则不重写

目标：
- 消除 `source file not found: comp.wxss` 告警
- 降低无意义文件改写和连锁重编译

### C. 页面层约束：SCSS 类必须被页面真实使用
对关键页面（如 `coach/index`、`coach/wallet/bind`、`coach/wallet/order`）保证：
- TSX 中引入 `./index.scss`
- 至少一个 class 在页面中真实使用（不只写内联 style）

目标：
- 提升对应 wxss 产出稳定性

## 不建议做法（已验证会放大问题）
- 在 `src/**` 人工补大量 `index.wxss` 桥接文件试图“补洞”
- 通过定时器高频重复重写 `dist`（如每 2s/5s 强制跑修复）
- 每次修复都全量 copy 全子包文件，不做内容变化判断

## 推荐工作流
### 开发模式
```bash
npm run dev:weapp
```
- 启动 watch
- 每轮构建完成后自动执行后处理脚本（一次）

### 一次性构建
```bash
npm run build:weapp
```
已在 `build:weapp` 中串联修复脚本，无需手工逐条执行。

## 快速排查清单（遇到白屏/ENOENT时）
1. 看 `npm run dev:weapp` 是否仍在高频重复刷“Running fix scripts...”
2. 检查 `dist` 是否出现 `source file not found: comp.wxss`
3. 检查报错页面 TSX 是否：
   - `import './index.scss'`
   - 页面 JSX 是否使用了 SCSS 定义的类
4. 若报错是接口字段导致渲染异常，先做前端兜底（number/boolean 归一化）
