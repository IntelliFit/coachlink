# T07–T09 前端验证文档

用于验证 T07 即兴训练、T08 训练历史日历、T09 教练主页订阅续费的前端和交互预期效果。便于自查与 bug 定位。

> **前置**：需确保后端 API 可用，且小程序 `TARO_APP_API_URL` 指向同一后端。参考 [P0_MIGRATION_VERIFICATION.md](P0_MIGRATION_VERIFICATION.md) 的环境说明。

## T07 · 即兴训练

### 入口路径

| 场景 | 入口 |
|------|------|
| 无计划时 | 今日训练页 → 主按钮「**开始即兴首练**」 |
| 计划制定中 | 今日训练页 → 按钮「**即兴锻炼**」 |
| 有训练卡片时 | 今日训练页 → 训练卡片右上角「**即兴锻炼**」按钮 |

### 预期效果

#### 即兴训练配置页 `pages/impromptu-training/index`

| 区域 | 预期 UI | 交互与效果 |
|------|---------|------------|
| 顶部 | 标题「即兴训练」、返回 / AI 计划入口 | 返回 → 今日训练；AI 计划 → plan-lib/create |
| 训练项列表 | 默认 1 项，可添加、删除 | 每项：类型（力量/有氧/饮食/习惯）、动作选择、组数/次数/休息/重量 |
| 底部 | 「开始训练」「返回训练」 | 开始训练 → 调 `impromptuService.start`，成功后跳转训练执行页；返回 → 今日训练 |

#### 训练执行页（即兴模式）

- URL 带 `impromptuId` 参数
- **不显示**「跳过今日」按钮
- 完成组、完成训练、添加/删除额外组与动作均走 impromptu API
- 完成训练后正常返回

### 自检要点

- [ ] 三个入口均能进入即兴训练配置页
- [ ] 能选择学员动作库中的动作
- [ ] 开始训练后跳转执行页，且执行页识别为即兴模式（无跳过今日）
- [ ] 执行页完成组、完成训练流程正常
- [ ] 额外组、临时动作的添加/删除正常

## T08 · 训练历史日历

### 入口路径

1. **我的** → **计划历史**（`pages/me/plan-history/index`）
2. 顶部点击「**日历**」入口

或直接进入：`pages/me/training-history/index`

### 预期效果

| 区域 | 预期 UI | 交互与效果 |
|------|---------|------------|
| 顶部 | 月份显示（如 2026年1月）、上一月 / 下一月 | 点击切换月份 |
| 日历网格 | 7 列，每天显示完成次数（有则「N 次」） | 点击某天 → 下方加载当天训练明细 |
| 月份统计 | 训练天数、总次数、完成组数、来源占比（即兴/我的/教练） | — |
| 右上角 | 「即兴锻炼」入口 | 跳转即兴训练配置页 |

### 自检要点

- [ ] 月份切换正常
- [ ] 日历能正确显示有训练的天数及次数
- [ ] 点击日期能加载当日明细
- [ ] 月份统计数据与日历一致
- [ ] 即兴锻炼入口可跳转

## T09 · 教练主页 — 订阅续费与待支付

### 入口路径

1. **我的** → **我的教练** / 或通过教练列表进入
2. 点击某个教练 → 进入教练主页 `pages/coach-profile/index`

### 预期效果

#### 续费按钮

| 订阅状态 | 预期按钮 | 交互 |
|----------|----------|------|
| active / 正常 | 「订阅」或「已订阅」 | 按原逻辑 |
| expired / near_expiry | 「**续费**」 | 点击 → 调用 `renewSubscription`，进入续费流程 |

#### 待支付横幅

| 条件 | 预期 UI | 交互 |
|------|---------|------|
| 有 `pending_payment` 订阅 | 顶部黄色/橙色横幅：「您有待支付的订阅，点击复制支付链接」 | 点击 → 复制支付链接到剪贴板，Toast 提示「已复制」 |

### 自检要点

- [ ] expired / near_expiry 时显示「续费」而非「订阅」
- [ ] 续费流程可正常发起
- [ ] 有待支付订阅时顶部显示横幅
- [ ] 点击横幅能复制支付链接

## 常见可能问题

1. **T07 即兴训练 start 失败**：检查 `POST /api/impromptu/start` 请求体（actions 结构）是否符合后端要求。
2. **T08 日历无数据**：确认 `POST /api/training-history/calendar` 的 `month` 为 `YYYY-MM` 格式；后端是否返回 `days` 数组。
3. **T09 续费/待支付不显示**：检查 `subscriptionService` 返回的订阅状态字段（`status`、`pending_payment`）是否与后端一致。
