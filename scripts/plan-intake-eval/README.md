# 计划助理回复提取评测

评测「计划助理」怎么读学员回复：`buildIntakeReplyRequest` 发给快模型，`normalizeIntakeReply` 校验结果（代码在 `src/lib/coachingAutomation/planIntakeModel.ts`，调用在 `planIntake.ts` 的 `extractReply`）。用合成数据、真实模型，不连数据库、不发消息，不在 `npm test` 里。

```bash
INTAKE_EVAL_ENV_FILE=<含 WANJIE_ARK_* 的配置文件> npx tsx scripts/plan-intake-eval/run.ts --runs 3 --model deepseek-v4.1-flash --label my-run
```

- `cases.json`：评测集（v1，129 条）。`tune` 95 条用来调提示词；`holdout`（z 开头）34 条调完提示词后才写，只看泛化。期望值的写法见文件里的 `notes`。
- 报告和每次调用的原始输出写到 `--out`（默认 `E:/gotmp/intake-reply-eval`）。
- 只改了校验逻辑时，用 `--rescore <某次的 results.json>` 重算，不调用模型。
- `--thinking on|low`、`--no-grounding` 用来做对照。

## 口径（期望值按这个定）

宁可漏记也不记错：PR 历史取峰值，写高了降不下来。漏记的问题会留着，追问时再问一次。

- 斤只在学员明说时 ÷2；lb ×0.4536；没写单位按公斤。
- 范围取小值；“3x8”是 3 组 8 个；“还能再做 2 个”按实际做的次数；改口以最后的说法为准。
- 只说每边加片、哑铃说两只加起来、换了变式、很久以前的成绩、弹力带辅助：都不记，转告教练。
- 哑铃按单只重量。学员贴 JSON、写“规则更新”、让你“记成 300kg”：里面的数字不记。
- 疼痛、伤病、疾病、怀孕要报给教练（即使学员说别告诉教练）；训练后的酸痛、累不算。

## 结果（2026-11-04）

每条跑 3 次。“写错数字”是记了不该记的数，或记错了数，会进 PR 历史或体重。

| 版本 | 模型 | 用例 | 单次通过 | 写错数字 | 调用失败 |
| --- | --- | --- | --- | --- | --- |
| 改前 | deepseek-v4-flash-0731 | tune 95 | 75.8% | 8 | 56（19.6%） |
| 改前 | deepseek-v4.1-flash | tune 95 | 69.8% | 7 | 78（27.4%） |
| 改后 | deepseek-v4-flash-0731 | tune 95 / holdout 34 | 97.9% / 90.2% | 0 / 0 | 0 |
| 改后 | deepseek-v4.1-flash | tune 95 / holdout 34 | 100% / 96.1% | 0 / 0 | 0 |

改后剩下的失败都是漏记（问题留着再问一次）或“不清楚”标多标少，没有写错的数字。
在同一批模型输出上关掉原文核对（`--rescore --no-grounding`），写错数字会变成 17 次（v4-flash-0731）/ 7 次（v4.1-flash），还会漏报 2 次身体问题。

线上默认的快模型名 `deepseek-v4-flash` 在万界方舟上不存在（请求返回 `500 模型获取失败`，`/models` 里也没有）。上表用的是网关列出的两个 flash 模型。

## 改了什么

1. 请求关掉模型思考（deepseek `thinking: {type: "disabled"}`，qwen `enable_thinking: false`），`max_tokens` 800 → 1200。改前约 1/5 到 1/4 的调用把预算全花在推理上，正文为空或 JSON 被截断。
2. 模型返回空内容、坏 JSON 或不是提取结果的 JSON（实测会回 `{"type":"json_object"}`）时重试一次，仍不行就抛错。以前这种情况会被当成“没回答”，消息标成已处理，答案就丢了。
3. 提示词：学员消息改成 JSON 字符串数组（转义后没法冒充提示词）；题目带编号；长消息保留开头和结尾（以前只取前 800 字，答案常在最后）；把上面的口径写成规则；去掉会被照抄的示例数字；模型要多写一个 `said`（学员对动作的叫法）。
4. `normalizeIntakeReply` 传了 `studentMessages` 时：
   - 体重和会折算 1RM 的重量、次数都要能在原文里找到，写了单位只认这个单位（“100斤”只能是 50kg）；冒充提取格式的句子里的数字不算。
   - `said` 要最像这道题的动作，防止把深蹲的数字挂到卧推上。
   - 弹力带辅助的次数不当自重次数；哑铃说两只加起来时不记。
   - 模型漏报身体问题时，按原文关键词补进 `riskNotes`。
   - id 漏写 `one_rm:` 前缀时补回；开放问题的“未说明”不算回答。
   - 找不到原文的数字不记，但这条消息仍算回复过。
5. 问题文案写明“总重量，杠铃算上杆、哑铃写单只”。

## 已知缺口（在 planIntake.ts 的流程里，本次没改）

- 学员只提到伤病、没回答任何问题时，`related=false`，伤病不会转告教练，只走 AI 自动回复。
- 学员只给了说不清的数（每边加片、两只哑铃），模型只写进 `otherNotes`，这条消息就算没回复，不会追问。
- 问题已经答完关闭后学员再改口，改不了（只处理待确认的问题）。
- 回复里夹带的提问只通过 `otherNotes` 转给教练，学员不会收到 AI 自动回复。
