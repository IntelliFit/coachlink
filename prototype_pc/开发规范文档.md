# CoachLink 开发规范文档

## 1. 前言 (Introduction)

本文档旨在规范 CoachLink 项目（PC
原型）的开发流程与代码风格。遵循本规范有助于保持代码的一致性，降低维护成本，并防止在后续修改中引入错误。所有参与开发的工程师请务必仔细阅读并遵守。

## 2. 项目结构 (Project Structure)

项目采用清晰的分层结构，HTML、CSS 和 JS 文件分离。

```text
prototype_pc/
├── coach/                  # 教练端页面
│   ├── client-profile.html # 学员档案详情
│   ├── clients.html        # 学员列表
│   ├── dashboard.html      # 教练仪表盘
│   ├── library.html        # 动作库
│   ├── plan-editor.html    # 计划编辑器
│   └── templates.html      # 模板库
├── student/                # 学员端页面
│   ├── dashboard.html      # 学员仪表盘
│   ├── plan.html           # 训练计划查看
│   ├── execution.html      # 训练执行页面
│   └── profile.html        # 个人档案
├── css/                    # 样式文件
│   ├── main.css            # 全局变量、重置样式、通用工具类
│   ├── layout.css          # 布局相关（Sidebar, Header, Grid）
│   └── components.css      # 组件样式（Buttons, Cards, Inputs）
├── js/                     # 脚本文件
│   ├── app.js              # 核心应用逻辑（路由、导航渲染、UI初始化）
│   └── mock_data.js        # 模拟数据与本地存储逻辑
├── index.html              # 入口页（登录/角色选择）
└── 需求文档简略版.md        # 项目需求说明
```

### 规范要求：

- **页面文件**：根据角色放入 `coach/` 或 `student/` 目录。
- **样式文件**：
  - 全局变量和工具类放入 `main.css`。
  - 页面布局结构放入 `layout.css`。
  - 可复用的 UI 组件放入 `components.css`。
- **脚本文件**：通用逻辑放入 `app.js`，数据相关放入 `mock_data.js`。

## 3. 命名规范 (Naming Conventions)

### 3.1 文件命名

- **HTML/CSS/JS 文件**：使用 **kebab-case**（小写字母，连字符分隔）。
  - ✅ `client-profile.html`
  - ❌ `ClientProfile.html`, `client_profile.html`

### 3.2 CSS 命名

- **类名**：使用 **kebab-case**。
- **风格**：采用 **Utility-First**（工具类优先）与 **Semantic
  Component**（语义化组件）结合的方式。
  - **工具类**：`.text-center`, `.mt-md`, `.flex`, `.text-primary` (参考
    `main.css`)。
  - **组件类**：`.profile-section`, `.timeline-item`, `.nav-item`。
- **变量**：使用 CSS Variables (`--variable-name`) 定义主题色和间距。
  - ✅ `--primary-color`, `--spacing-md`

### 3.3 JavaScript 命名

- **变量与函数**：使用 **camelCase**（小驼峰）。
  - ✅ `currentUser`, `renderSidebar`, `initChart`
- **常量**：使用
  **UPPER_SNAKE_CASE**（全大写，下划线分隔），或者作为配置对象属性。
- **类/命名空间对象**：使用 **PascalCase**（大驼峰）。
  - ✅ `App`, `MockData`, `Store`

## 4. HTML 开发规范

- **语义化**：优先使用 `<header>`, `<nav>`, `<main>`, `<aside>`, `<section>`
  等语义化标签。
- **图标**：统一使用 **Lucide Icons**。
  - 用法：`<i data-lucide="icon-name"></i>`，并在 JS 中调用
    `lucide.createIcons()`。
- **内联样式**：**禁止**大量使用内联样式
  (`style="..."`)。仅在动态计算值（如进度条宽度）或快速原型验证时允许少量使用，稳定后应提取至
  CSS 文件。
- **注释**：主要区块应添加注释，如 `<!-- Sidebar -->`, `<!-- Main Content -->`。

## 5. CSS 开发规范

- **主题变量**：必须使用 `main.css`
  中定义的变量，严禁硬编码颜色值或像素值（特殊情况除外）。
  - ✅ `color: var(--primary-color);`
  - ❌ `color: #6366f1;`
  - ✅ `padding: var(--spacing-md);`
  - ❌ `padding: 16px;`
- **布局**：主要使用 **Flexbox** (`.flex`, `.flex-col`)，复杂网格使用 Grid。
- **响应式**：使用 `.container` 类控制最大宽度，确保页面在大屏下不失控。

## 6. JavaScript与数据规范

### 6.1 核心架构

- **App 对象**：`js/app.js` 中的 `App` 对象负责全局 UI
  逻辑（如侧边栏渲染、高亮当前导航）。
- **Store 对象**：`js/mock_data.js` 中的 `Store` 对象负责数据读写。
  - **读取数据**：`const clients = Store.get('clients');`
  - **写入数据**：`Store.set('clients', newClientsArray);`
  - **持久化**：`Store` 封装了
    `localStorage`，页面刷新后数据应保留（除非清除缓存）。

### 6.2 数据流向

1. 页面加载时 (`DOMContentLoaded`)，从 `Store` 获取数据。
2. 渲染 UI。
3. 用户交互触发数据变更。
4. 调用 `Store.set()` 更新数据。
5. 重新渲染 UI 或跳转页面。

### 6.3 模拟数据 (Mock Data)

- 所有初始数据定义在 `MockData` 对象中。
- 新增数据字段时，请同步更新 `MockData`
  中的结构，确保所有页面都能获取到一致的数据结构。

## 7. 修改与维护流程

1. **新增页面**：
   - 复制现有的类似页面（如 `dashboard.html`）作为模板。
   - 保留 `<head>` 中的 CSS/JS 引用。
   - 修改 `<body>` 内容，保持 `.app-layout` 结构。
   - 在 `js/app.js` 的 `renderSidebar` 函数中添加新页面的导航项。

2. **修改样式**：
   - 优先查找 `main.css` 中的工具类是否满足需求。
   - 如果是通用组件修改，编辑 `components.css`。
   - 如果是页面特有样式，可以在 HTML `<head>` 的 `<style>` 中编写，或在
     `layout.css` 中添加带页面前缀的类。

3. **修改逻辑**：
   - 通用逻辑（如导航、头部用户信息）修改 `js/app.js`。
   - 页面特定逻辑（如图表初始化、按钮点击）写在 HTML 文件底部的 `<script>`
     标签内。

## 8. 注意事项

- **不要破坏文件引用**：确保 `../css/` 和 `../js/` 的相对路径正确。
- **保持一致性**：新增 UI 元素时，请参考现有元素的 HTML 结构和 CSS 类名。
- **测试**：修改后请同时检查 **教练端** 和 **学员端**
  的相关页面，确保没有引入回归错误。
