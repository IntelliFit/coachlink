 **“CoachLink 学员-教练握手协议 v1.0”**。

为了方便你的团队成员（前端/后端）直接执行，我将你的思路转化为一份详细的**功能实施规范**：

### 核心实施方案：通用档案 + 差异化问答

#### 1\. 学员端：公共档案系统 (The Common Passport)

这是学员的“底座”，一次填写，全平台通用。

  * **基础信息 (Base Info)**：
      * 所有用户必填：头像、昵称、性别、年龄、身高、体重、伤病史（关键！）、生活作息。
  * **运动卡片 (Sport Cards)**：
      * **交互逻辑**：
        1.  用户在“编辑档案”时，可以看到一个“标签选择器”（如：`[ ] 力量举` `[ ] 健美` `[ ] 减脂` `[ ] 跑步`）。
        2.  **选中即激活**：选中“力量举”，下方立即展开“力量举卡片”的填写区；取消选中则折叠/隐藏。
        3.  **多卡片并存**：用户可以同时是“力量举爱好者”和“跑步爱好者”，主页会按顺序堆叠展示这两张卡片。
      * **卡片类型定义 (Schema)**：
          * **力量举卡片**：深蹲/卧推/硬拉 1RM 数据。
          * **健美/形体卡片**：胸围、臂围、腰臀比、体脂率、正/背/侧照片位。
          * **一般体能卡片**：引体向上个数、静态心率等。
  * **数据价值**：教练点开学员主页，一眼就能看到这些卡片，直接对齐学员的基础水平。

#### 2\. 教练端：服务设置 (Service Setup)

  * **功能入口**：教练设置 -\> 服务与定价 -\> 入队问卷设置。
  * **交互形式**：
      * 系统提供一段**强提示 (Hint)**：“请不要询问身高、体重、伤病史等基础信息，这些将在学员档案中自动展示。请专注于询问个性化需求、训练频率、器材限制等。”
      * **问答列表配置**：简单的字符串数组编辑器。
          * `[ + 添加问题 ]` 按钮。
          * 例如输入：`1. 你一周能练几天？`
          * 例如输入：`2. 你的健身房有深蹲架吗？`
  * **数据存储**：存为 JSON 数组 `["Question A", "Question B"]`。

#### 3\. 握手流程：订阅与需求确认 (The Handshake)

当学员点击“订阅/购买”时：

  * **界面展示**：
    1.  **顶部提示**：你的公共档案（身高/体重/运动数据）将授权给教练查看。
    2.  **差异化问答区**：根据教练设置的 JSON 数组，动态渲染出 N 个文本输入框。
          * *Q: 你一周能练几天？*
          * *A: [ 用户输入区域 ]*
  * **提交逻辑**：
      * 前端将问答对（Q\&A Pairs）打包，连同订单一起发给后端。
      * **不包含**公共档案数据（减少数据冗余），后端只需建立关联即可。

#### 4\. 教练端：查看新学员 (Reviewing New Client)

当订单生成，教练在“学员管理”列表看到新学员时：

  * **视图结构**：
      * **左侧/顶部**：学员的【公共档案】快照（点击可查看详情，看到力量举卡片等）。
      * **右侧/主要区域**：学员填写的【差异化回答】（一周练几天、有什么器材）。
  * **互补效果**：教练结合两边信息，脑海中形成完整画像，开始制定计划。

### 给开发团队的执行清单 (Action Items)

基于 `ui-prototype-pc` 现有代码，我们需要做以下具体修改：

**1. 修改数据层 (`js/mock_data.js`)**

你需要扩展 User 和 Coach 的数据结构：

```javascript
// 1. 在 User 对象中增加 profileCards 结构
users: [{
    id: 'student_maliu',
    // ... 基础信息 ...
    profile: {
        height: 178,
        weight: 75,
        injuries: ['左膝前交叉韧带轻微损伤'], // 伤病史放这里
        activeCards: ['powerlifting'], // 用户激活的标签
        cardData: {
            powerlifting: { squat: 140, bench: 100, deadlift: 180 }, // 力量举数据
            bodybuilding: { ... } // 如果没激活，这里可以是空的或者不存在
        }
    }
}]

// 2. 在 CoachProfile 中增加 intakeQuestions
coachProfiles: {
    'coach_zhang': {
        // ...
        intakeQuestions: [
            "你所在的健身房有什么短板器械（比如没有哈克深蹲机）？",
            "你期望的周训练频率是多少？",
            "除了增肌，还有什么特殊体态改善需求？"
        ]
    }
}
```

**2. 修改前端页面**

  * **`student/profile.html` (个人档案页)**：

      * **新增**：一个“编辑档案”的模态框或页面。
      * **功能**：包含“基础信息表单” + “运动标签选择器（Checkbox）” + “对应卡片输入区”。
      * **展示**：根据 `activeCards` 动态渲染卡片 UI。

  * **`student/coach-profile.html` 或 `subscription.html` (订阅页)**：

      * **逻辑**：点击订阅 -\> 读取该教练的 `intakeQuestions` -\> `v-for` 循环渲染出输入框 -\> 用户填写 -\> 提交。

  * **`coach/clients.html` (教练看学员)**：

      * **优化**：点击学员时，除了显示基本信息，还要能方便地看到他提交的 `intakeAnswers`（差异化回答）。

### 总结

这个方案非常成熟。它\*\*默认了“教练是专业的”\*\*这一前提（即教练会去查看公共档案，而不会傻傻地重复问身高体重）。这也符合 CoachLink 垂直、专业的平台定位。

### 2. 教练在哪里查看回答？ (Viewing Location)

你的直觉完全正确：**`plan-editor.html` 的“学员档案”侧边栏是查看这些信息的最佳战场**。

目前侧边栏 (`.profile-panel`) 的结构是：

2.  个人信息 (Info Grid)
3.  进步趋势 (Chart)

5.  观察与建议

**建议的修改方案：引入“置顶服务单”**

我们不要把它深埋在下面，而是应该作为**“本次周期的核心任务书”**置顶展示。

#### 方案 A：新增“当前需求”卡片 (推荐)
在 **头像区域下方** 和 **个人信息上方** 之间，插入一个新的高亮 Section。

* **视觉样式**：使用醒目的浅色背景（如浅蓝色 `bg-blue-50`）或带边框的卡片，区别于普通的档案信息。
* **标题**：📋 本期需求 (Service Request)
* **内容展示**：
    * **Q:** 一周能练几天？
    * **A:** *只能练3天，周末要陪孩子。*
    * **Q:** 有什么伤病隐患？
    * **A:** *左肩推举时有点响，不痛。*

#### 方案 B：改造侧边栏为“双标签页” (Tab View)
如果信息太多，可以将侧边栏顶部改为两个 Tab：
* **[ 档案 (Profile) ]**：展示现有的身高、体重、1RM、历史记录。
* **[ 需求 (Request) ]**：展示本次订阅填写的问卷答案、沟通重点、目标设定。
* **默认行为**：如果是新订单或刚开始制定计划，默认打开 **[ 需求 ]** Tab。
