## Supabase → 自建 PostgreSQL 数据迁移（完成）

为降低 Supabase 成本，把线上 Supabase（项目 `uhlqribpagvklpqmcqvo`，region ap-southeast-1，PG 17.4）的 `public` schema 全量迁到自建 PostgreSQL。

- 源库直连无 DB 密码（Supabase 创建后不可见、且 Dashboard 无 Reset 入口）。解决方式：在 Supabase SQL Editor 新建只读迁移角色
  - `create role migrator with login password 'coachlink_mig_2026'; grant pg_read_all_data to migrator;`
  - 因 12 张表开了 RLS、`migrator` 无 BYPASSRLS，又执行 `grant service_role to migrator;`，用 `pg_dump --role=service_role` 绕过 RLS。
  - 连接用 Session pooler：`migrator.uhlqribpagvklpqmcqvo@aws-0-ap-southeast-1.pooler.supabase.com:5432`（直连 `db.<ref>.supabase.co` 不解析）。
- 流程：`pg_dump --schema-only` → 目标库应用；`pg_dump --data-only --role=service_role --disable-triggers` → 目标库 `set session_replication_role=replica` 导入。
- 目标库兼容处理（纯 PG，应用层鉴权，不需要真实 RLS/auth）：
  - 建 `pgcrypto` / `uuid-ossp`；建 `extensions` schema + `uuid_generate_v4()/gen_random_uuid()` 包装函数（源表默认值用 `extensions.uuid_generate_v4()`）。
  - 建 `auth`/`storage` stub schema + `auth.uid()/role()/jwt()` stub，建 stub 角色 `anon/authenticated/service_role`，让 RLS 策略可创建。
