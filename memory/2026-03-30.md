# 2026-03-30

- 用户反馈很多页面存在“虚假登录状态”："明明已登录，但页面显示未登录/跳登录页"。
- 本轮做了代码筛查 + 浏览器验证，结论：
  - 浏览器已直接复现：`/training` 会把已登录用户打回 `/login`
  - 浏览器已直接复现：`/generate-plan?coachId=...` 会把已登录用户打回 `/login`
  - `coach/discovery` 移动端头部存在明显时序风险：用 `session?.user` 直接渲染“登录”按钮，缺少 `status === 'loading'` 保护
  - `coach/profile/[id]/CoachSubscription.tsx`、`streetlifting-index/data/page.tsx`、`me/cart/page.tsx` 的点击链路也有会话未 ready 时误报“请先登录”的风险
- 当前判断：这是一个“会话加载时序不一致”问题，不是单页孤立 bug；后续应统一 `useSession()` 门禁规则。
