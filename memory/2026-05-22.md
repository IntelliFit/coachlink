# 2026-05-22

- Web student onboarding follow-up:
  - After the standalone admin login decoupling work, the user tested with a newly registered student account and found that re-login did not immediately enter the mandatory onboarding flow.
  - Root cause identified in code: `OnboardingModalContext` kept a cross-login `suppressedUntilCleared` flag that was intended only to prevent same-user re-open after onboarding completion, but it was not reset when the authenticated user changed or logged out.
  - Fix direction implemented: reset onboarding suppression/modal state when `session.user.id` changes so a newly logged-in incomplete student can be prompted immediately again.
  - After the first fix, the user retested and reported the new account still did not enter the fill-profile flow.
  - Strengthened fix implemented:
    - Added `src/lib/auth/postLoginFlow.ts` to centralize "where should this user go right after login/register".
    - Added `/complete-profile` as an explicit incomplete-profile entry that force-opens the onboarding modal.
    - Registration auto-login and standard login now send incomplete students to `/complete-profile` instead of relying on `/` or `/today-training` side effects.

- WeApp delete-account modal polish:
  - User reported the gray default text inside the delete-account confirmation input looked vertically too high.
  - Adjusted `wechat_app/src/me/settings/index.scss` shared modal input sizing to explicit `height: 40px`, `line-height: 40px`, and horizontal-only padding so the placeholder/input text sits centered in the field.
  - No WeChat DevTools/manual verification was run because the local workspace preference says not to auto-run it unless explicitly requested.
- Web vs `food_link` onboarding-flow comparison:
  - The user reported that `coachlink` feels like it repeatedly falls into a "quick registration / onboarding" step, while sibling project `D:\projects\food_link` feels lighter.
  - Comparison result:
    - `coachlink` Web triggers onboarding globally from `src/components/NavigationStudent.tsx` whenever `profile.onboarding_completed !== true`.
    - `food_link` only guards login in `src/utils/withAuth.tsx`; onboarding completion is handled more softly from specific surfaces like `src/pages/profile/index.tsx`.
  - So the current difference is mainly intentional flow placement/strictness rather than the exact same logic behaving inconsistently.
