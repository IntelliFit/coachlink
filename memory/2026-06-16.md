## Power Analysis Topic-Scoped Recovery

- User asked for a better fallback so jobs do not get stuck forever if queue publish/consume fails, while avoiding local workers claiming production jobs.
- Implemented topic-scoped recovery:
  - Added migration `supabase/migrations/20260616_power_analysis_queue_topic.sql`.
  - New DB ownership fields: `queue_driver`, `queue_topic`, `queue_consumer_group`, `enqueued_at`.
  - `create-upload-url` writes the current queue config into each new `tool_power_analysis_jobs` row.
  - `enqueue` refreshes queue ownership fields and sets `enqueued_at` when moving a job to `queued`.
  - Queue workers run recovery again, but only republish `queued` rows whose `queue_topic` equals the worker's configured `TASK_QUEUE_TOPIC`.
  - Queue delivery claim also filters by `queue_topic`, so a message on the wrong topic cannot claim another environment's job.
  - Legacy `npm run power-analysis:poll-worker` remains an explicit manual full-DB fallback.
  - Updated `docs/done/system-design/power-analysis-worker-queue.md` with the topic-scoped recovery model.
- Clarification:
  - Topic values are not hard-coded as local/dev/main in code. Web and worker both derive the topic from runtime config (`getTaskQueueConfig()` / `TASK_QUEUE_TOPIC`) after local/Apollo bootstrap.
  - Power-analysis task creation and queue workers require an explicit `TASK_QUEUE_TOPIC`; missing local/Apollo config now fails fast rather than silently using the generic queue default.
- Verification:
  - `npm run typecheck`: passed.
  - `npm run lint`: passed.
  - `npm test`: passed, 33 files / 162 tests.
  - `npx next build`: passed with existing baseline-browser-mapping/edge-runtime warnings only.
- Deployment note:
  - After running the queue-topic migration, deploy both Web/Next.js and the Power Analysis worker.
  - Web/Next.js owns writing `queue_topic` on job creation/enqueue; the worker owns topic-scoped claim/recovery.
  - Safer rollout order is Web first, then worker, to avoid new worker filtering out jobs created by old Web code without `queue_topic`.
