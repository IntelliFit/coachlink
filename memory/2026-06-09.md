## Web Image Build Fix After Worker Integration

- User ran `npm run push-docker-ccr` and Web image build failed because Next/Turbopack pulled `scripts/power-analysis-worker.ts` into the Web/Instrumentation bundle through `embeddedWorker`.
- Root cause:
  - The Web app statically imported worker code containing Node-only APIs (`process.argv`, `process.exit`, `process.once`, `eval("require")`, child process/stdio use), and Next reported Edge Runtime unsupported APIs.
- Fix:
  - Removed Web/instrumentation imports of `src/lib/powerAnalysis/embeddedWorker.ts`.
  - Deleted `src/lib/powerAnalysis/embeddedWorker.ts`.
  - Removed `ensureEmbeddedPowerAnalysisWorker()` from the enqueue API.
  - Changed `scripts/start-dev.mjs` so local `TASK_QUEUE_DRIVER=memory` starts `node scripts/power-analysis-worker.mjs --queue` as a separate child process alongside `next dev`.
  - Production Web now only publishes to Kafka and never bundles/runs worker code.
