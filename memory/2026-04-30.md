- Diagnosed `The client is closed` logs from `src/app/api/coach/get-overview-data/route.ts`:
  - The route wraps `redis.get` / `redis.setEx` in `try/catch`, so coach overview still falls back to live Supabase aggregation and returns normally when Redis is unavailable.
  - Root cause is the shared Redis client in `src/lib/redisClient.ts` being configured as fail-fast (`disableOfflineQueue: true`, `reconnectStrategy: false`); when `REDIS_URL` exists but the Redis connection is not open, calls throw `The client is closed`.
  - Safe to treat as cache-layer noise for this overview endpoint in local/dev, but not safe to ignore globally because several auth / captcha / verification-code routes still assume Redis availability.
