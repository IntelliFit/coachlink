## WeChat Impromptu Execution Stuck Loading Root Cause

- User provided `[CL-EXEC-DEBUG]` logs from the failing flow. Key pattern:
  - loading screen rendered with `impromptuId` present;
  - `useDidShow requestStartTraining` ran;
  - `requestStartTraining executing startTrainingRef` logged;
  - no `startTraining enter` logged;
  - 28ms later the initial effect call was skipped by debounce.
- Diagnosis:
  - `useDidShow` fired before `useEffect(() => { startTrainingRef.current = startTraining })`.
  - The first call executed the initial no-op ref and consumed the debounce timestamp.
  - The real initial load was skipped, so `impromptuService.get()` was never called and `execution` stayed null.
- Fix:
  - In `wechat_app/src/training/training-execution/index.tsx`, assign `startTrainingRef.current = startTraining` synchronously during render instead of waiting for `useEffect`.
- Network sequence clarified for future debugging:
  - `POST /api/impromptu/start` is called from the action picker `开始` button and returns the new execution id/action executions.
  - `POST /api/impromptu/get` is then called by the training execution page with `{ id: impromptuId }` and should return the execution board data.
- Verification:
  - `npm run typecheck`, `cd wechat_app && npm run build:weapp`, `npm run lint`, `npm test`, `npx next build`, and `git diff --check` passed.
