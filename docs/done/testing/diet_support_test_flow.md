# Diet 支持功能 - 测试流程

## 前置条件

- 开发服务器已运行 (`npm run dev`)
- 有教练账号可以登录

---

## 步骤 1️⃣：执行数据库迁移

在 Supabase SQL Editor 中执行以下 SQL：

```sql
-- 为 coach_actions 添加 type 字段
ALTER TABLE coach_actions 
ADD COLUMN IF NOT EXISTS type TEXT NOT NULL DEFAULT 'STRENGTH';

-- 为 student_actions 添加 type 字段
ALTER TABLE student_actions 
ADD COLUMN IF NOT EXISTS type TEXT NOT NULL DEFAULT 'STRENGTH';

-- 添加索引
CREATE INDEX IF NOT EXISTS idx_coach_actions_type ON coach_actions(type);
CREATE INDEX IF NOT EXISTS idx_student_actions_type ON student_actions(type);
```

**验证**：执行成功后，在 Supabase 的 Table Editor 中查看 `coach_actions`
表，确认 `type` 列已添加。

---

## 步骤 2️⃣：创建饮食类型动作

1. 以教练身份登录系统
2. 进入 **动作库** 页面（通常在教练仪表板中）
3. 点击 **添加动作** 按钮
4. 在弹出的对话框中：
   - **项目类型**：选择 `🍎 饮食`
   - **饮食名称**：输入 `早餐`
   - **饮食内容**：输入 `燕麦+鸡蛋+牛奶，蛋白质约30g`
5. 点击 **保存**

**预期结果**：

- ✅ 选择"饮食"类型后，"自动计算负重"、"动作类型"、"动作属性"字段应该消失
- ✅ 标签应显示"饮食名称"和"饮食内容"
- ✅ 保存成功后，动作列表中应能看到新创建的饮食项

---

## 步骤 3️⃣：验证动作库列表显示

1. 在动作库页面查看刚创建的"早餐"项目
2. 可以再创建一个力量训练类型的动作进行对比

**预期结果**：

- ✅ 饮食类型和力量训练类型的动作都能正常显示
- ✅ 编辑饮食类型动作时，类型下拉框应显示"🍎 饮食"

---

## 步骤 4️⃣：将饮食动作添加到计划模板

1. 进入 **计划库** 页面
2. 创建新模板或编辑现有模板
3. 在某个训练日中添加动作
4. 搜索并选择刚创建的"早餐"饮食项目
5. 保存模板

**预期结果**：

- ✅ 饮食类型动作可以被添加到计划中
- ✅ 模板保存成功

---

## 步骤 5️⃣：验证学员端显示

1. 将包含饮食项目的计划分配给一个学员
2. 以学员身份登录（或在教练端查看学员计划）
3. 查看训练计划详情

**预期结果**：

- ✅ 饮食项目显示为绿色背景样式
- ✅ 显示苹果图标 🍎
- ✅ 显示饮食名称和内容
- ✅ 与力量训练项目（灰色/蓝色背景）视觉区分明显

---

## 可选：测试其他类型

重复步骤 2-5，测试以下类型：

- 🏃 **有氧运动**（如：跑步 30 分钟）
- ✅ **习惯打卡**（如：每天喝 8 杯水）

---

## 问题排查

### 如果看不到 type 字段或选项：

1. 确认迁移 SQL 已成功执行
2. 刷新页面（F5）或清除浏览器缓存
3. 重启开发服务器

### 如果保存失败：

1. 打开浏览器开发者工具（F12）
2. 查看 Console 和 Network 标签页中的错误信息
3. 确认 API 返回的错误信息

### 如果学员端没有绿色样式：

1. 确认动作的 `type` 字段在数据库中确实是 `DIET`
2. 检查计划实例中 action_id 是否正确关联

---
