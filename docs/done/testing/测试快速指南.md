# 测试快速指南（开发者必读）

> 目标：让新同学在 10 分钟内知道“怎么测”“测什么”“出了问题怎么定位”。
>
> 本项目测试体系：**Vitest（单测/集成） + Playwright（E2E）**。  
> 运行命令以 `package.json` scripts 为准。

---

## 1. 一句话原则

- **改业务逻辑**：至少补/跑一条 Vitest（单测或集成测试）。
- **改核心链路（订阅/计划/执行/支付/鉴权）**：必须跑 Playwright 相关用例或补一个最小 E2E。
- **线上问题复盘**：把复现步骤固化成测试（或最小脚本）。

---

## 2. 常用命令

### 2.1 环境自检

- `npm run check-env`

### 2.2 单元测试 / 集成测试（Vitest）

- **一次性跑完**：`npm run test`
- **Watch 模式**：`npm run test:watch`
- **生成报告**：`npm run test:report`

> 说明：项目里存在“集成测试风格”的 Vitest（例如 API 相关的 `.integration.test.ts`），运行方式同上。

### 2.3 端到端（Playwright）

- `npm run test:e2e`

> 说明：E2E 默认依赖开发/测试环境的可用配置（如数据库、登录态、测试数据清理接口等）。

---

## 3. 测试分层与写测试的落点（怎么选）

### 3.1 适合写单测（Vitest）的地方

- `src/lib/` 下的纯函数/计算逻辑：
  - credits 计算、估算天数、RM/百分比换算等
- “输入/输出明确”的数据转换函数：
  - 计划模板 → 实例 → 执行视图的映射

### 3.2 适合写集成测试（Vitest）的地方

- API route 的关键分支：鉴权、参数校验、幂等、错误码
- 与 Supabase 交互但可用 mock 或最小替身覆盖的逻辑

### 3.3 适合写 E2E（Playwright）的地方

- 订阅创建 → 分配计划 → 今日训练执行 → 完成 → 余额/进度刷新
- 支付创建订单/回调/查询
- 关键 UI 行为：上传视频、查看待点评、分享卡片生成

---

## 4. 出问题怎么定位（最短路径）

### 4.1 先问：是“口径错”还是“实现 bug”

- 口径错：优先对齐 `docs/PROJECT_BIBLE.md` + `docs/done/core-business/*` 的定义（不要用 UI 文案猜）。
- 实现 bug：看最近改动的 API route / lib 函数，再看是否缺测试覆盖。

### 4.2 常见高风险点（建议优先加测试）

- `plan_instance_executions` 外键字段误用（`instance_id` vs `plan_instance_id`）
- B1 模型下 `end_date` 的语义（estimated completion，仅用于展示）
- “新建阶段 vs 覆盖当前”语义分叉（执行次数是否清零）
- Push 权限与订阅存储（iOS 手势触发）

---

## 5. 推荐的最小回归清单（本地/预发）

- 能正常启动：`npm run dev`
- 跑完单测：`npm run test`
- 订阅/计划/执行最小链路：
  - 进入今日训练页
  - start → finish
  - 进度/预计完成日刷新
-（如涉及）支付：create → query（回调可 mock）
