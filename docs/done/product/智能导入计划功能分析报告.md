## 1. 功能概述

智能导入计划是 Coach Link 平台的核心功能之一，允许用户通过粘贴自由格式的训练计划文本，利用 AI 自动解析并生成结构化的训练计划模板。该功能极大提升了教练和学员创建训练计划的效率，避免了手动逐个添加动作的繁琐操作。

### 1.1 核心价值

- **⚡️ 极速导入**：从文本到结构化模板，耗时仅需几十秒至1分钟
- **🤖 AI 智能解析**：自动识别动作、组数、次数、强度、休息时间等训练参数
- **🔄 动作复用**：智能匹配现有动作库，避免重复创建
- **📝 格式灵活**：支持多种文本格式（简洁风格、详细风格、Excel 导出等）
- **✏️ 可编辑确认**：用户可在导入前编辑和确认动作信息

### 1.2 适用场景

1. **教练创建模板**：从 Excel、文档、聊天记录快速导入训练计划
2. **学员自建计划**：学员可以导入自己的训练计划文本
3. **AI 辅助生成**：先用 DeepSeek 等 AI 生成文本计划，再导入平台

## 3. 核心流程详解

### 3.1 两阶段解析流程

智能导入采用**两阶段解析**设计，确保动作库的准确性和模板结构的完整性。

#### 阶段 1：动作解析与匹配

**目标**：从文本中提取所有动作，并与现有动作库进行匹配

**流程**：
```
用户输入文本
    ↓
文本预处理 (normalizeTextForActionExtraction)
    ↓
DeepSeek 提取动作列表
    ↓
动作名清洗 (sanitizeActionName)
    ↓
过滤非动作内容 (isLikelyNonActionName)
    ↓
匹配现有动作库 (findBestExistingActionMatch)
    ↓
推断动作属性 (inferStrengthAttrs)
    ↓
返回动作列表（含匹配信息）
```

**关键处理**：

1. **文本预处理**：
   - 在动作名和强度标记之间插入空格（如 "负重引体5RM" → "负重引体 5RM"）
   - 处理"然后"连接的动作，拆分为独立行
   - 统一标点符号和空格

2. **动作名清洗**：
   - 移除括号内容（通常包含强度/备注）
   - 移除尾部强度标记（5RM、70%、100kg 等）
   - 移除组次标记（4×4、3组8次等）
   - 移除休息时间描述（组休3分钟等）
   - 处理前导重量（"10公斤引体" → "负重引体"）

3. **动作匹配算法**：
   - 使用 Dice 系数（基于 bigram）计算相似度
   - 支持子串匹配（如 "锤式" → "锤式弯举"）
   - 阈值：短名称（≤2字符）0.85，长名称 0.78
   - 优先精确匹配，其次相似度匹配

4. **属性推断**：
   - 计时动作（悬挂、支撑等）→ `["组数", "持续时间", "休息时间"]`
   - 负重动作（杠铃、哑铃等）→ `["组数", "次数", "强度", "休息时间"]`
   - 默认 → `["组数", "次数", "休息时间"]`

#### 阶段 2：模板结构解析

**目标**：基于已确认的动作库，解析完整的周/天训练结构

**流程**：
```
原始文本 + 动作库
    ↓
按周拆分文本 (splitPlanByWeekSections)
    ↓
逐周并行解析 (Promise.all)
    ↓
DeepSeek 解析周内训练日
    ↓
强度配置处理
    ↓
次数推断规则应用
    ↓
周内天数标准化 (normalizeWeekDays)
    ↓
合并所有周的结果
    ↓
返回完整模板结构
```

**关键处理**：

1. **按周拆分**：
   - 识别 "W1D1"、"第X周" 等标记
   - 支持中文数字（一、二、三...）
   - 合并同周内容，避免重复解析

2. **强度解析优先级**：
   ```
   最高优先级：绝对重量（如 "112.5kg"）
   ↓
   百分比（如 "70%"、"80%1RM"）
   ↓
   RM 值（如 "5RM"、"10-11RM"）
   ↓
   无强度描述 → null
   ```

3. **复杂逻辑降级**：
   - 无法用结构化字段表达的逻辑 → 写入 `note` 或 `dayNote`
   - 例如："测试新极限"、"第一组/第二组"、"累积30个"、"力竭" 等

4. **休息日识别**：
   - 明确标记的休息日 → `type: "rest"`
   - "每周训练X天" → 自动推断并补齐休息日
   - 休息日占用 `dayOfWeek`，保持连续性

5. **次数推断规则**：
   - 如果原文未明确写次数（如只有 "12RM" 没有 "×5次"），则 `reps: null`
   - 计时动作（`durationSeconds` 存在）→ `reps: null`
   - 避免将 RM 值误当作次数

## 4. 关键特性分析

### 4.1 智能动作匹配

**实现方式**：
- 使用 Dice 系数（bigram 相似度）计算动作名相似度
- 支持精确匹配、子串匹配、相似度匹配
- 阈值可调，平衡匹配准确性和容错性

**优势**：
- ✅ 避免重复创建动作（如 "引体向上" vs "引体"）
- ✅ 支持别名和简称（如 "锤式" → "锤式弯举"）
- ✅ 区分不同动作（如 "引体向上" vs "反手引体"）

**局限性**：
- ⚠️ 短名称（≤2字符）匹配阈值较高，可能漏匹配
- ⚠️ 完全不同的命名方式无法匹配（如 "上拉" vs "引体向上"）

### 4.2 动作属性智能推断

**推断规则**：

1. **计时动作识别**：
   - 关键词：悬挂、悬垂、支撑、保持、维持、计时
   - 属性：`["组数", "持续时间", "休息时间"]`

2. **负重动作识别**：
   - 关键词：杠铃、哑铃、器械、推举、深蹲、硬拉
   - 属性：`["组数", "次数", "强度", "休息时间"]`

3. **默认属性**：
   - `["组数", "次数", "休息时间"]`

**优势**：
- ✅ 减少用户手动配置
- ✅ 符合力量训练常见模式

### 4.3 强度解析多格式支持

**支持的强度格式**：

| 输入格式 | 解析结果 | 示例 |
|---------|---------|------|
| `5RM` / `5rm` | `{ type: "rm", value: 5 }` | 负重引体 5RM |
| `10-11RM` | `{ type: "rm", value: 10 }` | 取较小值 |
| `70%` / `70%rm` / `80%1RM` | `{ type: "percentage", value: 70 }` | 卧推 70% |
| `50kg` / `100lbs` | `{ type: "fixed", fixedWeight: 50 }` | 深蹲 50kg |
| `@ 112.5kg (75%)` | 同时包含固定重量和百分比 | 优先固定重量 |

**优先级规则**：
1. 绝对重量（最高优先级）
2. 百分比
3. RM 值
4. 无强度描述

### 4.4 周/天结构智能识别

**支持的格式**：

1. **标准格式**：
   - `W1D1`、`W2D3`
   - `第1周第1天`、`第X周`

2. **中文格式**：
   - `周一`、`周二` → `dayOfWeek: 1, 2`
   - `第一周`、`第二周` → `weekIndex: 1, 2`

3. **自动推断**：
   - 无明确标记时，按出现顺序分配
   - 每 7 天为一周，不足补齐休息日

**处理逻辑**：
- 按周拆分文本，逐周并行解析（提升性能）
- 周内天数标准化：确保 `dayOfWeek` 连续且不重复
- 自动补齐休息日：根据"每周训练X天"推断

### 4.5 复杂逻辑降级处理

**设计理念**：无法用结构化字段表达的训练逻辑，一律降级到 `note` 字段，避免信息丢失。

**降级场景**：

| 原文描述 | 处理方式 |
|---------|---------|
| "测试新极限" | → `note: "测试新极限"` |
| "第一组/第二组/循环三组" | → `sets: 3`, `note: "第一组/第二组"` |
| "累积30个" | → `sets: 合理值`, `reps: null`, `note: "累积30个"` |
| "力竭" | → `note: "力竭"` |
| "同等数量（参考上一动作）" | → `reps: null`, `note: "同等数量"` |

**优势**：
- ✅ 保留所有训练信息，不丢失细节
- ✅ 结构化字段保持规范，便于后续计算

## 5. 实现细节

### 5.1 文本预处理工具 (`planImportText.ts`)

**核心函数**：

1. **`normalizeTextForActionExtraction`**：
   - 在动作名和强度标记间插入空格
   - 处理"然后"连接的动作
   - 统一标点符号

2. **`sanitizeActionName`**：
   - 移除括号、强度标记、组次标记
   - 处理前导重量前缀
   - 清理尾部指令词

3. **`isLikelyNonActionName`**：
   - 过滤明显非动作的内容（如"休息"、"组休"等）

4. **`findBestExistingActionMatch`**：
   - Dice 系数匹配算法
   - 支持精确匹配、子串匹配、相似度匹配

5. **`inferStrengthAttrs`**：
   - 根据动作名和标志推断属性列表

### 5.2 API 端点实现

#### `/api/plan-lib/parse-actions`

**功能**：解析动作列表

**流程**：
1. 验证用户登录和教练权限
2. 获取现有动作库
3. 文本预处理
4. 调用 DeepSeek 提取动作
5. 动作名清洗和过滤
6. 匹配现有动作
7. 推断动作属性
8. 合并同义动作
9. 返回动作列表

**响应格式**：
```typescript
{
  success: true,
  data: {
    actions: [
      {
        name: "负重引体",
        matchedExistingId: "uuid" | null,
        needsAutoCompute: true,
        includesBodyWeight: false,
        attrs: ["组数", "次数", "强度", "休息时间"],
        isNew: false
      }
    ]
  }
}
```

#### `/api/plan-lib/parse-template`

**功能**：解析模板结构

**流程**：
1. 验证用户登录和教练权限
2. 按周拆分文本
3. 逐周并行调用 DeepSeek 解析
4. 处理强度配置
5. 应用次数推断规则
6. 标准化周内天数
7. 合并所有周的结果
8. 返回完整模板

**响应格式**：
```typescript
{
  success: true,
  data: {
    weeks: 4,
    trainingDays: [
      {
        weekIndex: 1,
        dayOfWeek: 1,
        type: "training" | "rest",
        actions: [
          {
            actionId: "uuid",
            sets: 4,
            reps: 4,
            restSeconds: 60,
            intensityConfig: {
              relativeIntensity: { type: "rm", value: 5 }
            },
            note: "rpe9"
          }
        ],
        dayNote: "当天备注"
      }
    ]
  }
}
```

#### `/api/plan-lib/batch-create-actions`

**功能**：批量创建新动作

**流程**：
1. 验证用户登录和教练权限
2. 检查动作名是否已存在（防重复）
3. 批量插入新动作
4. 返回创建的动作列表

**防重复机制**：
- 使用 `normalizeActionNameForMatch` 标准化动作名
- 已存在的动作跳过创建

### 5.3 前端组件实现

#### `SmartImportDialog.tsx` (教练端)

**状态管理**：
- `activeStep`: 当前步骤（0-2）
- `inputText`: 用户输入的文本
- `editableActions`: 可编辑的动作列表

**关键方法**：
1. `handleParseActions`: 调用阶段1 API，解析动作

4. `convertToTemplateDays`: 将解析结果转换为模板编辑器格式

**数据转换**：

## 7. 使用场景示例

### 场景 1：教练从 Excel 导入

**输入文本**（从 Excel 复制）：
```
第1周
周一：卧推 5×5 @ 80%1RM，组休3分钟
周二：深蹲 4×6 @ 75%，组休2分钟
周三：休息
周四：硬拉 3×5 @ 85%，组休4分钟
```

**解析结果**：
- 动作：卧推、深蹲、硬拉（自动匹配或新建）
- 强度：80%、75%、85%（百分比模式）
- 组次：5×5、4×6、3×5
- 休息：180秒、120秒、240秒
- 结构：W1D1-训练、W1D2-训练、W1D3-休息、W1D4-训练

### 场景 2：学员导入聊天记录

**输入文本**（微信聊天记录）：
```
W1 D1 
70%rm  4*4  负重引体 rpe9 组间60s 
3组自重引体

D2
反握引体 70% 4*4 rpe8

休息1天
```

**解析结果**：
- 动作：负重引体、自重引体、反握引体
- 强度：70%（百分比模式）
- 组次：4×4、3组自选
- 休息：60秒、默认180秒
- 结构：W1D1-训练、W1D2-训练、W1D3-休息

### 场景 3：AI 生成后导入

**流程**：
1. 用户使用 DeepSeek 生成训练计划文本
2. 复制生成的文本
3. 在平台中使用智能导入
4. 确认动作和预览模板
5. 导入完成

**优势**：
- ✅ AI 生成 + 平台结构化 = 完整工作流
- ✅ 无需手动输入每个动作

## 8. 存在的问题和改进建议

### 8.1 当前问题

#### 问题 1：动作匹配准确性

**现象**：
- 某些动作名无法正确匹配（如 "上拉" vs "引体向上"）
- 短名称匹配阈值过高，可能漏匹配

**影响**：
- 用户需要手动切换或创建重复动作

**改进建议**：
- 引入动作别名库（如 "上拉" → "引体向上"）
- 支持用户手动添加动作映射规则
- 降低短名称匹配阈值，但增加二次确认

#### 问题 2：复杂训练逻辑解析

**现象**：
- 某些复杂逻辑（如 "第一组10次，第二组8次，第三组6次"）无法完美解析
- 降级到 `note` 字段后，无法在计划执行时自动应用

**影响**：
- 用户需要手动调整组次设置

**改进建议**：
- 支持组次数组格式（如 `reps: [10, 8, 6]`）
- 在模板编辑器中提供"组次变化"配置选项

#### 问题 3：错误恢复机制

**现象**：
- 如果 AI 解析失败，用户需要重新输入文本
- 没有部分导入或修正机制

**影响**：
- 用户体验不佳，需要重复操作

**改进建议**：
- 提供"重新解析"按钮（保留用户输入）
- 支持手动修正解析结果（在预览阶段）
- 记录解析失败的原因，提供改进建议

#### 问题 4：性能优化

**现象**：
- 长计划（8周以上）解析时间较长
- 并行解析可能达到 API 速率限制

**影响**：
- 用户等待时间增加

**改进建议**：
- 增加进度提示（"正在解析第X周..."）
- 实现请求队列和重试机制
- 考虑缓存常见格式的解析结果

### 8.2 功能增强建议

#### 建议 1：支持更多输入格式

- **Excel 文件上传**：直接解析 Excel 文件，无需复制粘贴
- **图片 OCR**：支持从图片中识别训练计划文本
- **PDF 解析**：支持 PDF 文件导入

#### 建议 2：模板库智能推荐

- 基于解析出的动作，推荐相似的计划模板
- 用户可以选择"基于模板修改"而非"从零创建"

#### 建议 3：批量导入优化

- 支持一次导入多个计划（如 4 周计划拆分为 4 个模板）
- 提供"导入为多个模板"选项

#### 建议 4：解析结果验证

- 在预览阶段提供"验证"功能，检查：
  - 动作是否存在
  - 强度值是否合理
  - 组次是否完整
  - 休息时间是否设置

## 10. 总结

智能导入计划功能是 Coach Link 平台的重要创新，通过 AI 技术大幅提升了训练计划创建的效率。该功能采用两阶段解析设计，确保了动作库的准确性和模板结构的完整性。

### 核心优势

1. **效率提升**：从文本到结构化模板，耗时仅需几十秒
2. **智能匹配**：自动匹配现有动作库，避免重复创建
3. **格式灵活**：支持多种文本格式，适应不同用户习惯
4. **可编辑确认**：用户可在导入前编辑和确认，保证准确性

### 技术亮点

1. **两阶段解析**：动作解析 + 模板解析，确保数据准确性
2. **智能匹配算法**：Dice 系数 + 子串匹配，平衡准确性和容错性
3. **属性智能推断**：根据动作名自动推断属性列表
4. **复杂逻辑降级**：无法结构化的逻辑保留在 note 字段

### 改进方向

1. **准确性提升**：动作匹配、复杂逻辑解析
2. **性能优化**：长计划解析、并行处理
3. **功能增强**：更多输入格式、模板推荐、批量导入
4. **用户体验**：错误恢复、解析验证、进度提示
