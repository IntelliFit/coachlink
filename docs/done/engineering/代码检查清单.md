> 快速检查AI生成代码的正确性 - 按场景分类

## 🔍 API接口检查（route.ts）

### ✅ 必须检查项

#### 1. 导入语句
```typescript
// ✅ 正确
import { NextResponse } from 'next/server';
import { getServerSession } from '../../auth/[...nextauth]/auth';
import supabase from '@/lib/supabaseClient';
import type { RequestDto, ResponseDto } from './entity';

// ❌ 错误：缺少必要的导入
import { NextResponse } from 'next/server';
// 缺少 getServerSession 和 supabase
```

#### 2. 登录检查
```typescript
// ✅ 正确
const session = await getServerSession();
if (!session?.user?.id) {
    return NextResponse.json({
        success: false,
        message: '用户未登录',
        data: null
    }, { status: 401 });
}

// ❌ 错误：没有检查登录
export async function POST(req: Request) {
    // 直接处理请求，没有检查登录
}
```

#### 3. 获取用户ID
```typescript
// ✅ 正确：从session获取
const userId = session.user.id;

// ❌ 错误：从请求参数获取
const { userId } = await req.json(); // 不安全！
```

#### 4. 返回格式
```typescript
// ✅ 正确：统一格式
return NextResponse.json<ApiData<ResponseDto>>({
    success: true,
    message: '操作成功',
    data: result
});

// ❌ 错误：格式不一致
return NextResponse.json({ result }); // 缺少success和message
return NextResponse.json({ data: result }); // 缺少success和message
```

#### 5. 错误处理
```typescript
// ✅ 正确：检查数据库错误
const { data, error } = await supabase.from('users').select('*');
if (error) {
    return NextResponse.json({
        success: false,
        message: '查询失败',
        data: null
    });
}

// ❌ 错误：没有检查error
const { data } = await supabase.from('users').select('*');
return NextResponse.json({ success: true, data }); // 可能data是null
```

## 🔍 Entity文件检查（entity.ts）

### ✅ 必须检查项

#### 1. 请求参数类型
```typescript
// ✅ 正确：通常不需要userId（从session获取）
export interface GetUserProfileDto {
    // 空对象或只有必要的查询参数
}

// ⚠️ 注意：如果确实需要userId，应该有说明
export interface GetUserProfileDto {
    userId?: string; // 可选，通常从session获取
}

// ❌ 错误：不应该要求前端传userId
export interface GetUserProfileDto {
    userId: string; // 应该从session获取
}
```

#### 2. 返回数据类型
```typescript
// ✅ 正确：包含所有必要字段
export interface GetUserProfileResponseDto {
    id: string;
    name: string;
    email: string;
    avatar_url?: string; // 可选字段用?
}

// ❌ 错误：缺少必要字段
export interface GetUserProfileResponseDto {
    name: string; // 缺少id和email
}
```

## 🔍 Service层检查（service/*.ts）

### ✅ 必须检查项

#### 1. 继承BaseService
```typescript
// ✅ 正确
import { BaseService } from "@/lib/baseService";

export class UserService extends BaseService {
    // ...
}

// ❌ 错误：没有继承
export class UserService {
    // 无法使用this.post()等方法
}
```

#### 2. API调用方法
```typescript
// ✅ 正确：使用this.post()或this.get()
async getUserProfile(reqData: GetUserProfileDto) {
    const res = await this.post<GetUserProfileResponseDto>('user/get-profile', reqData);
    if (res.data && res.data.success) {
        return res.data.data || null;
    }
    return null;
}

// ❌ 错误：直接使用fetch
async getUserProfile(reqData: GetUserProfileDto) {
    const res = await fetch('/api/user/get-profile', {
        method: 'POST',
        body: JSON.stringify(reqData)
    });
    // 没有统一处理
}
```

#### 3. 成功状态检查
```typescript
// ✅ 正确：检查success
if (res.data && res.data.success) {
    return res.data.data || null;
}

// ❌ 错误：没有检查success
return res.data.data; // 可能失败时也返回了
```

## 🔍 常见错误模式

### ❌ 错误1：前端直接访问数据库
```typescript
// ❌ 错误
'use client';
import supabase from '@/lib/supabaseClient';
```

### ❌ 错误2：从请求参数获取userId
```typescript
// ❌ 错误
export async function POST(req: Request) {
    const { userId } = await req.json();
    // 不安全，用户可以伪造userId
}

// ✅ 正确
export async function POST(req: Request) {
    const session = await getServerSession();
    const userId = session.user.id;
}
```

### ❌ 错误3：返回格式不一致
```typescript
// ❌ 错误
return NextResponse.json({ data: result });
return NextResponse.json({ result });

// ✅ 正确
return NextResponse.json({
    success: true,
    message: '操作成功',
    data: result
});
```

### ❌ 错误4：没有检查数据库错误
```typescript
// ❌ 错误
const { data } = await supabase.from('users').select('*');
return NextResponse.json({ success: true, data });

// ✅ 正确
const { data, error } = await supabase.from('users').select('*');
if (error) {
    return NextResponse.json({
        success: false,
        message: '查询失败',
        data: null
    });
}
return NextResponse.json({ success: true, data });
```

### ❌ 错误5：使用setError而不是toast
```typescript
// ❌ 错误

setError('操作失败');

// ✅ 正确
import { toast } from '@/context/ToastContext';
toast.error('操作失败');
```

### ❌ 错误6：业务序号与数组下标混用（高频）
```typescript
// ❌ 错误1：传 dayIndex(1-based)，按 arrayIndex(0-based) 处理
onRemoveActionSet(day.dayIndex, setIndex);
// 父组件:
newDays[dayIndex].actionSets.splice(setIndex, 1); // dayIndex 语义不一致

// ✅ 正确：同一链路统一使用 arrayIndex
onRemoveActionSet(dayIndex, setIndex);
// 父组件:
newDays[dayIndex].actionSets.splice(setIndex, 1);

// ❌ 错误2：同页面多个 handler 索引转换方式不一致（2026-02-15 典型案例）
// PlanDayCard 传入 arrayIndex(0-based)
// handleActionSetChange: findIndex(d => d.dayIndex === dayIndex + 1)  ✅
// handleRemoveActionSet: findIndex(d => d.dayIndex === dayIndex)      ❌ 漏了 +1
// 结果：添加/编辑正常，删除失效

// ✅ 正确：同一组件的所有操作回调使用统一的索引转换逻辑
const actualDayIndex = newDays.findIndex(d => d.dayIndex === dayIndex + 1);
```

### ❌ 错误7：状态值不在数据库约束允许列表

### ❌ 错误8：新增/导入动作未确定 canonical_action_id
```typescript

  user_id: userId,
  name: action.name,
  type: 'STRENGTH',

  requireCanonical: true,
```

### ❌ 错误9：批量创建时动作名匹配多个 canonical 阻断流程
```typescript

  actionName: action.name,
  requireCanonical: true,
});

// ✅ 正确：批量/导入场景可启用 pickFirstOnAmbiguous 自动取首个
const resolved = resolveCanonicalActionId(lookup, {
  actionName: action.name,
  requireCanonical: true,
  pickFirstOnAmbiguous: true, // 避免「匹配到多个 canonical_action_id」阻断
});
```

- [ ] 批量创建/智能导入类 API 中，resolveCanonicalActionId 是否在必要时启用了 pickFirstOnAmbiguous？

### ❌ 错误10：编辑提案链路把 `null` 当成“未修改”
```typescript

const finalDetail = edit.proposed_detail ?? action.detail;

// ✅ 正确：仅 undefined 才表示“未传”，null 是“显式清空”
const hasOwn = Object.prototype.hasOwnProperty.call(body, "detail");
const proposedDetail = hasOwn ? (body.detail ?? null) : (action.detail ?? null);
const finalDetail = edit.proposed_detail;
```

- [ ] 编辑提案是否正确区分 `undefined`（未传）与 `null`（显式置空），并在提交前阻止“无改动提交”？

- [ ] AI 修改结果在预览/应用前，是否已统一参数键语义（`组数/次数/休息时间/load`）并通过“确认并映射动作 -> 确认应用”两步流程？

### ❌ 错误13：AI 新建动作未先查公共库就直接创建

### ❌ 错误16：请求型 `useEffect` 直接依赖临时数组/对象，导致无限重复加载
```typescript
// ❌ 错误：默认数组/内联数组每次渲染都变引用，effect 会反复请求
const Picker = ({ allowedTypes = ['STRENGTH'] }) => {
  useEffect(() => {
    loadActions();
  }, [allowedTypes]);
};

// ✅ 正确：先收敛成稳定 key，再用它驱动 effect / callback
const allowedTypesKey = useMemo(
  () => (allowedTypes?.length ? allowedTypes : ['STRENGTH'])
    .map((type) => String(type).toUpperCase())
    .sort()
    .join('|'),
  [allowedTypes]
);

useEffect(() => {
  loadActions();
}, [allowedTypesKey]);
```

- [ ] 任何会发请求的 `useEffect/useCallback`，是否避免直接依赖渲染期新建的数组、对象、默认 props？

- [ ] 历史计划详情若按实例 `id` 直查，是否区分“历史详情权限”与“当前订阅门禁”，避免 `completed/archived` 计划被误拦截成 403？

### 并发 `loadData` 与 `loading`

```ts

const seqRef = useRef(0)
const loadData = useCallback(async () => {
  const my = ++seqRef.current
  try {
    setLoading(true)
    // ...
  } finally {
    if (my === seqRef.current) setLoading(false)
  }
}, [稳定依赖])
```
