# 机构系统设计文档

> 版本：v1.0 | 创建日期：2026-01-14 | 状态：设计草案

## 一、概述

### 1.1 背景

当前教链平台已实现**教练级私域**功能：教练可通过专属邀请码邀请学员注册，学员在"专属模式"下只能看到邀请教练。

本次扩展目标是将私域模式从**单个教练**扩展到**机构级别**，支持：

- 单体健身房
- 连锁健身房
- 培训机构
- 俱乐部等

### 1.2 核心价值

| 角色 | 价值                                         |
| ---- | -------------------------------------------- |
| 机构 | 集中管理旗下教练，统一品牌曝光，私域流量沉淀 |
| 教练 | 可选择加入机构获得更多曝光，或独立运营       |
| 学员 | 通过机构邀请进入，可浏览机构内所有教练       |
| 平台 | 拓展 B 端客户，提升商业化空间                |

## 二、系统架构

### 2.1 实体关系图

```
┌─────────────────────────────────────────────────────────────────┐
│                         平台管理员                                │
│                    (审核机构入驻申请)                             │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                        organizations                             │
│  (机构表：健身房、连锁品牌、培训机构等)                            │
│  - id, name, logo, description, status, invitation_code...      │
└─────────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
      ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
      │ org_admins   │ │ org_coaches  │ │  org_branches │
      │ (机构管理员) │ │ (机构教练)   │ │  (分店/门店)  │
      └──────────────┘ └──────────────┘ └──────────────┘
              │               │
              ▼               ▼
      ┌──────────────────────────────────────────────────┐
      │                    coaches                        │
      │          (现有教练表，新增 org_id 外键)            │
      └──────────────────────────────────────────────────┘
                              │
                              ▼
      ┌──────────────────────────────────────────────────┐
      │                     users                         │
      │     (用户表，新增 referrer_org_id 外键)           │
      └──────────────────────────────────────────────────┘
```

### 2.2 数据流

```
机构入驻申请 → 平台审核 → 机构激活
                           ↓
              机构管理员设置邀请码/邀请模式
                           ↓
              机构邀请链接：/register?org_invite=XXXXXXXX
                           ↓
              学员注册 → referrer_org_id 记录
                           ↓
              学员访问"发现教练" → 只显示机构内教练
```

## 四、功能模块设计

### 4.1 机构入驻流程

```
用户填写入驻申请
    ↓
提交营业执照、机构信息
    ↓
平台管理员审核
    ↓
审核通过 → 自动生成邀请码
    ↓
用户成为机构 owner，可添加其他管理员
```

#### 页面需求

| 页面           | 路由                      | 说明                 |
| -------------- | ------------------------- | -------------------- |
| 机构入驻申请页 | `/org/apply`              | 填写机构信息提交申请 |
| 机构入驻审核页 | `/admin/org-applications` | 管理员审核入驻申请   |

## 六、视野控制逻辑（扩展）

### 6.1 优先级

```
用户访问"发现教练"页面时：

1. 检查 referrer_org_id（机构邀请）
   → 有值且机构为 exclusive 模式 → 只显示机构内教练

2. 检查 referrer_coach_id（教练邀请）
   → 有值且教练为 exclusive 模式 → 只显示邀请教练

3. 无邀请来源
   → 显示所有教练 + 机构列表入口
```

### 6.2 代码逻辑更新

```typescript
// /api/student/visibility-status 返回结构
interface VisibilityStatus {
    // 教练级私域
    focusMode: boolean;
    focusCoachId: string | null;
    focusCoachName: string | null;
    referrerCoachId: string | null;
    referrerCoachName: string | null;

    // 机构级私域 [NEW]
    orgFocusMode: boolean;
    focusOrgId: string | null;
    focusOrgName: string | null;
    referrerOrgId: string | null;
    referrerOrgName: string | null;
}
```

## 九、与现有系统的兼容性

### 9.1 教练私域 vs 机构私域

| 场景                     | 处理方式                               |
| ------------------------ | -------------------------------------- |
| 通过教练邀请注册         | referrer_coach_id 有值，按教练私域处理 |
| 通过机构邀请注册         | referrer_org_id 有值，按机构私域处理   |
| 两者都有（理论上不应该） | 优先机构私域（覆盖范围更大）           |
| 都没有                   | 公域模式，显示所有教练和机构           |

### 9.2 独立教练兼容

- 教练可以选择**不加入任何机构**，保持独立运营
- 独立教练仍可使用自己的邀请码进行教练级私域
- 机构教练也可以有自己的邀请码（链接到自己，而非机构）

---

## 十、风险与注意事项

1. **数据迁移**：现有教练默认 org_id 为空
2. **权限隔离**：机构管理员只能管理自己机构的教练
3. **邀请码冲突**：教练邀请码和机构邀请码需要区分（可通过前缀或参数名）
4. **订阅归属**：学员订阅的是教练个人，与机构无直接关系
5. **分成机制**：如果有机构抽成，需要额外的财务模块设计
