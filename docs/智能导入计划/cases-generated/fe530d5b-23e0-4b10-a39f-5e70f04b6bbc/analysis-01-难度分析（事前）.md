## 案例难度分析（事前）

- traceId：`fe530d5b-23e0-4b10-a39f-5e70f04b6bbc`
- 输入文件：`stage1.input.txt`（与 `stage2.input.txt` 同源）

### 1. 输入结构概览

- 周/日标记：`W1D1 / W1D3 / W1D5 ... W4D5`（训练日用 D1/D3/D5 跳号表达）
- 休息日表达：`休一天 / 休两天`（有时独立一行，有时黏在动作行末尾）
- 动作+处方：混合了 `RM`、`组数×次数`、中文组数、`RPE`、`组休/组间歇`
- 存在“规则句”而非动作句：如“每组拉到降速临界点…共五组”
- 存在“复合动作句”：如“自重引体力竭然后双手悬垂力竭 两组…”
- 存在“累积逻辑”：如“5公斤引体累积（极限个数×5）个…够即可”

### 2. 识别难点清单（按风险从高到低）

#### 2.1 动作边界不清（复合动作/一行多语义）

- **复合动作**：`自重引体力竭然后双手悬垂力竭 两组 组间歇3分`
  - 风险：需要拆成两个动作（自重引体、双手悬垂），但“2 组”到底是每个动作 2 组还是合计 2 组存在歧义。
  - 期望：宁可拆成 2 个动作，并把歧义写入 `note`（例如“该处原文为两个动作串联，组数是否分别适用需人工确认”）。

- **动作行末尾黏休息日**：`单手悬垂交替力竭五组 组间歇30秒休一天`
  - 风险：`休一天` 应生成“独立休息日”，但非常容易被当作上一动作的 `note`，导致自然日占位错位。
  - 期望：强规则——识别到“休X天”必须产出 `type:"rest"` 的天，并占用 dayIndex/dayOfWeek。

#### 2.2 “只有规则，没有动作名”的行（应落到 dayNote/note）

- 示例：`每组拉到降速临界点，组间歇2分 共五组`
  - 风险：这不是动作名；如果被当成动作，会出现“凭空安排一个动作”，并污染动作库匹配。
  - 期望：
    - 优先作为 `dayNote`（当天整体规则），或附加到下一条动作 `note`；
    - `共五组` 不应单独生成动作，也不应覆盖真实动作的 sets（除非明确对应某个动作）。

#### 2.3 RM 强度 + 组数，但缺少 reps（次数）

- 示例：`负重引体10RM 三组 RPE9 组休3分`
  - 风险：最常见错误是把 `10RM` 当成 `10 次`，导致 reps 虚构。
  - 期望：如果该动作 attrs 包含“次数”，则 `sets=3`、`reps=null`（不猜）、强度=`10RM`、`note="RPE9"`，并在 UI 提醒“缺少每组次数”；（计时动作场景另见 2.4/断言补充）

#### 2.4 “累积/极限个数×N/够即可”无法完整结构化

- 示例：`5公斤引体累积（极限个数×5）个，每组RPE9，累积够即可`
  - 风险：无法可靠落到标准 `sets×reps`，但信息又必须保留给学员执行。
  - 期望：结构化字段只填“确定的”（如 sets 可能可取 ×5；重量 5kg 可作为 fixedWeight），其余全部写进 `note`；并且不要伪造 reps（若 attrs 包含“次数”，则 `reps=null`；若某些动作更适合计时/静力，则应通过 attrs 选择“持续时间”而非“次数”）。

#### 2.5 D1/D3/D5 跳号 vs 系统自然日

- 风险：文本里 D3/D5 是“训练日编号”，但系统 dayIndex/dayOfWeek 必须按自然日连续占位；休息日不占位会导致后续全部错位。
- 期望：每周补齐到 7 天，训练日+休息日按出现顺序顺延。

#### 2.6 同日同动作重复出现（需要保留为两个 actionSet）

- 示例：同一天有两条“负重引体”（5RM 3×3 + 10RM 三组 RPE9）
  - 风险：如果阶段 1 去重后阶段 2 误合并，会丢掉其中一个处方。
  - 期望：阶段 2 必须允许同日重复动作（同 actionId 多条），用强度/sets/reps 区分。

### 3. 测试人员“应重点核对”的断言（建议）

- **休息日占位**：`休一天/休两天` 必须变成独立 rest day（并占用 dayIndex/dayOfWeek）。
- **RM 不等于次数**：出现 `10RM` 但未写次数时，`reps` 必须为 `null`。
- **RM 不等于次数**：出现 `10RM` 但未写次数时（且该动作 attrs 包含“次数”），`reps` 必须为 `null`（不猜）。
- **累积逻辑不虚构 reps**：`累积/极限个数×N/够即可` 相关动作不应伪造 reps（attrs 包含“次数”则 `reps=null`），关键文本进入 `note`。
- **计时动作的属性选择**：对“悬挂/支撑/保持/计时”类动作，优先在动作库 attrs 勾选“持续时间”、取消“次数”；计划里应落到 `durationSeconds`，而不是用 reps 表达。
- **规则句不应生成“凭空动作”**：类似“降速临界点…共五组”应进入 `dayNote` 或某动作 `note`，而不是独立 action。
- **复合动作拆分**：`A 然后 B` 至少要保留两个动作的信息，不应把 B 丢失。

### 4. 难度等级（主观评估）

- **整体难度**：高
- **主要风险来源**：动作边界（复合句/规则句）+ 信息不完备（RM-only/累积）+ 自然日占位（休息日解析）
