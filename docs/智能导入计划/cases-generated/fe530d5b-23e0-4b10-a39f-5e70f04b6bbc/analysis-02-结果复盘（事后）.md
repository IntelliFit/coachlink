- 结果：`sets=3`，`reps=null`，强度 `10RM`，`note="RPE9"`

#### 3.3 重大问题 1：`5×3` 被解析反了（处方错误）

示例（Week2 Day1 第一条，来自 `stage2.merged.json`）：

- 原文：`负重引体5RM 5×3 组休 3分`
- 输出却是：`sets=3`、`reps=5`、强度 `5RM`

这会把训练处方从“5 组 × 3 次”变成“3 组 × 5 次”，属于高风险错误。

可能原因（需要工程师确认）：

- 模型把 `5×3` 解释为“5 次做 3 组”
- prompt/示例虽然写了 `4*4=4组4次`，但在 “RM + 5×3” 场景里模型仍可能颠倒

建议的修复方向（不要求立刻实现）：

- 在阶段 2 增加确定性校正：当检测到 `\d+[x×*]\d+` 且同时出现 `RM/%/kg` 时，强制把前者作为 sets、后者作为 reps（或至少输出 warning 并要求确认）。

#### 3.4 重大问题 2：规则句被当成“独立动作”（应为 dayNote/note）

示例（Week1 Day3 第一个 action）：

- 原文：`每组拉到降速临界点，组间歇2分 共五组`
- 输出产生了一个动作（actionId 为某个库内动作），并把 `note="每组拉到降速临界点"`、`sets=5`、`restSeconds=120`

这违反了“规则句不应生成新动作”的预期：它应进入 `dayNote` 或附加到后续动作的 `note`。

建议修复方向：

- 阶段 2 后处理增加规则：当某条 action 的“来源行无法定位到任何动作名”（`findFirstLineForAction` 找不到），且 note 呈现为“每组/共X组/降速临界点”这类规则句时，将其合并进 `dayNote` 并移除该 action。

#### 3.5 重大问题 3：复合动作未拆分（丢失“双手悬垂”）

示例（Week1 Day3 第二个 action）：

- 原文：`自重引体力竭然后双手悬垂力竭 两组 组间歇3分`
- 输出只生成了一个动作（自重引体），`note="力竭然后双手悬垂力竭"`，但没有生成“双手悬垂”的动作条目。

这会导致学员执行时漏动作。

建议修复方向：

- prompt 进一步强调：`A 然后 B` 必须拆为两个动作；如果组数不明确，允许两个动作都 sets=null，并把歧义写入 note。
- 或增加确定性拆分：输入中出现“然后/再/接着”且两侧命中不同动作名时，强制拆动作。

#### 3.6 数据形态问题：`fixedWeight` 不稳定

示例（Week1 Day5 的 5kg 累积引体）：

- 输出为 `{"intensityConfig": { "fixedWeight": 5 }}`

而当前类型/前端更稳定的形态应是：

- `fixedWeight: { value: 5, unit: "kg" }`

这会在前端或写库时埋下兼容性风险。

建议修复方向：

- 阶段 2 后处理对 `fixedWeight: number` 做归一：自动包成 `{ value, unit }`（与既有处理“type=fixed”保持一致）。
