## 项目技术栈概览

### 前端技术栈

| 技术 | 作用 | 为什么用它 |
|------|------|-----------|
| **Next.js 16** | React框架 | 提供页面路由、服务端渲染、API路由 |
| **React 18** | UI库 | 构建用户界面的核心库 |
| **TypeScript** | 类型系统 | 提供类型检查，减少错误 |
| **PrimeReact** | UI组件库 | 提供现成的美观组件（按钮、表格、对话框等） |
| **Tailwind CSS** | CSS框架 | 快速编写样式，统一设计系统 |
| **NextAuth** | 身份认证 | 处理用户登录、权限管理 |

### 后端技术栈

| 技术 | 作用 | 为什么用它 |
|------|------|-----------|
| **Supabase** | 数据库+后端服务 | PostgreSQL数据库 + 实时功能 + 存储 |
| **Next.js API Routes** | 后端API | 在Next.js中直接写后端接口 |
| **NextAuth** | 身份认证 | 统一管理用户登录状态 |

### 其他重要技术

- **Redis**: 缓存和会话存储
- **支付宝SDK**: 支付功能
- **Google Gemini AI**: AI功能（计划生成、聊天等）

## 核心概念解释

### 1. Next.js App Router（应用路由）

**什么是路由？**
- 路由就是"网址"，比如 `/coach/dashboard` 对应教练后台页面
- Next.js会根据文件夹结构自动创建路由

**文件结构对应关系：**
```
src/app/coach/dashboard/page.tsx
         ↓
访问地址：/coach/dashboard
```

**关键文件类型：**
- `page.tsx` - 页面组件（用户看到的页面）
- `layout.tsx` - 布局组件（导航栏、侧边栏等共享部分）
- `route.ts` - API接口（后端逻辑）

### 2. TypeScript 类型系统

**为什么需要类型？**
- 防止写错代码，比如把数字传给需要字符串的地方
- IDE会提示错误，提前发现问题

**常见类型：**
```typescript
// 字符串类型
const name: string = "张三";

// 数字类型
const age: number = 25;

// 布尔类型
const isActive: boolean = true;

// 对象类型（接口）
interface User {
  id: string;
  name: string;
  email?: string; // ? 表示可选
}

// 数组类型
const users: User[] = [];
```

### 3. 前后端分离架构

**前端（Frontend）：**
- 位置：`src/app/*/page.tsx`
- 作用：显示界面，处理用户交互
- 特点：运行在浏览器中

**后端（Backend）：**
- 位置：`src/app/api/*/route.ts`
- 作用：处理业务逻辑，访问数据库
- 特点：运行在服务器上

**Service层（中间层）：**
- 位置：`src/app/service/*.ts`
- 作用：封装API调用，简化前端代码
- 特点：前端调用Service，Service调用API

### 4. 数据库概念（Supabase）

**表（Table）：**
- 就像Excel表格，存储结构化数据
- 例如：`users`表存储用户信息，`coach_plan_templates`表存储计划模板

**字段（Column）：**
- 表的列，定义数据的属性
- 例如：`users`表有`id`、`name`、`email`字段

**行（Row）：**
- 表的一条记录
- 例如：一个用户就是`users`表中的一行

**外键（Foreign Key）：**
- 关联两个表的字段
- 例如：`coach_plan_instances.student_id`关联`users.id`

**查询（Query）：**
- 从数据库获取数据
- 例如：`SELECT * FROM users WHERE id = 'xxx'`

```typescript
import { NextResponse } from 'next/server';

            message: '用户未登录',
            data: null

    }

    // 2. 获取请求数据
    const requestData = await req.json() as RequestDto;

    // 3. 业务逻辑（访问数据库等）
    // ...

    // 4. 返回结果
    return NextResponse.json<ApiData<ResponseDto>>({
        success: true,
        message: '操作成功',
        data: result
    });
}
```

**检查要点：**
- ✅ 是否检查了登录状态？
- ✅ 是否从session获取userId（而不是从请求参数）？
- ✅ 返回格式是否为`{success, message, data}`？
- ✅ 是否使用了正确的类型定义？

#### 2. Entity文件（类型定义）

**位置：** `src/app/api/*/entity.ts`

**标准格式：**
```typescript
// 请求参数类型
export interface GetUserProfileDto {
    userId?: string; // 通常不需要，因为从session获取
}

// 返回数据类型
export interface GetUserProfileResponseDto {
    id: string;
    name: string;
    email: string;

```

**检查要点：**
- ✅ 请求参数是否合理（通常不需要userId）？
- ✅ 返回数据是否包含所有必要字段？

#### 3. Service文件（前端API调用）

**位置：** `src/app/service/*.ts`

**标准格式：**
```typescript
import { BaseService } from "@/lib/baseService";
import type { GetUserProfileDto, GetUserProfileResponseDto } from '@/app/api/user/get-profile/entity';

export class UserService extends BaseService {
    async getUserProfile(reqData: GetUserProfileDto) {
        const res = await this.post<GetUserProfileResponseDto>('user/get-profile', reqData);
        if (res.data && res.data.success) {
            return res.data.data || null;
        }
        return null;
    }
}
```

**检查要点：**
- ✅ 是否继承了`BaseService`？
- ✅ 是否使用了正确的类型？
- ✅ 是否检查了`res.data.success`？

**位置：** `src/app/*/page.tsx`

**标准格式：**

```typescript
import { UserService } from '@/app/service/userService';
```

## 如何检查代码是否正确

### 1. API接口检查清单

**✅ 必须包含：**
- [ ] 导入`NextResponse`、`getServerSession`、`supabase`
- [ ] 检查登录状态（`if (!session?.user?.id)`）
- [ ] 从session获取userId（不要从请求参数获取）
- [ ] 返回格式：`{success: boolean, message: string, data: any}`
- [ ] 使用类型定义（`import type`）

**❌ 常见错误：**
- 从请求参数获取userId（应该从session获取）
- 返回格式不正确
- 没有检查登录状态
- 直接在前端访问Supabase（应该通过API）

### 2. Service层检查清单

**✅ 必须包含：**
- [ ] 继承`BaseService`
- [ ] 使用`this.post()`或`this.get()`方法
- [ ] 检查`res.data.success`
- [ ] 返回`res.data.data`或`null`

**❌ 常见错误：**
- 直接使用fetch而不是BaseService
- 没有检查success状态
- 返回整个response而不是data

### 3. 前端组件检查清单

**✅ 必须包含：**
- [ ] 使用Service层调用API
- [ ] 使用toast显示错误（不是setError）
- [ ] Loading时使用骨架屏（不是简单的"加载中"文字）
- [ ] 适配移动端（响应式设计）
- [ ] 使用PrimeReact组件（不是原生HTML）

**❌ 常见错误：**
- 直接在前端访问Supabase
- 使用setError而不是toast
- 没有适配移动端
- 使用原生HTML而不是PrimeReact组件

### 4. 数据库操作检查

**✅ 正确示例：**
```typescript
// 查询数据
const { data, error } = await supabase
    .from('users')
    .select('*')
    .eq('id', userId)
    .single();

if (error) {
    return NextResponse.json({
        success: false,
        message: '查询失败',
        data: null
    });
}
```

**❌ 常见错误：**
- 没有检查error
- 没有使用正确的表名
- 查询条件错误

## 常见问题与注意事项

### 1. 权限检查

**问题：** 如何判断用户是否有权限？

**答案：** 通过session获取用户角色
```typescript
const session = await getServerSession();
const isAdmin = session?.user?.is_admin;
const isCoach = session?.user?.is_coach;
```

### 2. 前端不能直接访问数据库

**问题：** 为什么前端不能直接访问Supabase？

**答案：** 
- 安全考虑：前端代码暴露在浏览器，任何人都能看到
- 应该通过后端API访问，后端可以验证权限

**错误示例：**
```typescript
// ❌ 错误：前端直接访问数据库
const { data } = await supabase.from('users').select('*');
```

**正确示例：**
```typescript
// ✅ 正确：通过Service调用API
const data = await new UserService().getUsers();
```

### 3. 类型安全

**问题：** 为什么要定义这么多类型？

**答案：**
- 防止类型错误（比如传错参数）
- IDE会提示，提前发现问题
- 代码更易维护

**示例：**
```typescript
// 定义类型
interface User {
    id: string;
    name: string;
}

// 使用时会有类型检查
function getUser(user: User) {
    console.log(user.name); // ✅ 正确
    console.log(user.age);  // ❌ 错误：User没有age属性
}
```

### 4. 错误处理

**问题：** 如何正确处理错误？

**答案：**
- API层：返回`{success: false, message: '错误信息'}`
- Service层：检查success，返回null或抛出错误
- 前端：使用toast显示错误信息

**示例：**
```typescript
// API层
if (error) {
    return NextResponse.json({
        success: false,
        message: '操作失败',
        data: null
    });
}

// Service层
if (!res.data?.success) {
    return null; // 或抛出错误
}

// 前端
try {
    const data = await service.getData();
    if (!data) {
        toast.error('获取数据失败');
    }
} catch (error) {
    toast.error('网络错误');
}
```
