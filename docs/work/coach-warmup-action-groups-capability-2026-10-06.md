# 教练热身文章与可复用动作组合：能力核查

日期：2026-10-06（Asia/Tokyo）

## 用户需求

用户询问教练专栏/文章是否支持上传热身教学视频，以及能否从当前动作库选择多个热身动作，保存为动作组并整组加入计划；也提出超级组的可能形态。本轮按能力核查及方案讨论处理，尚无明确实施或发布指令。

## 当前源码能力

- Web 教练内容编辑器 `src/app/dashboard/content/ContentEditor.tsx` 使用 `RichTextEditor`。正文工具栏已有“插入视频”，可选择本地文件或视频 URL。
- `src/components/RichTextEditor.tsx:176` 本地插入仅接受 MP4/WebM/OGG，单文件上限 10MiB。实际通过 `FileReader.readAsDataURL` 将视频写入正文 HTML，没有调用云存储上传接口。多个视频会累计增加正文请求体，不能以单文件限制证明整篇发布一定成功。
- `src/components/tiptap-extensions/Video.ts` 生成带 controls 的 HTML video。URL 插入校验仅为 `new URL()`；实际需要可供播放器读取的视频地址，普通视频网站分享页不能当成视频文件直链。
- Web 详情 `src/app/coach/content/[id]/page.tsx` 渲染正文 HTML，并单独展示 `media_urls` 中的媒体。
- 小程序教练编辑 `apps/wechat/src/coach/content/edit/index.tsx` 有“视频内容”类型，但正文仍是 Textarea，没有文件选择/上传入口。小程序详情 `apps/wechat/src/content/content-detail/index.tsx` 用原生 Video 展示 video 类型的 `media_urls`，正文用 RichText；Web 插入正文的 video 并未走这个原生 Video 分支。本轮没有实际测试跨端播放，不能宣称两端都支持正常播放。
- Web 计划编辑通过 `PlanDayCard` 的 `onAddActionSet` 每次新增一个项目。`BatchActionsDialog` 支持在选定多天追加同一个动作，并非同时追加多个动作或选择已保存动作组合。
- 现有 `group_title` 为逻辑分组标题；`one-filter` 用于问卷选项动作，不是超级组。源码未找到可复用动作组合管理、整组插入、组内轮次交替执行的完整链路。样例动作名出现“超级组：引体+臂屈伸”不足以证明已有结构化超级组支持。

## 建议形态（待确认）

建立可复用“动作组合”：从既有动作库多选动作，保存名称、顺序、各动作组次/时长、休息及说明，可关联一篇热身教学文章或总览视频。单动作示范继续使用现有动作视频引用，避免每个计划重复上传。

计划编辑提供“添加动作 / 添加组合”；选择组合后一次插入全部动作及其默认参数，并可针对当前计划调整。普通热身采用顺序执行；超级组/循环组另外保存每轮顺序、轮数、动作间及轮间休息，执行页据此交替，不能把普通批量添加当成超级组已实现。

建议将教学内容与可执行组合关联：文章讲解流程和示范，组合承接执行和记录，计划引用组合。编辑组合模板后不应自动改动已分配计划或历史训练，插入计划时应固定当时的内容快照。

较长教学视频建议上传云存储后保存 URL，并补齐 Web/小程序原生播放展示；目前正文 Base64 方式不适合多段或较长教学视频。
