# 微信小程序临时免费运营版

## 范围与依据

用户于 2026-10-02 授权先查清、写好方案，再实施免费版。仅本地实现及验证，不含提交、推送、部署、上传或提审授权。此前等待 XPay 配齐的发布方案改为先准备免费候选版；正式发布仍需另行确认。

依据微信[虚拟支付指南](https://developers.weixin.qq.com/community/minihome/doc/00002cf077cd4810fee42f4b865c01)，虚拟商品购买/支付必须 XPay，不能站外引导。真正无虚拟购买的免费版本可并行准备，是规则判断，不保证微信审核。审核及公开版本保持同一行为。

## 选定架构与排除方案

1. 在共享 core 中放置编译期 `WECHAT_FREE_RELEASE` 策略（当前为 true）。没有开发/审核/正式差异，也不使用 Apollo 远程收费开关。恢复收费需改策略、重建、验证、新版本提审。
2. 小程序统一请求附加固定免费版本标识；原始训练视频上传同样附加。服务端结合编译期策略提供免费平台权益，并在订单接口再次拦截。标识只选择公开免费产品策略，不是身份认证或私有数据授权，原有鉴权/所有权检查必须保留。
3. 小程序专属支付接口在服务端免费版本中无条件关闭，不依赖前端标识；共用的 Web/API 接口只关闭小程序标识请求，Web/App 既有商业行为不擅自改变。旧免费客户端即使后端恢复收费也禁止创建收费订单。
4. 免费 AI 使用独立 Redis key（用户+北京时间月份+策略版本），原子限额，失败关闭；不修改 student_memberships 或 paid quota。存储使用原有统计，临时总量仅在响应/校验中取更大值。
5. 页面用免费权益页和暂停服务说明处理老路径/深链；保留收费组件源码供后续恢复，不能仅隐藏首页按钮。已有订单页、退款回调、汇付保护期/真实划转/钱包提现代码不改。

不采用：全员写入 premium（无限 AI 与权益污染）、只藏按钮（API 仍收费）、所有商品金额设 0（伪订单/教练服务污染）、关闭所有 subscription 检查（破坏真实教练合同）。
