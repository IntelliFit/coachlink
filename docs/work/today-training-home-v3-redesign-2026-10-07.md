## 首页的信息安排

1. 顶部一行：当前计划选择器、月份/月历、更多。保留多教练与个人计划的统一选择；不恢复昵称、问候、教练头像和重复的大标题。
2. 周历常驻：打开即可看见七天，直接选日；“月历”是明确的文字入口，可查看整期排期与计划总进度。复用当前计划的排期模型，不能把自然日期直接当作训练日序号。
3. 一行摘要：日序、动作数、当次完成组数。无需额外总览大卡，不重复显示多层训练标题。
4. 有内容的动作行：名称、组次/负重/休息、当次教练要求、明确的“动作讲解”。采用一个分组列表加细分隔线，允许内容自然增高、滚动；不靠隐藏要求来维持短页面。
5. 主按钮是开始/继续训练。实际轻任务仍在列表中出现；没任务不放空卡。低频管理留在更多。

保留必要训练信息并不等于把旧版所有模块加回首页。应减少重复介绍和装饰占位，而不是减少学员准备训练所需的内容。

## 点击行为

| 场景 | 交互规则 |
| --- | --- |
| 预览计划中的动作 | 点动作名称或“动作讲解”打开只读详情，展示视频、动作说明和当次教练要求；不调用 startExecution，不启动计时，不写执行记录或扣服务额度 |
| 未来/未开放训练日 | 可以预览动作与讲解；开始训练仍受原有计划顺序和权益规则约束，预览不以先开练为条件 |
| 开始训练 | 只有明确点击开始，才进入现有执行流程；上下文包含所选 instance/dayIndex/actionIndex |
| 训练中看讲解 | 当前动作标题附近保留同名“动作讲解”入口；返回时保持当前动作/组、已输入内容、完成情况和计时状态 |
| 完成训练 | 保留上一轮确认的设计：执行页完成总结自动显示生成打卡图，首页回显已完成/查看记录 |
| 多来源切换 | 替换所选计划的日期、处方、要求、动作素材和进度；不同教练/个人计划互不混合 |
| 无有效计划 | 保留即兴锻炼/找教练；已有个人计划继续展示，订阅待制定时可联系教练 |

## Web 与小程序一致性要求

两端对齐内容与状态，不要求照搬 Web 的大卡尺寸。后续实现至少满足：

- 动作名称、组次、重量/RM/强度、休息按同一处方口径显示；递增/降重等逐组结构不能压成误导性的单一数值。
- 区分动作库的通用说明与当前计划的教练备注，两者都能查看；本次要求优先出现在动作旁，不用通用说明覆盖。
- 统一 url/video_url 的兼容、媒体地址解析与动作身份；预览和执行复用同一讲解组件/读取规则，避免各自维护一套字段。
- 有视频时可播放，有文字无视频时展示文字说明；无素材时明确没有讲解，不伪造播放按钮或黑色空播放器。
- 视频直链和外链按小程序实际能力处理，外链明确其打开方式；“复制地址”不算视频播放成功。
- 讲解详情不能只依赖上一个页面临时写入的数据；缓存按动作身份和已有规则复用，并在缺失时只读获取内容。计划备注应绑定当次计划上下文，不写进全局动作说明。
- 历史执行优先保留其快照与当时处方，不能因动作库更新而混入另一计划的训练要求。

## 实施后应由用户验收的路径

1. 打开首页，不点击任何隐藏入口即可找到周历和当次处方；必要备注能读全。
2. 选当前和未来训练日，打开讲解并返回；没有新增 execution，日期/计划保持。
3. 开始训练、输入组记录、打开讲解、返回；输入与进度保留，讲解内容与预览一致。
4. 切换两位教练和个人计划，确认动作、视频、备注和进度各自对应。
5. 分别检查有视频、仅文字、无素材、外链、缓存缺失与媒体加载失败；不能把有入口当作播放验收。
6. 完成训练后仍能生成打卡图；轻任务、补记和联系教练入口仍可用。

本节为当前源码静态核对及设计安排，不代表端到端验证通过。主要依据 `apps/wechat/src/training/training-execution/index.tsx` 的逐组表单、完成组回看、上传处理、增删动作/组、计时和完成流程，以及首页现有功能入口。

| 层级 | 必须保留的信息或操作 | 新布局位置与约束 |
| --- | --- | --- |
| 计划/日期 | 多教练与个人计划、周历/月历、训练日及进度 | 顶部选择器和常驻周历；按 instance/dayIndex 隔离，日期与训练日映射沿用原逻辑 |
| 动作预览 | 名称、组次、重量/RM/强度、休息、必要备注、逐组差异 | 首页动作列表直接呈现核心处方；有逐组差异可展开查看全部组，不压成单一平均值 |
| 动作讲解 | 通用说明、演示视频、当次教练要求 | 预览和执行的动作标题旁均有明确入口；查看不触发开练 |
| 每组计划 | 组序号、计划重量/次数/休息等、待做/当前/完成状态 | 每组摘要及展开内容；计划值和实际值区分，不覆盖原处方 |
| 每组记录 | 实际重量、次数及各自加减控件、RPE | 当前组默认展开，已有输入规则与必填校验保留 |
| 每组进步 | 手动标记/取消进步组、已保存 PR 标志 | 当前组独立可见的勾选入口；组完成后在该组摘要显示 PR |
| 自动记录 | e1RM、自动新纪录标志 | 已完成组摘要显示新纪录，展开可查 e1RM；不能把手动进步组等同自动破纪录 |
| 每组备注 | 学员备注输入、保存、回看 | 当前组有明确“备注”入口；有内容自动展示，收起组显示备注标志；与教练要求分开 |
| 每组视频 | 相册/拍摄上传、换视频、粘贴链接、预览、上传中及失败反馈 | 当前组直接显示“上传本组视频”，已有附件显示“查看/更换”；贴链接可在该入口内选择，不能放全局更多里 |
| 已完成组 | 实际重量/次数/RPE、休息、e1RM、备注、视频、编辑/保存/取消编辑 | 点该组展开；依原有权限允许编辑，强制只读不提供写入口；不能只留下对勾 |
| 切组/切动作 | 选择不同待做组、查看已完成组、动作展开收起 | 非当前组显示摘要，点开后获得完整操作；输入草稿不能串组或丢失 |
| 额外训练 | 新增一组、从动作库搜索/选择动作、批量加入、删除额外组/动作 | 动作末尾“新增一组”、动作列表末尾“添加动作”；仅删除原规则允许的 student_extra 内容，保留确认 |
| 计时 | 总训练时长、组间休息、加减 10 秒、结束休息、最小化及恢复 | 执行页顶部总时长及休息面板/浮窗；看讲解或视频返回保留计时 |
| 非力量任务 | 饮食内容、有氧距离/时长、习惯完成及记录回看 | 保留各自字段和验证；有任务就展示，不能为统一表格改成只有重量/次数 |
| 训练结束 | 正常完成、一键完成的原条件、待完成轻任务提示 | 保留原状态判断；不能因完成力量组就错误宣布整日完成 |
| 异常/恢复 | 超时补记完成、重新训练、满足原条件时取消误开训练 | 状态对应位置显示；不能无条件允许取消/重开，不能重复扣权益 |
| 完成反馈 | 难度选择、反馈正文、发送给教练/跳过 | 沿用原反馈流程和提交条件 |
| 训练总结 | 训练统计、动作记录、肌群热图、生成打卡图、返回 | 完成执行后显示，并可从已完成记录重新进入；首页回显完成状态 |
| 辅助入口 | 补记、联系教练、计划进度、轻任务管理、即兴训练、找教练 | 原入口迁移必须明确去向；无计划/有个人计划/待制定计划分别按已确认规则展示 |
| 状态持久化 | 当前动作/组、输入草稿、附件、完成记录、首页进度 | 复用既有缓存与同步工具、60 天策略；保存返回首页立即回显，云端刷新不能错误串计划 |

### 当前组的交互结构

这是同一页内的展开状态，不新增多层页面：

```text
负重引体（底部暂停）                 动作讲解
教练要求：底部停顿……

第 1 组  7.5 kg × 7 次   已完成 · PR · 视频  ›

第 2 组                         当前组
计划 7.5 kg × 7 次 · 休息 5 分钟
实际重量 [ − 7.5 + ]   次数 [ − 7 + ]   RPE [ 8 ]
□ 标记进步组
上传本组视频                         添加备注
（已有视频/备注在这里直接显示，可查看或继续编辑）
                  [ 完成本组 ]

第 3 组  7.5 kg × 7 次   待完成             ›
……
+ 新增一组
```

“动作讲解”是教练/动作库的教学素材，“本组视频”是学员训练记录，两者数据和入口必须分开。非当前组收起的是编辑控件，不是删除数据或操作；已完成组点开后能回看详细记录并在允许时编辑。

### 源码核对发现的待验证差异

以下为实施前发现的问题；本地修复及仍需实际上传/回读验收的边界见两端对齐实施记录，不能用旧条目推断当前代码仍完全未改。

- 计划模式 completeSet 发送 rpe、notes、videoUrl、isPR；即兴模式当前调用只传 actualWeight、actualReps、notes，但随后内存仍会写 RPE/PR/视频。不能凭本地显示就承诺即兴模式这些字段已落云端；实施时需核对接口并验证重新进入后的回读。
- 已结束训练存在 canCorrectCompletedSets 分支，允许特定非强制只读入口更正已完成组；但上传/贴链接处理器目前直接拦截 isReadOnly。不能把“允许编辑数值”说成“所有历史记录均能补视频”。需要在实现前明确并对齐可编辑范围，保留已有能力，不能用本次重设计静默收紧权限。
- 当前图片尚不覆盖上述补充。这次仅更新设计规格，没有修复上述代码差异，也没有验证实际上传、自动 PR、记录回读或历史编辑。

### 防遗漏验收清单

1. 当前组填重量/次数/RPE、标进步组、写备注、上传或贴视频链接；完成后展开该组，逐字段核对，再离开重进检查云端回读。
2. 手动 PR 与自动新纪录分别检查；e1RM 无值时不伪造。换组、换动作、打开讲解返回时草稿、附件和计时不丢失。
3. 在训练中编辑已完成组并保存/取消；结束后允许更正的入口与强制只读入口分开检查，包括视频权限。
4. 额外组/动作可按原条件增删；计划原始组/动作不因布局调整意外获得删除能力。
5. 有氧、饮食、习惯、休息计时、超时补记、取消误开、完成反馈及打卡图逐项检查。
6. 两位教练、个人计划、即兴训练各核对记录所属来源和刷新后结果；Web 与 mini 的已有字段和状态逐项比较，不以单张效果图判定功能完整。
