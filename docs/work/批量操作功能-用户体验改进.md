# AI 批量操作功能 - 用户体验改进

## 改进内容

### 1. ✅ 开发模式下显示统计信息

**实现位置**: 后端 `route.ts` + 前端组件

**功能**:
- 自动检测 `NODE_ENV === 'development'`
- 显示 Token 使用量（提示词 + 生成 + 总计）
- 显示 AI 调用耗时
- 显示总处理时间

**示例输出**:
```
📊 Token: 1245 (提示:856 + 生成:389) | 耗时: 1234ms
分析完成，共发现 8 处修改 (总耗时 2145ms)
```

### 2. ✅ 移除代码显示

**改进**:
- 不再向用户展示生成的 TypeScript 代码
- 用户只看到友好的操作描述
- 开发者可以在后端日志查看代码（如需调试）

**之前**:
```
📝 将引体向上替换为跑步
```typescript
const targetAction = findActionByName("跑步");
if (targetAction) {
    trainingDays.forEach(day => {
        // ... 大量代码
    });
}
```
```

**现在**:
```
📋 将第1-7天的引体向上替换为跑步，并调整组数为5组
```

### 3. ✅ 用户友好的修改描述

**改进**:
- AI 生成 `actionPlan` 字段，用人类语言描述执行计划
- 每个修改都会实时显示具体内容
- 按训练日分组显示修改

**示例**:
```
📋 将第1-7天的深蹲替换为硬拉，并调整组数为5组
✏️ 第1天：将 深蹲 替换为 硬拉；深蹲的组数从 3 改为 5
✏️ 第2天：将 深蹲 替换为 硬拉；深蹲的组数从 3 改为 5
✏️ 第3天：删除 引体向上
```

### 4. ✅ 修改预览和确认机制

**核心改进**: 
- **不再立即保存到数据库**
- 执行分析后显示修改预览表格
- 用户可以查看所有修改详情
- 用户确认后才应用修改

**工作流程**:
```
用户输入指令
    ↓
点击"分析修改"
    ↓
AI 生成操作代码
    ↓
在沙箱中执行
    ↓
分析差异并显示预览表格
    ↓
用户查看并确认
    ↓
点击"应用修改"
    ↓
保存到数据库
    ↓
刷新页面显示最新内容
```

## 新的消息类型

### SSEMessage 类型更新

```typescript
export type SSEMessage =
    | { type: 'progress'; message: string }  
    // 进度信息
    
    | { type: 'action_plan'; plan: string }  
    // 执行计划(用户友好的描述)
    
    | { type: 'modification'; dayIndex: number; actionName: string; description: string }  
    // 具体修改描述(按训练日)
    
    | { type: 'stats'; tokenUsage?: {...}; duration?: number }  
    // 统计信息(仅开发模式)
    
    | { type: 'preview_result'; originalTrainingDays: any; updatedTrainingDays: any; modifications: ModificationDiff[] }  
    // 预览结果(不保存)
    
    | { type: 'error'; message: string };  
    // 错误信息
```

### ModificationDiff 类型

```typescript
export interface ModificationDiff {
    dayIndex: number;        // 训练日索引
    actionName: string;      // 动作名称
    field: string;           // 修改字段(组数/次数/重量等)
    oldValue: any;           // 原值
    newValue: any;           // 新值
}
```

## 修改预览表格

### 表格列

| 训练日 | 动作/项目 | 修改项 | 原值 | → | 新值 |
|--------|----------|--------|------|---|------|
| 第1天 | 深蹲 | 组数 | ~~3~~ | → | **5** |

### 表格特性

- 原值显示为删除线 + 灰色
- 新值显示为绿色加粗
- 支持滚动查看大量修改
- 按训练日和动作分组

## 差异分析算法

### analyzeModifications() 函数

**检测以下类型的修改**:

1. **训练日级别**:
   - 添加训练日
   - 删除训练日
   - 类型变更 (训练日 ↔ 休息日)
   - 备注修改

2. **动作级别**:
   - 添加动作
   - 删除动作
   - 替换动作 (ID 变更)

3. **参数级别**:
   - 组数 (sets)
   - 次数 (reps)
   - 重量 (weight)
   - 休息时间 (rest_seconds)

```

## 前端组件改进

### 状态管理

```typescript
const [previewData, setPreviewData] = useState<{
    originalTrainingDays: any;
    updatedTrainingDays: any;
    modifications: ModificationDiff[];
} | null>(null);
```

### 两阶段操作

1. **分析阶段**: 
   - 按钮: "分析修改"
   - 调用 `/api/plan-lib/batch-operation`
   - 只预览，不保存

2. **应用阶段**:
   - 按钮: "应用修改"
   - 调用 `/api/plan-lib/apply-batch-operation`
   - 保存到数据库

### 用户操作流

```
[输入指令] → [分析修改] → [查看预览] → [应用修改] / [重新分析]
```

## 错误处理

### 友好的错误提示

**之前**:
```
❌ Error: Cannot read property 'actionId' of undefined
```

**现在**:
```
❌ 执行失败：无法找到指定的动作，请检查动作库
```

### 边界情况处理

1. 找不到动作: "在动作库中未找到匹配的动作"
2. 参数缺失: "缺少必要的参数设置"
3. 没有修改: "未发现需要修改的内容"

## 性能优化

### 1. 避免不必要的保存

- 用户可以分析多次而不保存
- 只在确认后才写数据库
- 减少不必要的数据库操作

### 2. 差异分析优化

- 深拷贝原始数据用于对比
- 高效的数组遍历和对比算法
- 按训练日批量处理修改

### 3. 前端渲染优化

- 虚拟滚动的日志区域
- DataTable 的懒加载
- 分页显示大量修改
