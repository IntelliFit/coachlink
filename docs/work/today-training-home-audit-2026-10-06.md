# 小程序训练首页：截图与源码诊断

日期：2026-10-06。范围：学员个人训练首页，包含教练计划和我的计划两种来源。用户枭马葛反馈首页信息过多、阅读和操作方向不清；同时具有学员与教练身份，但截图中的两种计划来源不是两种角色。

本轮交付是诊断与信息层级建议。未修改业务代码、测试、数据库或发布；建议未记为用户已确认的改版方案。

## 证据与两个观察步骤

1. 教练计划首页：可识别开始训练主按钮，但同一场训练摘要反复出现，补记、切换计划、整期进度、空任务和分享入口均单独占位，阅读负担大。

## 页面为什么会显得乱

从当前结构看，首页把多个模块各自的标题、摘要和入口直接串联，没有围绕“今天练什么、现在做什么、已经完成多少”形成统一层级。无法仅凭当前结构断言历史上是谁或哪次改动造成堆叠。

- **重复表达同一训练**：“今天重点 / 连续力量训练”“今日安排 / 连续力量训练”“计划训练”均指向选中日的力量训练，动作数、组数至少重复三处。
- **时间尺度混在一起**：当天组数和整期计划完成百分比分别有价值，但独立大卡让用户不断切换理解口径。
- **辅助操作占据主路径**：补记在训练主卡之前，全宽展示；即兴锻炼在主卡中占第二个全宽按钮；联系教练、切计划、生成打卡图也各占一个层级。
- **空内容仍占版面**：没有轻量任务仍显示标题、空卡和新增按钮，制造额外待办感。
- **状态上下文不一致**：第二图的完成横幅未说明是否对应当前选中日期/训练日，下面未开始的训练仍称“今日安排”。这首先是可见的表达冲突，尚不能据此断言数据库记录错误。
- **专业和内部措辞过多**：“连续力量训练”“模块”等词不能直接帮助用户决定下一步；首页应优先显示可理解的训练名称和具体任务。

可见优点：品牌色主按钮容易识别，动作名称和完成组数能看清，两份计划来源也可区分。主要问题在结构和状态，而非单纯配色。

## 建议的信息结构

首页围绕日期、当前训练和下一步操作呈现。功能保留，按使用时机安排入口。

| 现有内容 | 建议位置与行为 |
| --- | --- |
| 问候 + 本周日历 | 紧凑日期区；月历按需展开，主训练内容尽早进入首屏 |
| 教练计划 / 我的计划切换 | 一个明确显示当前来源的紧凑选择器；切换后日期、状态、训练内容同步更新 |
| 教练身份与联系 | 当前计划来源一行；联系放来源详情或更多菜单 |
| 今天重点 + 今日安排 + 计划训练 | 合并成一个训练区：具体标题、动作数/组数、当次状态、一个主按钮 |
| 动作卡的重量、休息、强度备注 | 首页简洁预览动作名称与组数；执行页保留完整训练参数和逐动作直达能力 |
| 当前计划进度 | 计划详情；首页可保留一个低权重的查看计划入口，避免独立大卡 |
| 补记已练过的这一天 | 对应日期/训练记录的更多菜单，保持实际日期校核与原有业务语义 |
| 即兴锻炼 | 次级文字入口；无计划时可成为主操作 |
| 轻量任务 | 有实际任务时才显示内容；新增入口收进更多菜单；休息日有任务时成为主体 |
| 今日成果 / 整日打卡图 | 有实际记录后，在完成或记录回顾区域提供；未开始时不占独立板块 |

首页预期阅读顺序：日期和计划来源 → 今天具体练什么与完成情况 → 开始/继续/查看记录 → 简洁动作预览 → 有内容的其他任务。

## 状态与日期规则建议

- 当前训练区的日期、计划来源、完成提示、组数和主按钮必须指向同一个选中上下文。
- 未开始显示“开始训练”；进行中显示“继续训练”；该场完成显示“查看训练记录”。
- 今天完成一场后若自动推进下一训练日，应明确区分“今天已完成的记录”和“下一次训练”，不能同时把二者称为今日安排。
- 浏览历史日期使用明确日期或当天安排；休息日使用恢复/实际轻任务，无计划使用自由训练或找教练入口。
- 力量训练完成但其他任务未完成时，分别准确表达，不能把全日完成和单模块完成混为一谈。

## 可读性风险与验证边界

截图里多处灰色小字、深色卡中的即兴按钮和被截断的动作备注存在可读性风险；本轮未做像素对比测量，不能给出精确对比度或合规结论。日期圆点的颜色含义不明显，后续应补明确说明或可感知状态，不能只靠颜色。

本轮没有进入微信开发者工具、点击实际页面、切换登录态或读写真实训练数据；没有对请求性能、点击范围、原生滚动、读屏或真实账号状态进行验收。若后续实施，按仓库规则使用 weapp-devtools，在确认归属的窗口中串行验证未开始/进行中/完成、不同日期/计划来源、休息日、有无轻任务与无计划等状态，保留截图和至少一条交互路径，恢复所有测试状态并收尾。

建议下一步先按上述结构做首页信息层级调整，并同时修正日期与状态表达；不应只缩小字体或重新装饰卡片。
