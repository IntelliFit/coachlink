## 本次结果

修复当前 `coach_plan_instances / plan_instance_executions` 主链：Web 今日训练与执行页、微信首页/执行/旧计划详情入口、App 入口与执行能力。之前的详细原因见 [判断冲突审计](training-entry-decision-audit-2026-10-08.md)。不是把服务端身份、权益或并发保护移除。

流程现在是：

1. 首页读取聚合进度，使用共享 `trainingEntry` 同时决定按钮文案与进入意图。
2. 路由只带 `execute / preview / review`；须知保存意图，不再保存旧的“可写/只读”结论。
3. 明确开练重新调用服务端 start；身份、归属、服务周权益、计划更新及顺序由后台重新校验。
4. 只有云端确认的真实执行记录可获得对应操作能力。失败展示真实原因与重试，不让已显示的预览遮住失败。
5. 写入成功后，同步执行快照和首页 execution、推进位置、完成日期；旧首页响应不得覆盖这之后的新缓存。

| 当前状态 | 行为 |
| --- | --- |
| 预览/旧 readonly 链接 | 不自动开练、不启动可写表单；资格满足时可明确选择开始 |
| 进行中且云端确认 | 可录组、计时、完成；按钮显示继续训练 |
| 已完成 | 查看记录与原有更正入口，不作为新一轮开练 |
| 超时 | 不显示普通可写表单；可按实际日期补记，或确认后重新开始 |
| 同步失败/只有旧快照 | 保留可见内容、明确错误与重试；缓存不能授予写权限 |
| 旧的越序 active 记录 | 显示“查看待处理记录”，不再显示误导性的“继续训练” |

操作能力用于界面展示，**不是授权凭证**。即使刚核对过，下一次写入时服务端仍可因实际状态变化拒绝；此时必须展示原因，不能悄悄降级为预览。

## 具体修复

- 新建 core `trainingAccess`，统一字段兼容、跨纯休息日、主按钮意图、记录能力和同日 attempt 选择；主站旧 `planProgress / planDayFacts` 路径保留兼容转导出，规则在 core 共用。
- D76/D77 都无任务时允许 D78；休息日只要存在处方任务（含未知类型/蛇形字段）就不能当作纯休息日跨越。
- 已完成事实优先于同日重复 active 记录，避免完成后又显示继续；进度事实与展示 attempt 仍是明确分开的概念。
- get-instance 和旧 next-day 接口使用同一进度；next-day 不再独立只看 completed、忽略 abandoned。小程序旧详情入口不再混用两次不同时间的查询。
- start 先校验该实例的归属/权益，再做过期执行与计划版本生命周期处理；删除“只要还有任意一个 active 订阅就放行”的旧兜底分支，保留具体实例权限。
- mini 开始接口不再把业务错误折叠成 null。预览、缓存、须知、新开练、超时重开失败都有可恢复路径；旧 readonly URL 不会因一次明确的开始而永久锁定。
- Web 已超时训练不能继续录组；提供补记和确认重开。显式预览不计开始埋点、不创建执行；更换计划/天/意图时重建页面状态。
- App 接入同一跨休息与状态能力规则；云端未确认时禁止写，失败可重试。重进页面重置意图，并隔离不同路由请求的迟到响应。
- 新建 core `planCacheProgress` 给 mini/App 更新缓存进度和实际完成日期。缓存不把补记提交日期当训练日期；原 60 天、账号隔离与键名保持。
- 区分本地预热与云端结果：预热不可擦掉真实快照，但云端明确不存在记录时可以替换旧快照；不再用旧缓存覆盖云端的“没有这条记录”。
- React 检查项用于明确事件触发、异步旧响应隔离、路由重进状态和重复请求保护，未借此改换 UI 框架或扩大支付范围。
- 顺带更正同一执行页暴露的即兴视频返回类型、读取方法与轻任务计数返回字段；未重做用户既有处方、订阅结转或日历历史数据。
