# 器材分类筛选：现有描述核对与方案

进展：用户随后明确“好的 开始修改吧”。2026-10-06 已本地实现并通过 API/小程序交互验证，详情见本文末尾；以下 990 条数据与方案是最初只读分析的历史快照。

## 用户需求与范围

用户希望从现有名称/描述提取单杠、双杠、云梯等器材，增加筛选，并扩展更多具体训练器材。一个地点可能包含多种器材，重点是现场器材区和训练信息。用户本轮以“这样会不会更好”询问方向；本轮完成只读核对、分类候选及方案，没有修改客户端或线上数据、不直接发布新功能。

## 实际数据

2026-10-05 JST 08:00 左右，通过正式公开 POST https://coachlink.fit/api/streetlifting-index/locations/list 只读33页、3并发，没有使用身份令牌。共990条唯一点位，各页total一致；762条有描述、228条没有描述。

当前客户端类型、后端列表类型及create/update DTO没有独立器材字段。现有搜索同时匹配名称、国家、省、城市、地址和描述：搜“双杠”返回286条，但名称/描述实际提及双杠/单双杠为285条；否定句和其他字段也能命中，搜索数不等于器材存在数量。

实际例子：水电街“单杠，双杠都有”；四维花园“小区内有单双杠云梯”；语言大学家属院“粗单杠，没双杠，有肋木架……校园单杠点没肋木架可以来这里”，后面的否定指另一地点，不能否定整个地点的肋木架。北京语言大学“肋木架缺失”应排除；曲江文化运动公园“好像有那种吊环器械”需确认。坏损、生锈、晃动应独立记录状态，不能自动当成没有器材。

脚本、990条逐点候选及原文证据位于 artifacts/streetlifting-equipment/2026-10-05/；--reuse-snapshot 仅重分类已读快照，不再请求或写数据库。未做图片识别。

## 建议交互

- 第一阶段先做“全部器材 / 单杠 / 双杠 / 云梯”，肋木架和吊环有现有描述基础，可沿同一机制追加。一点多标签，卡片显示具备的器材。
- 器材与国家/省州/搜索条件共同生效；若开放多选，建议明确“同时具备所选器材”，例如单杠+双杠。多选AND是建议，未当用户已确认细则。
- 上传继续先地图选位置再补信息，新增简短“这里有哪些器材？”多选。描述可生成建议标签，用户核对或修改；不要求为分类重复填写文字或必填全部器材尺寸。
- 旧数据先提取候选，否定、比较另一地点、自带器材、损坏或不确定语气先核对；保留原描述、照片、贡献者和位置，不覆盖人工确认标签。未确认器材的点位保留在全部列表，不凭空承诺某类器材。
- 标记落到具体健身器材区；相邻器材可共用点，公园里相隔很远的器材区应分别建点。仅靠文字不能纠正粗略旧坐标，不能自动挪点。
- 高度、粗细、数量、双杠间距、遮雨、可否进入和坏损状态可逐步补充；先保留原描述，避免一次增加过多必填项。

## 实现注意事项与下一步

- 新筛选控件需要更新小程序包，单改后端无法让旧客户端出现控件；原国家筛选和排序、旧客户端/API保持兼容。
- 后端先按器材/地理条件过滤，再count和分页，不能仅筛当前30条。列表/附近/map-pins共用有效标签规则，避免地图和列表冲突。
- 复用streetlifting_location_cache_v1/60天缓存；器材参数纳入列表/map-pins键，草稿纳入器材字段，不另起互不相认的storage。
- 使用稳定器材code及可扩展类型定义，点位与器材为多对多关系；保留来源、确认状态、证据、更新时间，类型与可用状态/尺寸独立。
- 历史批量补标签须记录原值、可重跑且不覆盖人工确认；当前只有候选报告，无批量写入。
- 后续实现先本地，按weapp-devtools实机工具展示/交互核验。当前没有页面改动，不执行UI回归；没有修改已有测试、部署/上传/提审。

## 本地实现与验收（2026-10-06）

- 首版支持单杠、双杠、云梯，地点可以选择多个标签；多个筛选项采用 AND，界面明确“同时包含所选器材”。“全部器材”清空器材筛选，并保留国家、省州、名称/地址搜索条件。
- 列表卡片、附近结果、地图使用同一 core 规则。旧名称/描述直接生成读取时的候选标签，显示“据描述”；未识别点位显示“器材待补充”，仍在全部列表中。否定/拆除/不确定表述保守排除，不把缺少描述视为具备单杠，也不把生锈与器材类型混为一谈。有限规则仍可能误读跨地点比较等复杂语句，用户现场确认优先。
- 上传/编辑增加器材多选；未手动选择时描述更新会更新建议，手动选择或清空后不再覆盖。草稿复用已有 60 天缓存键，关闭重开保留确认标签/清空状态。地图回到列表保留器材条件；分页之前完成服务器筛选，不只过滤当前页。既有附近照片功能保留。
- Schema 首版用 nullable text[] equipment_types 表达一点多标签，无额外关联表。NULL 表示未确认并可读时推断，[] 表示已主动清空。GET/list/map返回来源；人工标签由现有 create/update 写入。老客户端没有该字段时不写新列、不清除原标签。SQL仅新增列与GIN索引，没有历史批量回填、照片识别、改动旧文本/贡献人/坐标。
- 稳定 code 与选项位于 packages/core/src/locationEquipment.ts，后续新增器材可沿同一字段、UI与匹配逻辑扩展。当前候选筛选用500条批次读取全体符合地理/搜索条件的记录，然后分页；当前1020点位实测可用。规模明显增长后可引入持久候选/索引化查询，同时保持手动标签优先；本轮未实现该优化。
