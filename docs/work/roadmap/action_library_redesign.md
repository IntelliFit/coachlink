# 动作库重新设计方案

> **版本**: v1.0\
> **创建日期**: 2026-01-09\
> **状态**: 设计中

---

## 一、问题

当前每个教练有独立的动作库，导致：

- 同一动作命名不一致，无法识别
- 学员跨教练的进步曲线无法关联
- 缺乏标准化基础

---

## 二、方案：公共库 + 私有库关联

### 2.1 核心思路

**最小改动原则**：在现有 `coach_actions` 表基础上，新增一个
`canonical_action_id` 字段，关联到新建的公共动作库。

```
┌─────────────────────────────────────────┐
│  公共动作库 canonical_actions           │
│  • 平台维护的标准动作字典               │
│  • 提供统一的命名和别名                 │
└─────────────────────────────────────────┘
                    ↑ 关联（可选）
┌─────────────────────────────────────────┐
│  现有 coach_actions 表                  │
│  • 新增字段：canonical_action_id        │
│  • 教练手动关联到公共库                 │
│  • 未关联的动作正常使用，不影响现有功能  │
└─────────────────────────────────────────┘
```

### 2.2 数据库改动

```sql
-- 1. 新建公共动作库表
CREATE TABLE canonical_actions (
    id TEXT PRIMARY KEY,           -- 如 "squat_low_bar"
    name TEXT NOT NULL,            -- "低杠深蹲"
    aliases TEXT[] DEFAULT '{}',   -- ["竞技深蹲", "Low Bar Squat"]
    category TEXT,                 -- "下肢"
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. 现有表新增字段（仅此一项改动）
ALTER TABLE coach_actions 
ADD COLUMN canonical_action_id TEXT REFERENCES canonical_actions(id);

-- 学员动作库同理
ALTER TABLE student_actions 
ADD COLUMN canonical_action_id TEXT REFERENCES canonical_actions(id);
```

### 2.3 AI 导入流程（简化版）

**当前阶段**：跳过公共库匹配，降低复杂度

```
AI 解析出动作名
        │
        ▼
┌─────────────────────────────────┐
│ 匹配教练私有库                   │
└─────────────────────────────────┘
        │
        ├── 找到 → 使用现有动作
        │
        ▼ 没找到
┌─────────────────────────────────┐
│ 创建纯私有动作                   │
│ (canonical_action_id = NULL)    │
│ 提示教练：去公共库关联此动作      │
└─────────────────────────────────┘
```

**后期升级**：自动匹配公共库并创建关联

## 三、操作流程

### 3.1 存量动作处理

教练进入动作库页面时，提示：

> "您有 X 个动作尚未关联公共库，关联后可获得更好的数据分析体验"

教练手动选择公共动作进行关联。

### 3.2 新建动作

- AI 导入创建的动作：`canonical_action_id = NULL`，提示教练关联
- 教练手动创建：可选择从公共库派生或直接新建私有动作

### 3.3 公共库管理

- 教练不能直接添加公共动作
- 可申请提交新动作，平台审核后入库

## 四、进步曲线

### 4.1 展示维度

**以教练为维度**，每个教练下有独立的曲线。

| 场景                    | 行为                                           |
| ----------------------- | ---------------------------------------------- |
| 学员跟教练A练深蹲       | 生成"教练A-深蹲"曲线                           |
| 学员换到教练B继续练深蹲 | 生成新的"教练B-深蹲"曲线                       |
| 两条曲线独立，不合并    | 除非两个动作关联了相同的 `canonical_action_id` |

### 4.2 UI 展示建议

学员个人主页的进步曲线需要**按教练分组显示**：

```
📈 我的进步曲线

┌─ 教练A（2025.06 - 2025.12）─────────────┐
│  深蹲：80kg → 120kg  [查看曲线]          │
│  卧推：60kg → 85kg   [查看曲线]          │
└──────────────────────────────────────────┘

┌─ 教练B（2026.01 - 至今）────────────────┐
│  深蹲：125kg → 130kg [查看曲线]          │
│  硬拉：140kg → 160kg [查看曲线]          │
└──────────────────────────────────────────┘

┌─ 自主训练 ───────────────────────────────┐
│  引体向上：+20kg → +35kg [查看曲线]       │
└──────────────────────────────────────────┘
```

### 4.3 学员自建计划的 PR

**计入 PR 表**，但标记来源为"自主训练"。

| 计划来源       | 是否计入 PR | 曲线归属         |
| -------------- | ----------- | ---------------- |
| 教练下发的计划 | ✅          | 归属到该教练     |
| 学员自建计划   | ✅          | 归属到"自主训练" |

## 五、学员使用教练动作

### 5.1 需求

学员订阅教练后：

- 可以看到教练的动作库
- 自建计划时可以选择教练的动作（用于加练）
- 执行时使用教练定义的动作标准

### 5.2 实现方式

学员创建计划时，动作选择范围：

1. **教练动作库**（只读引用，来自已订阅的教练）
2. **公共动作库**（可私有化到学员名下）
3. **学员自己的私有动作**

```sql
-- 学员可用的动作来源
SELECT * FROM coach_actions 
WHERE coach_id IN (
    SELECT coach_id FROM coach_subscriptions 
    WHERE student_id = $student_id AND status = 'active'
)
UNION
SELECT * FROM student_actions WHERE user_id = $student_id
UNION
SELECT * FROM canonical_actions;
```

### 5.3 PR 记录关联

学员使用教练动作自建计划并执行时：

- PR 记录关联到**教练的动作 ID**
- 曲线归入"自主训练"分组，但动作定义沿用教练的

## 六、实施步骤

1. **创建 `canonical_actions` 表**，导入 50-100 个常见动作
2. **给现有表加字段** `canonical_action_id`
3. **前端**：动作编辑页增加"关联公共动作"选项
4. **前端**：学员自建计划时可选择教练动作
5. **前端**：进步曲线按教练分组展示
6. **提示引导**：提示教练关联存量动作
7. **后期**：升级 AI 导入流程，自动匹配公共库
