# CoachLink 内容驱动的学习与社区闭环

日期：2026-08-14
状态：产品方案草案，待确认后进入 PRD 与开发拆分

## 一、产品定位

CoachLink 不应只是训练记录工具，也不应把知识库做成文章、书籍、视频和计划的简单货架。

建议将它定义为：

> 一个从“我现在卡在哪里”出发，通过系统学习、最小行动、真实记录和专业交流，帮助用户逐步建立训练能力的平台。

内容的作用不是单纯获得阅读量，而是把用户带入产品闭环：

```text
外部内容触达
  → 10题起点测试
  → 找到当前主要卡点
  → 推荐一条学习路径
  → 每课完成一个最小行动
  → 在 CoachLink 记录训练或饮食反馈
  → 围绕本课问题交流
  → 七天复测与调整
  → 必要时连接教练
```

内容负责解释“为什么”，测试负责判断“先解决什么”，产品负责落实“下一步做什么”，社区和教练负责处理个体差异。

## 二、为什么与 CoachLink 现状匹配

CoachLink 已经具备不少基础组件，不需要另起炉灶：

| 已有能力 | 可复用方式 |
|---|---|
| `coach_content_columns` 教练专栏 | 承载系列教程及课程序号 |
| `coach_contents` 图文、视频、付费分级 | 承载单节课程和公开内容 |
| `knowledge_nodes` 知识树 | 给课程标注主题、身体部位、器械和难度 |
| 训练计划库及复制链路 | 把教程中的方法直接变成可执行计划 |
| 今日训练与训练记录 | 承接课程作业和七天实践 |
| 新用户档案与 onboarding 问卷 | 复用目标、水平、器械、时间和关注部位 |
| 书籍讨论区 | 可作为课程讨论区的交互参考 |
| 人体地图 | 后续按肌肉、关节和问题节点组织专题内容 |
| AI 知识问答 | 在用户学习后处理追问，不代替测试和路线判断 |

当前真正缺少的不是内容入口，而是以下连接层：

1. 没有“测完之后为什么推荐这些内容”的结果页。
2. 专栏在小程序知识首页仍以散文章为主，缺少有顺序的学习路径。
3. 没有统一的课程完成进度、课后任务和七天复盘。
4. 文章有点赞，但没有成熟的逐课讨论；书籍讨论还不能覆盖全部知识内容。
5. 内容与计划、训练执行之间缺少明确的“马上应用”动作。

## 三、第一版不要做什么

1. 不先做无限信息流式社区。冷启动内容少时会显得空，内容多时又容易变成低质量闲聊。
2. 不先建设覆盖全身、全项目、全等级的大型课程体系。
3. 不让 AI 一次生成几十节泛泛课程后直接发布。
4. 不用一张总分把用户简单分成“优秀、一般、差”。测试应给出具体卡点和下一步。
5. 不把测试结果包装成医学诊断；疼痛、疾病和红旗风险必须提示就医或联系专业人员。

## 四、第一个内容产品

### 系列名称

主名称建议：**《从“坚持不下来”到真正开始：科学健身第一课》**

传播标题可以使用：

- 《我分析了36,162条健身评论，发现很多人缺的不只是自律》
- 《健身总是半途而废？先别做计划，先找出你的卡点》
- 《新手健身第一周，不需要一份完美计划》

### 目标用户

- 18 岁以上；
- 没有复杂疾病或急性伤病；
- 想开始力量训练，但不知道如何起步或总是中断；
- 需要一个低决策负担、可以七天验证的起点。

### 课程结构

| 节次 | 内容主题 | 用户要带走的结论 | CoachLink 内的动作 | 讨论问题 |
|---|---|---|---|---|
| 0 | 10题起点测试 | 先找卡点，不先责怪自律 | 保存测试结果 | 你最意外的结果是什么？ |
| 1 | 为什么坚持不是第一个问题 | 伤病、知识、饮食、时间等问题通常更具体 | 选择主要卡点 | 以前在哪一步中断？ |
| 2 | 目标与起点 | 目标必须转换成七天可观察行为 | 创建七天目标 | 你真正想改变的是什么？ |
| 3 | 找到最小训练剂量 | 先确定真实可用时间，再谈理想计划 | 选择每周次数和单次时长 | 哪个时间段最容易兑现？ |
| 4 | 新手动作与训练结构 | 先掌握推、拉、蹲、髋、核心等基础模式 | 复制入门训练模板 | 哪个动作最没把握？ |
| 5 | 疼痛、酸痛与风险边界 | 能区分正常训练反应和需要暂停升级处理的情况 | 人体地图进入对应部位 | 你最担心哪里受伤？ |
| 6 | 饮食先解决什么 | 不先追求完美计算，先找到最影响执行的一餐 | 记录三天晚餐 | 最容易失控的饮食场景是什么？ |
| 7 | 用记录代替感觉 | 用完成度、重量、次数和主观感受判断是否有效 | 完成一次训练记录 | 你以前如何判断“没效果”？ |
| 8 | 七天复盘与下一步 | 根据真实反馈升级任务，而不是盲目加码 | 复测并生成下一周建议 | 下周准备保留和改变什么？ |

每一节统一采用六段结构：

1. 一个真实问题或评论；
2. 一个核心判断；
3. 一张图表或示意图；
4. 一个常见误区；
5. 一个可以在产品内完成的动作；
6. 一个要求用户结合自身经历回答的讨论题。

## 五、10题起点测试

### 测试原则

- 3 分钟内完成；
- 不给复杂人格标签；
- 输出一个主要卡点、一个次要卡点和本周两件事；
- 可以读取已有 onboarding 数据，避免重复提问；
- 七天后允许复测并对比变化；
- 伤病题只用于风险分流，不用于医学诊断。

### 建议问题

1. 你目前最想解决的健身目标是什么？
2. 你过去连续训练最长维持了多久？
3. 一周真实能训练几次、每次多久？
4. 你能稳定使用哪些器械和场地？
5. 最近是否存在疼痛、旧伤或医生限制？
6. 以前最常因为什么中断？
7. 你现在最不确定的训练问题是什么？
8. 你最难控制的是哪一餐或哪一种饮食情境？
9. 最近一周的睡眠和疲劳处于什么水平？
10. 未来七天，你愿意完成哪一种最小行动？

### 结果不使用单一总分

建议输出六个方向的相对优先级：

- 风险与身体状态；
- 知识与计划清晰度；
- 时间与环境可行性；
- 饮食与恢复；
- 执行与反馈；
- 是否需要教练介入。

结果页示例：

> 你现在最需要解决的不是训练强度，而是“计划与真实时间不匹配”。本周先做两件事：① 周二、周六各完成一次20分钟全身训练；② 连续三天记录晚餐，不要求立刻改变。完成后再决定是否增加训练量。

## 六、知识首页的信息架构

知识首页不再只按内容类型平铺。建议按用户任务排序：

1. **我的下一步**：未测试则显示“3分钟找到健身起点”；已测试则显示本周两件事。
2. **继续学习**：显示正在进行的系列、当前第几课和七天完成度。
3. **按问题找答案**：不舒服、没效果、不知道怎么练、饮食困难、没时间。
4. **系统课程**：按顺序学习的教程系列。
5. **马上开练**：可直接复制并执行的训练计划。
6. **围绕身体找内容**：人体地图，进入具体肌肉、关节或问题节点。
7. **精选文章与书籍深读**：作为扩展阅读，不占第一屏核心位置。
8. **本周高质量讨论**：优先显示带真实训练背景、被教练回应或被编辑精选的讨论。

## 七、社区如何保持高质量

第一版社区应当“长在内容下面”，而不是先建立一个空泛广场。

### 每条讨论使用结构化模板

- 我的起点：训练经历、目标和可用条件；
- 我实际做了什么；
- 发生了什么结果或困难；
- 我希望大家帮我判断什么；
- 可选：关联训练记录、动作视频或测试结果。

### 内容身份标签

- `个人经历`：描述自己的实践，不外推到所有人；
- `教练建议`：通过平台教练身份发布；
- `证据解释`：需要标注来源和适用边界；
- `编辑精选`：有完整背景、过程和结果；
- `已采纳回答`：提问者或课程编辑确认最有帮助的回应。

### 排序信号

高质量讨论的排序不只看点赞，还应考虑：

- 是否完整填写背景；
- 是否关联真实训练或复测记录；
- 是否被课程作者或教练回复；
- 是否被提问者采纳；
- 是否被举报或出现危险健康建议；
- 回复能否帮助用户完成下一步。

### 安全边界

- 疼痛、伤病和疾病问题不做远程确诊；
- 出现红旗症状时终止普通训练建议，提示就医；
- 教练建议与普通用户经验必须在视觉上明确区分；
- AI 回答需要展示引用内容和风险声明，不能伪装成真人教练结论。

## 八、人体地图在第二阶段的角色

人体地图不是第一套课程的主导航，而是解决具体部位问题的长期知识底座。

节点应以用户实际点击意图为粒度，例如：肱二头肌、肱三头肌、肱桡肌、肘关节、网球肘、三角肌、肩袖、髌腱，而不是只停留在“手臂、肩部、腿部”。

每个节点固定包含：

1. 基础介绍；
2. 训练方法；
3. 体态管理；
4. 伤病管理；
5. 相关动作；
6. 关联课程与训练计划；
7. 该节点下的高质量讨论。

这样，同一篇“肩前侧不适”教程既可以属于新手课程，也可以挂到肩关节、肩袖和卧推动作相关节点，避免重复建设内容。

## 九、最小开发范围

### MVP 0：先把内容发起来

不改核心产品即可完成：

1. 使用现有教练专栏创建第一个系列；
2. 发布第1篇数据研究文章及配套图表；
3. 每篇文末使用统一的下一课、课后任务和讨论问题；
4. 在外部视频、博客和小程序使用同一系列名称与封面；
5. 先人工收集评论中的主要卡点，为测试规则校准样本。

### MVP 1：形成可用闭环

建议开发五项：

1. 10题起点测试、结果页和七天复测；
2. 有顺序、有进度的学习路径页面；
3. 通用课程讨论区，支持回复、教练身份和精选；
4. 课程内“加入计划 / 开始记录 / 打开人体地图”等行动按钮；
5. 知识首页顶部的“我的下一步”和“继续学习”。

### MVP 2：扩大社区与创作者

1. 教练可创建课程系列并挂载计划、动作和测试；
2. 用户可发布关联训练记录的学习复盘；
3. 编辑精选、采纳回答、危险建议举报和内容审核；
4. 根据学习和执行数据推荐内容，而不是只按热度推荐；
5. 将高质量讨论反向沉淀为 FAQ、课程补充和 AI 知识来源。

## 十、建议的数据模型边界

可以继续复用 `coach_contents` 和 `coach_content_columns` 保存文章与系列，但学习状态和讨论不要硬塞进文章字段。

MVP 1 建议增加以下独立实体：

- `fitness_assessment_attempts`：测试版本、答案、卡点结果、本周两件事、复测关系；
- `learning_paths`：学习路径定义；
- `learning_path_units`：路径中的内容、顺序、任务和讨论题；
- `user_learning_progress`：开始、完成、任务状态和完成时间；
- `knowledge_discussions`：可挂文章、课程、人体节点或计划的通用讨论；
- `knowledge_discussion_moderation`：精选、采纳、举报和审核状态。

不要用 `content_interactions` 的一条 `comment` 类型记录承载正文评论；该表更适合点赞、浏览等行为事件。书籍已有的 `knowledge_book_comments` 可以作为接口和 UI 参考，但长期应抽象成通用知识讨论能力。

## 十一、首期内容与产品共同指标

不要只看播放量和阅读量，重点观察：

1. 外部内容 → 测试开始率；
2. 测试完成率；
3. 结果页 → 第一课进入率；
4. 第一课 → 本周行动创建率；
5. 七天内至少完成一次行动的比例；
6. 七天复测率；
7. 每100名学习者产生的有背景、有过程、有问题的有效讨论数；
8. 教练回复率和被采纳回答率；
9. 需要专业介入的用户 → 教练咨询转化率。

北极星指标建议为：

> 每周完成至少一个“学习—行动—记录—复盘”闭环的用户数。

## 十二、推荐的立即行动

1. 确认第一个系列的名称和目标用户；
2. 将现有36,162条评论研究作为第1课，同时作为测试的传播入口；
3. 从现有 onboarding 中确认可复用字段，只新增“中断原因、饮食场景、睡眠疲劳、最小行动”四类问题；
4. 先画出测试结果页和学习路径页两个核心页面；
5. 用10—20名真实用户跑完“测试 → 第一课 → 两件事 → 七天复测”，再扩展课程数量与社区能力。
