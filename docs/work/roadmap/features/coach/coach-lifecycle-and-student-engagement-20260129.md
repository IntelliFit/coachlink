# [需求] 教练生命周期管理 & 学员活跃度生态系统

> **文档版本**：V3.1 (20260129 修正版)\
> **最后更新**：2026-01-29\
> **面向对象**：产品经理、后端工程师、前端工程师\
> **核心目标**：构建“优胜劣汰”的教练生态，同时通过“强互动”机制激励学员活跃，形成正向闭环。

## 1. 教练生命周期管理 (Coach Lifecycle Management)

### 1.1 业务逻辑：自动关闭 (Auto-Close Logic)

系统后台需运行定时任务（Cron Job，建议每日凌晨执行），扫描所有状态为 `ACTIVE`
的教练账号。当且仅当做以下 **两个条件同时满足** 时，执行关闭操作。

#### 判定条件 (Conditions)

1. **账户余额清零 (Balance Cleared)**
   - **字段检查**：`coach_wallet.balance == 0.00`
   - **业务含义**：确保没有待结算资金，避免财务纠纷。
2. **长期无有效业务 (Business Inactivity)**
   - **时间窗口**：过去 **14天** (2周)。
   - **判定规则**：
     - 查询该教练名下所有学员的关联状态。
     - 若 `COUNT(active_students) == 0`。
     - _注：active_students 定义为当前服务期内切未过期的学员。_

### 1.2 状态流转 (State Transition)

- **当前状态**：`ACTIVE` (正常营业)
- **触发事件**：满足上述 Auto-Close 条件。
- **目标状态**：`REVOKED` (资格回收)
  - **系统动作**：
    1. 更新 `users.role` 或 `coach_profile.status`。
    2. 发送通知（短信/微信模板消息）：_“因长期未开展业务且余额为零，您的教练权限已被回收。如需恢复，请重新提交入驻申请。”_
  - **前端表现**：
    1. 教练登录后，重定向至“重新入驻”页面。
    2. 无法访问“教练工作台” (Dashboard)。

## 2. 学员活跃度生态 (Student Engagement Ecosystem)

### 2.1 签到机制设计 (Check-in System)

**核心原则**：签到是**结果**，而非**动作**。用户不能点击一个“签到”按钮，签到必须由**实质性的训练行为**触发。

#### 触发规则 (Triggers)

只有完成以下任一行为，系统自动记录一次有效“签到”：

1. **完成训练计划**：
   - 学员在 App 中点击“完成训练” (Finish Workout)。
   - 后台接收到 `workout_session.status = COMPLETED` 事件。
2. **提交训练日志**：
   - 学员手动上传图片/视频/文字日志。
   - 后台接收到 `training_log.create` 事件。

#### 数据结构 (Schema Suggestion)

建议新增 `user_checkins` 表，用于快速查询和统计：

```sql
TABLE user_checkins {
  id: uuid,
  user_id: uuid,
  checkin_date: date,  -- 仅记录日期，每日重/复行为合并或去重
  source_type: enum('PLAN_COMPLETION', 'LOG_UPLOAD'),
  source_id: uuid,     -- 关联的 workout_id 或 log_id
  created_at: timestamp
}
```

### 2.2 激励与可视化 (Incentives & Gamification)

#### 2.2.1 视觉激励 (Visuals)

1. **活跃热力图 (Activity Heatmap)**：
   - **位置**：学员 Profile 页 / 首页顶部。
   - **样式**：仿 GitHub Contribution 图，用深浅绿色方块表示过去一年的训练频率。
   - **心理学**：利用“填满格子”的强迫症心理激励持续训练。
2. **连胜统计 (Current Streak)**：
   - **显示**：首页显著位置展示 _“已连续训练 X 天”_ 或 _“本周已练 Y 天”_。
   - **规则**：连续 2 天无记录则 Streak
     清零（由于健身需休息，建议算法宽容度为“每周至少 3 次”视为 Streak
     延续，具体算法待定）。

#### 2.2.2 荣誉体系 (Badges)

- **里程碑勋章**：累计训练 10天 / 30天 / 100天。
- **早鸟勋章**：连续 5 次早晨 6:00-9:00 完成训练。

### 2.3 教练-学员互动闭环 (Coach Interaction Loop)

这是促活的最关键环节：**让机器的冷冰冰记录转化为人的温情鼓励。**

#### 交互流程

1. **学员动作**：User A 完成了 "Leg Day" 训练计划。
2. **系统通知**：
   - **推送对象**：Coach B (User A 的当前教练)。
   - **推送内容**：_“您的学员 User A
     刚刚完成了【腿部力量训练】，状态不错！快去鼓励一下吧。”_
   - **通道**：微信服务号模板消息 / App 内红点通知。
3. **教练动作 (Actionable Notification)**：
   - 在通知详情页，提供 **一键互动按钮**：
     - `[👍 点赞]` (Like)
     - `[🔥 太强了]` (Fire)
     - `[💬 快速回复]` (Quick Reply)
4. **反馈闭环**：
   - 学员收到教练的赞/评论。
   - APP 弹出 Toast：_“教练给你的训练点了个赞！”_
