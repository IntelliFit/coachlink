# ICP+EDI 证书申请网站改造计划（基于现有 CoachLink 形态，最小改动过审版）

> **核心原则**：不“硬做一个假商城”，而是把你们真实在卖的东西（教练订阅/计划）以审核能理解的方式呈现为「商品/服务」，并补齐 ICP+EDI 常见必备页面与信息披露。

## 一、你们现在的情况（快速对齐）

- **首页**：已有大量“功能点/服务价值”介绍，本质上已经是“服务分类介绍”的雏形，但缺少“明确的商品入口/购买入口”。
- **登录/注册**：已有，且注册页已有用户协议弹窗（满足“注册需要用户协议”）。
- **入驻流程**：已有教练申请页（`/coach/application`），可视为“商家入驻流程”的产品化形态。
- **联系我们**：已有（`/contact`，读取 `public/docs/contact.md`）。
- **可售卖内容（商品来源）**：教练主页的订阅产品区块已存在（`src/app/coach/profile/[id]/CoachSubscription.tsx`），非常适合直接作为“商品”使用。

## 二、审核要求拆解 → 对应最小实现

> 目标是让审核人员能在 3 分钟内看到：**首页→分类→商品列表/详情→登录拦截→购买/下单入口**，并且有：**关于我们/联系我们/入驻流程/资讯**。

### 2.1 必备栏目与最小形态

| 审核项 | 他们想看到什么 | 我们的最小实现（基于现状） |
|---|---|---|
| 首页 | 有“商品/服务分类介绍”且能进入商品列表 | 首页保留现有功能点，同时增加“服务分类入口卡片”（跳转到 `/market` 或发现页商品Tab） |
| 登录/注册 | 注册有用户协议 | 维持现状；补充注册页用户协议“可打开完整页面”入口（可选但加分） |
| 商品分类（含具体产品≥6） | 有分类 + 至少6个商品 + 加购/购买需登录 | 用“教练订阅计划/服务包”作为商品，做一个**独立商品聚合页** `/market`（≥6条），并在发现页增加“商品”入口 |
| 关于我们 | 主体信息披露 + 经营范围/售卖内容说明 | 新建 `/about`，写“平台/主体介绍、主要售卖服务、合规信息（公司/联系方式引用）”，避免与首页重复 |
| 联系我们 | 公司地址/邮箱/电话等 | 维持现状（补齐 `contact.md` 里的主体信息即可） |
| 入驻流程 | 商家入驻过程说明 | 复用 `/coach/application`，并补一个“入驻流程说明页” `/merchant-onboarding`（可选，若担心教练申请页不够“流程化”） |
| 资讯 | 至少3篇科技类文章 + 详情 + “付费二维码”交互示例 | 新建 `/articles`（列表）+ `/articles/[slug]`（详情），文章主题为“训练科技/产品技术/数据分析”，详情页点击“查看更多”弹出二维码 |

### 2.2 内容红线（必须贯彻到所有页面）

**不得出现**：教育、新闻、金融、招聘、风控投资理财等内容。

建议将“资讯”栏目命名为：**技术文章 / 产品技术 / 训练科技**（避免“新闻/资讯”被误会成时事资讯）。

> 让审核路径更顺：从首页/发现页都能进“商品”，并且页面名直观。

- **新增**：`/about`（关于我们/主体披露）
- **新增**：`/articles`（文章列表）
- **新增**：`/articles/[slug]`（文章详情+二维码弹窗）
- **可选新增**：`/merchant-onboarding`（把入驻流程写成“步骤页”，并链接到 `/coach/application`）

### 3.2 导航入口（建议最小改动）

- 首页增加：一个“服务商品”入口按钮/卡片（不必展示具体商品列表）
- 发现页增加：Tab/切换（`教练` / `服务商品`），并引导去 `/market`

## 四、核心改造点（按模块落地）

### 4.1 首页：从“功能亮点”升级为“服务分类+入口”

你们首页现在可以被解释为“服务能力介绍”，但为了稳过审，建议补齐两点：

- **明确的分类命名**：用“服务商品分类”而不是“功能亮点”。
- **明确的购买入口**：给出“去选购服务”的按钮/卡片，指向 `/market`。

> 首页不必摆出 6 个商品；但一定要“看得见能去买”。

### 4.2 商品：用“教练订阅/计划”做真实商品（≥6条）

#### 商品定义（与现有业务一致）
- **商品=教练提供的订阅/训练计划服务包**（可含：周期、价格、权益说明）
- 来源建议：
  - **优先**：复用教练主页订阅组件（`CoachSubscription.tsx`）里已经存在的“产品卡片”结构
  - **聚合**：在 `/market` 聚合所有教练的产品（按分类/档位/教练维度展示）

#### 商品分类建议（避免“金融/教育”等敏感词）
- 按“训练目标/人群/档位”做分类，例如：
  - 增肌训练计划
  - 减脂训练计划
  - 力量提升计划
  - 动作纠正/视频点评服务（如果你们确实提供）

#### “加入购物车/购买需登录”如何最小实现
审核要求通常关注的是“**下单/购买动作受登录保护**”，不强制你们必须有完整购物车。

- 最小实现（推荐）：按钮文案用 **“立即购买 / 选择订阅”**（比“加入购物车”更贴合你们现状）
- 行为：未登录 → 跳转 `/login?redirect=...`；已登录 → 进入现有订阅/支付流程（或先弹出“联系教练确认/支付”）

### 4.3 发现页：不破坏“发现教练”，但提供“商品入口”

发现页当前只有教练列表。建议两种方式（二选一，推荐 A）：

- **A（推荐）**：发现页顶部加 Tab：`教练` / `服务商品`  
  - `服务商品` Tab 内展示商品卡片（来自 `/market` 的聚合数据或同源组件）
  - 这样审核人员很容易理解“平台有商品”
- **B（更轻）**：发现页顶部加一个“去选购服务商品”的入口卡片，跳转 `/market`

### 4.4 关于我们：做“主体信息披露页”，避免和首页重复

“关于我们”在审核语境里更像：**我们是谁、卖什么、怎么联系、提供什么服务范围**。

建议结构：
- 平台/主体简介（1段）
- 主要售卖/提供的服务（列表，引用你们真实业务：教练订阅/训练计划/相关服务）
- 服务流程概述（可引用“发现教练→订阅→训练执行→视频沟通”）
- 合规信息（运营主体信息、投诉/客服邮箱、工作时间等）

实现方式建议：参考 `/contact` 的做法，用 `public/docs/about.md` 渲染成页面，后续易改。

### 4.5 资讯/文章：独立栏目最稳（避免“新闻”误会）

建议栏目命名：**技术文章**（路由 `/articles`）。

#### 最小内容要求
- 至少 3 篇文章（主题偏“科技/技术/产品”，不写时事新闻）

示例选题（安全且贴合产品）：
- 《AI 在训练计划结构化中的应用：从自然语言到可执行计划》
- 《数据驱动训练：如何用训练记录与PR趋势做阶段复盘》
- 《视频+结构化记录：让远程指导更高效的技术实践》

#### “点击后显示二维码服务”的最小实现
- 文章详情页展示正文
- 正文底部（或中段）放一个 CTA：**“查看更多/获取完整内容（¥X）”** → 弹出二维码对话框
- 二维码可以先用固定图片（`public/images/...`），满足审核示例即可

> 注意：这里的“付费二维码”只需符合他们示例交互，不必与真实支付链路完全打通（但文案要合规、避免金融化表述）。

### 4.6 入驻流程：复用教练申请 + 可选补“流程说明页”

你们已有 `/coach/application`，但页面更像“申请表”。为更贴近“入驻流程”，建议：
- **可选新增** `/merchant-onboarding`：写清楚“入驻步骤（提交资料→审核→上架服务→开始接单）”，并提供“立即入驻”按钮跳转 `/coach/application`。

## 七、验收标准（按审核视角）

### 7.3 内容合规
- 全站不出现：教育/新闻/金融/招聘/风控投资理财
- 文章主题为“科技/技术/产品/训练科技”，不做时事新闻
