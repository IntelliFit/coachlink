# 测试快速指南

## 🎯 测试代码位置

### E2E测试（端到端测试）
- **文件**: `e2e/b1-subscription.spec.ts`
- **框架**: Playwright
- **测试内容**: 订阅状态和训练执行流程

### 单元测试
- **文件**: `tests/backend/api/feedback/submit.test.ts`
- **框架**: Vitest
- **测试内容**: API接口单元测试

---

## 🚀 如何运行测试

### 1. 运行单元测试
```bash
npm test
```

### 2. 运行E2E测试
```bash
npm run test:e2e
```

### 3. 上线前完整检查（推荐）
```bash
npm run pre-deploy-check
```

这个命令会依次运行：
1. ✅ 环境变量检查
2. ✅ 单元测试
3. ✅ E2E测试
4. ✅ 构建检查

---

## 📋 上线前检查清单

在每次上线前，请确保：

- [ ] 运行 `npm run pre-deploy-check` 所有检查通过
- [ ] 手动测试核心功能：
  - [ ] 用户登录
  - [ ] 订阅创建和支付
  - [ ] 训练计划执行
- [ ] 检查CI/CD测试通过（GitHub Actions）

## 🔧 测试配置

### 环境变量
E2E测试需要以下环境变量：
- `E2E_SECRET` - E2E测试密钥（可选，本地开发可不设置）

### CI/CD
GitHub Actions会自动运行：
- ✅ 单元测试
- ✅ E2E测试（已添加）

---

## 📝 扩展测试

### 添加新的E2E测试
1. 在 `e2e/` 目录创建新的测试文件，例如 `e2e/auth.spec.ts`
2. 使用现有的 `seed` 和 `cleanup` API准备测试数据
3. 参考 `e2e/b1-subscription.spec.ts` 的写法

### 添加新的单元测试
1. 在 `tests/` 目录创建测试文件
2. 使用 Vitest 框架编写测试
3. 参考 `tests/backend/api/feedback/submit.test.ts` 的写法

---

## ⚠️ 注意事项

1. **测试数据**: E2E测试会自动创建和清理测试数据，不会影响生产数据
2. **测试环境**: 确保使用测试数据库或开发数据库
3. **测试稳定性**: E2E测试可能因网络等因素不稳定，失败时请检查是否是环境问题

## 🆘 常见问题

### E2E测试失败怎么办？
1. 检查开发服务器是否正常运行
2. 检查环境变量是否正确配置
3. 查看测试报告：`npx playwright show-report`

### 如何调试E2E测试？
```bash
# 以UI模式运行，可以逐步调试
npx playwright test --ui
```

### 如何只运行特定测试？
```bash
# 运行特定文件
npx playwright test e2e/b1-subscription.spec.ts

# 运行特定测试用例
npx playwright test -g "B1 status labels"
```

## 🤔 常见疑问

### E2E测试是否"强行依赖业务逻辑"？
是的，但这是它的价值所在。E2E测试验证的是"用户可见的行为"，所以必须知道"什么情况下应该显示什么"。这是好事：能抓到"新功能把老功能改坏"（回归保护）。

### 单元测试主要测API，但API本身一般都不会有什么问题？
单元测试的价值不只是"API不出错"，而是验证**复杂的业务规则**（如credits计算、权限判断、状态转换等）。这些是纯逻辑，如果改错了会导致业务问题。

**详细说明**：请查看 [测试价值与分工说明.md](./测试价值与分工说明.md)
