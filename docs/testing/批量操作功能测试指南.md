# 批量操作功能测试指南

## 测试环境准备

1. 确保已安装依赖:
```bash
npm install
```

2. 确认环境变量已配置:
```env
DEEPSEEK_API_KEY=your-key-here
```

3. 启动开发服务器:
```bash
npm run dev
```

## 测试步骤

### 1. 创建测试用的训练计划模板

1. 登录为教练账号
2. 进入"计划库"页面 (`/dashboard/plan-lib`)
3. 点击"新建"按钮
4. 创建一个包含多个训练日的模板,例如:
   - 第1天: 深蹲、引体向上
   - 第2天: 卧推、硬拉
   - 第3天: 休息
   - 第4天: 深蹲、引体向上

### 2. 测试批量操作

#### 测试用例 1: 替换动作

1. 在训练计划卡片上找到"闪电"图标(批量操作按钮)
2. 点击按钮打开对话框
3. 输入指令: `把所有引体向上替换为跑步`
4. 点击"执行"
5. 观察日志输出:
   - ✅ 看到"正在加载训练计划模板..."
   - ✅ 看到"正在加载动作库..."
   - ✅ 看到"正在分析您的指令..."
   - ✅ 看到生成的 TypeScript 代码
   - ✅ 看到"代码执行成功"
   - ✅ 看到"操作完成!"

#### 测试用例 2: 修改参数

输入指令: `把所有深蹲的组数改为5组,重量改为80kg`

预期结果:
- 所有包含"深蹲"的动作的 sets 参数变为 5
- 所有包含"深蹲"的动作的 weight 参数变为 80

#### 测试用例 3: 删除动作

输入指令: `删除所有的卧推动作`

预期结果:
- 所有包含"卧推"的 actionSet 被移除

#### 测试用例 4: 删除休息日

输入指令: `删除所有休息日`

预期结果:
- 所有 type 为 'rest' 的训练日被移除

#### 测试用例 5: 批量添加备注

输入指令: `给所有训练日添加备注"保持良好姿势"`

预期结果:
- 所有训练日的 note 字段被设置为指定内容

### 3. 验证结果

1. 操作完成后,点击"编辑"按钮查看训练计划
2. 检查修改是否正确应用
3. 确认数据库中的 trainingDays 已更新

## 常见问题排查

### 问题 1: 对话框不显示

**检查**:
- 是否正确导入了 BatchOperationDialog 组件
- selectedTemplateId 是否正确设置

### 问题 2: SSE 连接失败

**检查**:
- 网络连接
- 后端服务是否运行
- 环境变量是否配置

### 问题 3: 代码执行失败

**检查**:
- isolated-vm 是否正确安装
- 生成的代码语法是否正确
- 是否超过内存或时间限制

### 问题 4: AI 生成的代码不符合预期

**可能原因**:
- 指令不够明确
- 动作库中没有匹配的动作
- trainingDays 结构不符合预期

**解决方法**:
- 改写指令,使其更具体
- 在动作库中添加需要的动作
- 检查 prompt 是否包含正确的数据结构示例
