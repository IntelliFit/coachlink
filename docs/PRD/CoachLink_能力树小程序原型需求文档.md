# CoachLink 能力树小程序原型需求文档

版本：v0.3  
日期：2026-05-09  
交付物：一个“像真实小程序一样能点”的移动端产品雏形需求规格，而不是产品思路展示页

---

## 0. 自我评估与本次修订结论

v0.2 的方向是对的，但还不够好。它已经解决了“不要再做解释型网页”的问题，也把现有功能映射到了新体系里；但它还偏产品概述，不够像能直接指导前端原型开发的需求文档。

主要不足：

- 页面状态不够明确：例如今日页、训练执行页、能力树页分别有哪些空状态、进行中状态、完成状态。
- 点击路径不够硬：知道要有这些页面，但还没规定“点哪个按钮到哪个页面，回来后状态怎么变”。
- 能力树规则不够清楚：节点怎么解锁、怎么点亮、怎么升级/退阶、疼痛风险怎么影响路径。
- 原型验收不够可操作：只有原则，没有一条完整的可录屏演示脚本。
- 现有功能映射还偏模块级，没有进一步落到具体页面组件和入口层级。

v0.3 的修改目标：

1. 把原型从“产品方向文档”推进为“交互原型规格”。
2. 明确 P0 只做一条主线，不把所有功能都塞进第一版原型。
3. 给出能力树节点状态机、页面状态、点击路径、mock 场景和验收脚本。
4. 让下一步做出来的东西更像一个真实小程序，而不是一个讲方案的网页。

## 1. 本次先纠正原型定义

用户说的“原型设计”不是一张解释图，也不是右侧放说明文字的方案页面，而是一个小程序雏形：

- 只有手机界面，不出现桌面右侧解释面板。
- 页面里不写“这是我们的产品设计思路”这类说明。
- 用户打开后能完成一条真实路径：测起点、看今天练什么、进入训练、看节点知识、完成后复盘、卡住时找教练。
- 原型先用前端 mock 数据，不接后端、不改数据库、不影响当前 CoachLink 主项目运行。
- 原型必须建立在现有 CoachLink 功能上，只是重组入口和表达方式，不是另起炉灶。

一句话：这不是“讲给别人听的方案页”，而是“用户真的会打开的小程序体验草图”。

## 2. 重构目标

### 2.1 当前产品问题

CoachLink 现在不是功能不够，而是功能太散：

- 今日训练、训练执行、动作库、知识库、工具箱、街健、排行榜、好友、会员、教练发现都在争夺用户注意力。
- 小白不知道自己来平台第一件事应该做什么。
- 高质量内容还停留在“内容库/知识点/动作解释”，没有被转成“当前阶段该怎么练”的行动指导。
- 教练发现像一个独立入口，和用户卡关、动作不标准、计划迷茫之间的触发关系不够强。
- 高阶能力如街健、排行榜、专项工具很有价值，但过早出现会让小白觉得平台太专业、太复杂。

### 2.2 新产品主线

把 CoachLink 从“功能集合”重构成：

**起点诊断 -> 能力树路径 -> 今日训练 -> 训练执行 -> 节点知识 -> 复盘升级 -> 教练/伙伴支持**

用户第一眼要明白：

- 我现在在哪个阶段。
- 今天只需要做什么。
- 为什么平台让我做这个。
- 怎么判断我能升级。
- 卡住、疼痛、没效果时应该找谁。

### 2.3 原型验证目标

本原型只验证五件事：

1. 小白打开后是否知道“今天该做什么”。
2. 用户是否能看懂自己属于哪个能力树、哪个等级、哪个节点。
3. 知识是否被转成当前节点的行动提示，而不是资料堆。
4. 教练是否在“卡关/疼痛/动作不确定”时自然出现，而不是首屏硬卖。
5. 这个产品形态是否适合录屏传播，10 秒内能讲清楚卖点。

## 3. 已有功能提炼

下面是现有 CoachLink 功能在新体系里的位置。第一轮不删除这些功能，只调整入口层级。

### 3.1 学生侧功能资产

| 现有功能 | 现有位置 | 新体系角色 | 原型中怎么表现 |
|---|---|---|---|
| 今日训练 | `wechat_app/src/training/today-training`、`src/app/today-training` | 绝对核心首页 | “今日”Tab，首屏只突出一个主任务 |
| 训练执行 | `wechat_app/src/training/training-execution`、`src/app/training-execution/[instanceId]` | 节点挑战页 | 点击“开始训练”进入组次记录、RPE、疼痛反馈 |
| 训练记录/计划历史 | `wechat_app/src/me/profile/detail`、计划历史接口 | 升级依据 | 完成后显示是否升级、维持、退阶 |
| 学生计划库 | `wechat_app/src/me/plan-lib`、`src/app/me/plan-lib` | 高阶自定义能力 | 不放首屏，放到“我的/更多计划” |
| 即兴训练 | `wechat_app/src/training/today-training/components/LightweightTaskSheet.tsx` 等 | 无计划时的补充训练 | “今日”页次级入口，不抢主任务 |
| 动作库 | `wechat_app/src/me/action-lib`、`wechat_app/src/training/actions`、`src/app/me/action-lib` | 能力节点标准库 | 节点详情里的动作标准、退阶、进阶、常见错误 |
| 知识库 | `wechat_app/src/content/knowledge`、`src/app/dashboard/knowledge`、`src/app/api/knowledge/*` | 节点说明书 | 每个节点只露出当前需要看的知识卡 |
| 工具箱 | `wechat_app/src/me/toolbox`、`src/app/toolbox` | 高阶辅助工具 | 放在“我的/工具”或能力树高级节点后 |
| 街健指数/地点/故事 | `wechat_app/src/streetlifting`、`src/app/streetlifting-index` | 高阶专项分支和传播内容 | 能力树高级分支，不给小白首屏 |
| 排行榜 | `wechat_app/src/discovery/ranking`、`src/app/ranking` | 挑战和社群激励 | 达到一定等级后出现 |
| 教练发现/教练主页 | `wechat_app/src/discovery/coach-profile`、`src/app/coach/discovery` | 卡关解决方案 | 从卡关、疼痛、视频点评入口进入 |
| 我的教练/私信 | `wechat_app/src/me/my-coaches`、`wechat_app/src/me/messages` | 支持层 | 教练 Tab 和训练反馈后承接 |
| 好友/动态 | `wechat_app/src/me/friends` | 陪伴和激励 | 后置为“同路径伙伴”，不做泛社交 |
| 会员/支付/订单 | `src/app/me/membership`、`src/app/payment/*` | 商业层 | 原型只保留入口，不作为主线展示 |

### 3.2 教练侧功能资产

| 现有功能 | 现有位置 | 新体系角色 |
|---|---|---|
| 教练工作台 | `wechat_app/src/coach/overview`、`src/app/coach/*` | 教练供给侧后台，不进学生首屏 |
| 我的学生 | `wechat_app/src/coach/students` | 用户卡关后进入教练服务的承接能力 |
| 教练计划库 | `wechat_app/src/coach/plan-lib`、`src/app/dashboard/plan-lib` | 能力节点训练方案的供给来源 |
| 教练动作库 | `wechat_app/src/coach/action-lib`、`src/app/dashboard/action-lib` | 动作标准、纠错、示范视频供给来源 |
| 教练内容 | `wechat_app/src/coach/content`、`src/app/coach/content/*` | 高质量内容供给来源 |
| 视频点评 | `wechat_app/src/coach/videos/review`、`src/app/api/coach/video/*` | 训练执行后升级服务 |
| 教练定价/订阅 | `wechat_app/src/coach/pricing`、支付链路 | 卡关服务商品化 |
| 教练申请/分层 | `wechat_app/src/coach/application`、`src/app/coach/application` | 训练搭子/进阶教练/专业教练供给分层 |

### 3.3 可复用底层能力

- 训练执行闭环：开始训练、完成组、跳过、完成动作、完成整次训练。
- 本地缓存：今日训练首页缓存、训练执行快照缓存。
- 计划体系：教练计划、学生自建计划、历史计划。
- 视频能力：训练视频上传、教练点评、动作示范视频。
- AI 能力：计划生成、模板解析、内容解释，可转成诊断、节点解释、周复盘。
- 支付订阅：后置到教练服务和会员服务，不放在原型主线第一屏。

## 4. 新信息架构

### 4.1 底部导航

原型只保留 4 个 Tab：

| Tab | 用户理解 | 承接旧功能 |
|---|---|---|
| 今日 | 今天我该练什么 | 今日训练、训练执行、轻量打卡、复盘 |
| 能力 | 我在能力树哪里，下一步去哪 | 动作库、知识库、训练记录、高阶分支 |
| 教练 | 我卡住了，谁能帮我 | 教练发现、教练主页、视频点评、私信 |
| 我的 | 我的记录和工具 | 训练历史、计划库、工具箱、好友、会员 |

不再单独做“知识”Tab。知识必须嵌入“今日”和“能力”的节点里。

### 4.2 首页优先级

“今日”页首屏顺序：

1. 当前路径：例如“零基础起步 L1 / 推力树 / 墙面推”。
2. 今日主任务：只给一个最重要动作或训练模块。
3. 为什么练：一句节点解释。
4. 开始训练按钮。
5. 安全提示：疼痛、疲劳、退阶动作、找教练入口。
6. 本周进度：用来强化正反馈，不抢主任务。

首屏不出现：排行榜、复杂计算器、会员权益、购物车、教练商品列表、大量知识文章列表。

## 5. 能力树模型

### 5.1 主干设计

能力树第一层不按“胸背腿肩”这种健身房分化，而按大众能理解的运动能力分：

| 能力树 | 解决问题 | 典型节点 |
|---|---|---|
| 推力树 | 俯卧撑、支撑、肩肘控制 | 墙面推、上斜俯卧撑、标准俯卧撑、臂屈伸 |
| 拉力树 | 悬垂、划船、引体、背部发力 | 主动悬垂、肩胛引体、澳式划船、引体向上 |
| 下肢树 | 深蹲、单腿稳定、跑跳基础 | 坐站、徒手深蹲、分腿蹲、单腿蹲 |
| 髋与后链树 | 臀腿后侧、腰背保护、硬拉基础 | 臀桥、髋铰链、罗马尼亚硬拉 |
| 核心树 | 抗伸展、抗旋转、身体控制 | 死虫、鸟狗、平板、折刀、悬垂举腿 |
| 心肺与移动树 | 减脂、体能、耐力、移动能力 | 快走、台阶、跳绳、慢跑、间歇 |
| 恢复与活动度树 | 体态、疼痛筛查、恢复、热身 | 肩颈准备、髋踝活动、疼痛自检、睡眠复盘 |

恢复与活动度树必须表达为“筛查、预防、动作准备、转介提示”，不能表达成医疗诊断。

### 5.2 用户阶段

| 阶段 | 典型痛点 | 原型路径 |
|---|---|---|
| 青少年/儿童 | 安全、习惯、家长信任 | 低风险动作、趣味反馈、家长能看懂 |
| 零基础成人 | 不知道怎么练、怕练错 | 唯一路径、最小训练任务 |
| 体态/恢复用户 | 肩颈腰膝不适、怕受伤 | 筛查、退阶、替换动作、安全边界 |
| 进阶卡关用户 | 没效果、平台期 | 数据复盘、瓶颈诊断、计划调整 |
| 专项高阶用户 | 标准、周期、视频反馈 | 专项分支、排行榜、教练点评 |

### 5.3 节点状态规则

原型里每个能力节点必须有清晰状态，不能只是漂亮的点位。

| 状态 | 含义 | UI 表现 | 用户能做什么 |
|---|---|---|---|
| locked | 未解锁 | 灰色节点、显示前置条件 | 只能预览，不能加入今日训练 |
| available | 可选择 | 普通亮色节点 | 查看详情、加入今日训练 |
| current | 当前节点 | 高亮、带“今日”标记 | 进入今日训练、看标准、执行 |
| completed | 已完成 | 点亮、显示完成日期或次数 | 查看历史、继续巩固 |
| risk | 风险节点 | 带安全提示 | 优先看退阶/恢复，提示找教练 |

### 5.4 升级、维持、退阶规则

第一版原型不需要做真实算法，但要表现出规则感：

- 升级：连续 2 次完成今日任务，RPE 不高于 8，疼痛不高于 3。
- 维持：完成训练但动作不稳、RPE 偏高、或只完成部分组数。
- 退阶：疼痛高于 4、连续 2 次失败、或用户主动选择“今天不舒服”。
- 找教练：退阶后仍失败、疼痛风险高、上传视频求点评、或连续两周没有进步。

这些规则在原型里用 mock 状态触发，不接真实后端。

## 6. P0 原型页面需求

### 6.1 起点诊断页

目标：让用户从“不知道怎么练”进入“平台知道我从哪开始”。

页面内容：

- 标题：先测你从哪一层开始。
- 6 组选择卡：
  - 目标：减脂、增肌、力量、体态健康、专项。
  - 水平：零基础、练过一点、卡关、高阶。
  - 时间：10-20 分钟、30-45 分钟、60 分钟以上。
  - 器械：无器械、弹力带/哑铃、健身房、单杠。
  - 不适：无、肩颈、腰背、膝、腕肘。
  - 饮食困扰：不知道吃什么、外食多、蛋白不足、暂不关注。
- 结果卡：
  - 当前路径。
  - 本周目标。
  - 今日第一任务。
  - 推荐能力树。

交互：

- 选择卡片后即时高亮。
- 点击“生成我的路径”进入“今日”页。
- 允许跳过，跳过后进入默认“零基础起步路径”。

AI 占位：

- 显示“AI 已根据目标、时间、器械、不适生成起步路径”，但不接真实接口。

### 6.2 今日页

目标：让用户知道今天只做什么。

页面内容：

- 当前路径卡：阶段、能力树、节点、本周完成度。
- 今日主任务卡：
  - 节点动作。
  - 组次/时长。
  - 通过标准。
  - “开始训练”主按钮。
- 今日辅助任务：
  - 看 1 条节点标准。
  - 记录疼痛/RPE。
  - 饮食原则 1 条。
- 轻量复盘：
  - 上次完成情况。
  - 系统建议：升级、维持、退阶。

交互：

- 点击“开始训练”进入训练执行页。
- 点击“为什么练这个”进入节点详情页。
- 点击“我今天不舒服”弹出退阶/找教练提示。

对应旧功能：

- 今日训练 -> 今日主任务。
- 训练执行 -> 开始训练。
- 知识库 -> 节点解释。
- 训练记录 -> 本周完成度和复盘。

### 6.3 能力树页

目标：让用户看见长期路径，但不迷路。

页面内容：

- 7 个能力树切换。
- 当前能力树节点地图。
- 节点状态：
  - 已完成。
  - 当前。
  - 未解锁。
  - 风险提示。
- 当前节点详情入口。

交互：

- 点击能力树切换节点地图。
- 点击节点打开节点详情页。
- 当前节点可以加入今日训练。
- 未解锁节点可以预览，但不能直接训练。

### 6.4 节点详情页

目标：把高质量内容变成可执行规则。

页面内容：

- 节点名、等级、所属能力树。
- 为什么练这个。
- 通过标准。
- 今日训练建议。
- 常见错误。
- 退阶动作。
- 进阶动作。
- 疼痛/禁忌边界。
- 对应教练/视频点评入口。

对应旧功能：

- 动作库 -> 动作标准、示范视频、常见错误。
- 知识库 -> 原理解释、安全边界。
- 教练发现 -> 看不懂、卡住、疼痛时进入。

### 6.5 训练执行页

目标：把训练过程变成反馈数据。

页面内容：

- 动作示范视频占位。
- 当前动作标准。
- 组次列表。
- 完成按钮。
- 组间休息。
- 疼痛记录。
- RPE 记录。
- 上传视频/请求点评入口。
- 完成后复盘卡。

交互：

- 每完成一组，进度条推进。
- 完成全部后显示：
  - 今日完成。
  - 是否达到升级条件。
  - 下次建议。
- 如果疼痛高或连续失败，推荐退阶或找教练。

### 6.6 教练升级页

目标：教练不是首屏广告，而是卡关解决方案。

触发场景：

- 动作连续两次不达标。
- 疼痛/RPE 风险高。
- 连续两周没有进步。
- 用户主动点击“找人帮我看”。

页面内容：

- 用户当前问题。
- 推荐教练类型：
  - 训练搭子：陪练、监督、低成本反馈。
  - 进阶教练：动作纠错、计划调整。
  - 专业教练：伤病友好、专项周期。
- 推荐教练卡片。
- 视频点评、私信、订阅入口。

### 6.7 我的页

目标：承接记录和次级功能，不承担主线。

页面内容：

- 我的阶段、训练天数、完成节点数。
- 训练记录。
- 我的计划。
- 我的动作库。
- 工具箱。
- 我的教练/私信。
- 好友。
- 会员。

### 6.8 P0 页面状态总表

| 页面 | 必须覆盖的状态 | 说明 |
|---|---|---|
| 起点诊断 | 未选择、已选择、生成中、生成结果 | 生成中可以用短动画或进度文案，但不要变成 AI 炫技页 |
| 今日 | 新用户默认任务、进行中任务、已完成任务、身体不适提示 | 首页永远围绕“今天做什么” |
| 能力树 | 默认推荐树、切换树、点击节点、未解锁预览 | 能力树是路径地图，不是复杂知识导航 |
| 节点详情 | 当前节点、未解锁节点、风险节点 | 当前节点可加入今日，未解锁只能预览 |
| 训练执行 | 未开始、组间进行、全部完成、风险反馈 | 完成一组必须有即时反馈 |
| 教练升级 | 动作卡关、疼痛风险、平台期、主动求助 | 根据原因推荐不同教练类型 |
| 我的 | 普通记录页、更多功能入口 | 不抢首页主线 |

### 6.9 P0 点击路径

原型第一版必须至少打通这些点击：

| 起点 | 点击 | 结果 |
|---|---|---|
| 起点诊断 | 生成我的路径 | 进入今日页，显示推荐路径和今日任务 |
| 今日页 | 开始训练 | 进入训练执行页 |
| 今日页 | 为什么练这个 | 进入当前节点详情 |
| 今日页 | 今天不舒服 | 弹出退阶建议，并提供教练升级入口 |
| 能力页 | 切换能力树 | 节点地图切换 |
| 能力页 | 点击当前节点 | 进入节点详情 |
| 节点详情 | 加入今日训练 | 回到今日页并替换/确认主任务 |
| 训练执行 | 完成一组 | 当前组变完成，进度推进 |
| 训练执行 | 完成训练 | 显示复盘结果，节点状态变 completed 或 current |
| 训练执行 | 疼痛较高 | 进入风险提示，可跳到教练升级 |
| 教练升级 | 选择问题原因 | 推荐教练类型和服务入口 |
| 底部 Tab | 今日/能力/教练/我的 | 切换主页面，不改变当前 mock 用户状态 |

## 8. 高质量内容结构

高质量内容不能只是文章和视频列表，必须转成平台结构。

每个能力节点至少包含：

| 字段 | 说明 |
|---|---|
| 节点名 | 用户能理解的动作或能力 |
| 适合人群 | 谁应该练 |
| 训练目的 | 为什么现在练 |
| 通过标准 | 怎么算过关 |
| 今日任务 | 组次/时长 |
| 退阶动作 | 做不了怎么降级 |
| 进阶动作 | 做好了下一步是什么 |
| 常见错误 | 小白最容易错在哪里 |
| 疼痛边界 | 什么时候停止或找教练 |
| 饮食提示 | 和当前目标相关的一条原则 |
| 来源 | 平台原创、教练、外部参考、审核人 |

内容来源可以来自教练、平台原创、外部资料，但进入平台前必须被转译成以上结构，不能简单复制粘贴。

## 9. AI 功能定位

AI 不作为独立 Tab，不抢主线。它嵌在流程里：

- 起点诊断：把问卷答案转成路径。
- 节点解释：把专业知识改写成小白能执行的规则。
- 训练复盘：根据完成度、疼痛、RPE、睡眠给建议。
- 瓶颈诊断：连续停滞后判断是训练量、动作、恢复、饮食还是计划问题。
- 教练助手：帮教练生成点评 cue、下周调整建议、节点内容草稿。

原型阶段全部使用 mock，不调用真实 API。

## 10. 原型制作边界

本轮原型应该放在 `prototypes/` 下，独立运行，不影响主项目：

- 不改 `src/app` 正式路由。
- 不改 `wechat_app` 真实逻辑。
- 不接数据库。
- 不接真实登录。
- 不接真实支付。
- 不接真实教练列表 API。
- 使用本地 mock 数据和前端状态。
- 可以用 Next.js 做移动端网页壳，但视觉和交互必须像小程序。

旧的 `prototypes/ability-tree-app` 如果继续使用，必须重做为纯手机小程序界面，移除右侧解释面板和宣传脚本面板。

## 12. 页面流程

### 12.1 新用户

```text
打开小程序
  -> 起点诊断
  -> 生成本周路径
  -> 今日页
  -> 开始今日训练
  -> 完成训练反馈
  -> 点亮当前节点
```

### 12.2 老用户

```text
打开小程序
  -> 今日页
  -> 继续今日主任务
  -> 训练执行
  -> 完成后复盘
```

### 12.3 卡关用户

```text
训练表现停滞 / 疼痛风险高 / 动作不达标
  -> 系统提示原因
  -> 推荐节点知识或退阶动作
  -> 仍解决不了
  -> 推荐教练类型
  -> 进入视频点评/私信/订阅
```

### 12.4 第一条录屏演示脚本

第一版原型必须支持一条 30 秒内能录完的主线：

```text
打开原型
  -> 选择“零基础 / 每次 10-20 分钟 / 无器械 / 没有明显疼痛”
  -> 点击“生成我的路径”
  -> 今日页显示“基础能力 L1 / 推力树 / 墙面推”
  -> 点击“为什么练这个”看节点标准
  -> 返回今日页点击“开始训练”
  -> 完成 2 组
  -> 出现复盘：“今日完成，节点进度 +1，下次继续巩固”
  -> 切到能力页，看到当前节点被点亮
```

第二条可选录屏线：

```text
今日页点击“今天不舒服”
  -> 选择“肩颈不适”
  -> 系统推荐退阶动作和安全提示
  -> 点击“找人帮我看”
  -> 教练页按问题推荐“进阶教练 / 视频点评”
```

## 13. 入口隐藏和合并规则

### 13.1 首屏隐藏

以下功能不出现在新手首屏：

- 街健指数、复杂计算器。
- 排行榜。
- 会员权益。
- 购物车、订单。
- 大量教练商品。
- 计划库编辑。
- 专业术语密集的知识列表。

### 13.2 合并规则

- 知识库合并到节点详情。
- 动作库合并到能力节点标准。
- 工具箱合并到“我的”和高级节点。
- 教练发现合并到卡关升级路径。
- 好友/动态合并到同路径进度激励。
- 会员/支付合并到教练服务或高级权益，不作为小白主线。

## 14. 视觉和交互要求

原型可以炫酷，但不能像广告页。

要求：

- 手机全屏界面，宽度按移动端设计。
- 有底部 Tab。
- 有真实页面跳转或状态切换。
- 有明确主按钮，但按钮使用纯色，不使用渐变。
- 首屏必须看见“当前路径 + 今日任务 + 开始训练”。
- 动画只服务于状态变化：生成路径、点亮节点、完成训练。
- 不在页面里写大段产品解释。
- 适合录屏传播的关键画面：
  - 选完诊断后生成路径。
  - 今日只给一个主任务。
  - 完成训练后节点点亮。
  - 卡关后推荐教练类型。

### 14.1 手机壳结构

如果原型用网页实现，在桌面浏览器里也只能展示一个居中的手机界面：

- 推荐视觉宽度：`390px` 左右，模拟主流手机。
- 页面高度按移动端滚动处理，不做桌面双栏。
- 顶部可以有小程序式标题栏。
- 底部 Tab 固定。
- 内容区可以滚动。
- 任何解释、备注、设计说明都不能放在手机界面右侧。

### 14.2 P0 组件清单

| 页面 | 必须有的组件 | 不要出现 |
|---|---|---|
| 起点诊断 | 选择卡、生成按钮、路径结果卡 | 长表单、专业问卷术语 |
| 今日 | 当前路径卡、今日主任务卡、开始按钮、安全提示、周进度 | 功能宫格、排行榜、会员广告 |
| 能力 | 能力树切换、节点地图、节点状态说明 | 大段理论说明 |
| 节点详情 | 动作标准、通过条件、退阶/进阶、常见错误、安全边界 | 完整文章列表 |
| 训练执行 | 视频位、组次卡、完成按钮、RPE/疼痛记录、完成复盘 | 教练商城、知识流 |
| 教练 | 卡关原因、教练类型、推荐卡、视频点评入口 | 泛泛的教练列表首屏 |
| 我的 | 训练记录、计划、动作库、工具、好友、会员入口 | 主线任务卡 |

### 14.3 文案约束

- 面向小白的按钮和标题必须用行动语言，例如“开始今天训练”“看动作标准”“我今天不舒服”。
- 避免在首屏使用 RM、分化训练、周期化、容量、代偿等专业词；必须出现时要放在节点解释里。
- 每张卡只讲一个目的，避免一张卡同时塞训练、知识、社交、会员和教练。

## 15. 验收标准

原型验收只问这些问题：

1. 它看起来是不是一个小程序雏形，而不是解释网页？
2. 右侧有没有解释面板？如果有，失败。
3. 小白 10 秒内是否知道今天该做什么？
4. 用户是否知道自己在哪个能力树、哪个等级、哪个节点？
5. 知识内容是否服务当前动作，而不是堆成资料库？
6. 教练是否在卡关时自然出现，而不是首屏卖课？
7. 现有 CoachLink 功能是否被合理保留和重组？
8. 原型是否可以独立运行，不影响主项目？
