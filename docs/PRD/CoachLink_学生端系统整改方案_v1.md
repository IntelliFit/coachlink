# CoachLink 学生端系统整改方案 v1

- 日期：2026-05-10
- 状态：讨论稿
- 目标：把当前分散的功能集合，收敛成一个小白能理解、进阶用户也有路径的学生端产品系统。
- 原则：先改信息架构和入口层，不推倒重写，不删除已有模块；先隐藏、合并、重排，再逐步升级数据和内容结构。

## 1. 结论先行

CoachLink 初期不应该继续表达成“健身功能平台”，而应该表达成：

> 可信健身路径系统：先判断你在哪，再告诉你本周做什么，边练边学，记录反馈，卡住时升级到教练、伙伴或进阶工具。

学生端主线建议固定为：

```text
起点诊断 -> 本周路径 -> 今日训练 -> 训练执行 -> 记录反馈 -> 能力升级 / 教练支持 / 伙伴激励
```

对用户来说，第一屏要回答三个问题：

1. 我现在处在哪个阶段？
2. 我今天具体要做什么？
3. 为什么这样做，以及做完以后怎么进步？

这比展示“知识库、找教练、排行榜、工具箱、动作库、会员、商城”等入口更重要。

## 2. 当前产品问题

当前 CoachLink 的问题不是能力不足，而是能力过多且并列出现。

主要问题：

- 训练、知识、教练、工具、社交、会员、排行榜、商城都像主功能，小白不知道该从哪里开始。
- 知识库更像资料仓库，不像“我当前阶段该看的内容”。
- 找教练更像市场，不像“我卡在某个问题时的解决方案”。
- 工具箱、排行榜、街健计算器等功能很有价值，但提前暴露会让新手觉得专业、复杂、和自己无关。
- 今日训练最接近核心价值，但还没有完全承担“路径首页”的职责。
- 用户的真实痛点不是“没有功能”，而是“不知道该信谁、不知道怎么练、练了没效果、吃不明白、怕受伤、坚持没有反馈”。
- 新手还有一类很强的进入门槛：害怕进入健身房、害怕被别人看到动作不标准、害怕不会用器械、害怕被私教销售围住。这类心理阻力会发生在训练开始之前，如果不处理，用户根本走不到训练执行页。

## 3. 整改原则

### 3.1 不删功能，先降噪

已有模块先保留，入口层重新组织。复杂功能从一级入口收进二级入口，避免新手首屏被打散。

### 3.2 不做内容仓库，做内容转化

高质量内容不能只是搬进知识库。每条内容要转成平台可用资产：

- 路径
- 诊断题
- 动作标准
- 安全边界
- 饮食规则
- 计划规则
- 今日任务
- 复盘解释
- 教练匹配标签

### 3.3 不让小白自己做复杂选择

新手不需要 10 个入口，他需要一个可信的推荐：

> 本周先做这几件事。

### 3.4 按阶段露出功能

同一个功能对不同阶段用户价值不同：

- 动作库：新手看标准动作，进阶者看变式和弱点。
- 知识库：新手看少量必读，进阶者看体系专题。
- 排行榜：新手阶段隐藏，高阶专项用户再露出。
- 教练：新手是护航，进阶是纠错，高阶是周期化和专项突破。

### 3.5 伤病/恢复必须谨慎表达

平台可以做疼痛筛查、风险提示、动作替换、恢复建议、转介提醒，但不应在普通产品页面宣称医疗诊断或治疗。

### 3.6 心理安全感要前置

对新手来说，“我敢不敢开始”往往比“我该练什么”更早发生。

产品需要明确降低这些心理门槛：

- 不强迫用户一开始就去健身房。
- 给出家里、宿舍、户外、健身房角落都能完成的低暴露训练方案。
- 教用户如何在健身房安全开始：怎么选器械、怎么避开高峰、怎么做不尴尬的第一组。
- 文案避免羞辱和身材焦虑，不把“不自律”当成用户失败原因。
- 教练入口需要区分“新手护航 / 动作纠错 / 私教避坑”，而不是只展示专业头衔。
- 社群和伙伴机制早期不应制造攀比，应该先提供匿名、低压力、只看完成度的陪伴。

## 4. 用户分层与首页任务

| 用户阶段 | 核心痛点 | 首页一句话 | 今日主按钮 | 主要内容 | 工具/教练露出 |
|---|---|---|---|---|---|
| 儿童/青少年 | 安全、兴趣、习惯、家长/教练可见 | 安全建立运动习惯 | 完成今日动作挑战 | 基础动作、安全规则、趣味任务 | 家长/教练可见，弱化强度和身材焦虑 |
| 成人零基础 | 怕练错、信息乱、怕丢脸、怕进健身房 | 本周先学会安全开始 | 开始 10 分钟低暴露训练 | 动作基础、训练前检查、饮食三原则、健身房不尴尬指南 | 动作纠错教练、新手护航、低门槛陪伴 |
| 减脂/塑形新手 | 吃不明白、时间少、看不到效果 | 用最低有效剂量建立反馈 | 开始今日 20 分钟训练 | 简化饮食、外食指南、体型反馈 | 饮食框架、打卡反馈 |
| 普通自练者 | 计划连续性、记录、偶尔纠错 | 继续你的本周计划 | 继续今日训练 | 动作标准、训练记录、计划解释 | 视频点评、计划微调 |
| 平台期进阶者 | 没效果、瓶颈、饮食/恢复混乱 | 找出你卡住的原因 | 做平台期诊断 | 容量、强度、恢复、营养诊断 | 个性化教练、周期化计划 |
| 伤病/体态恢复用户 | 疼痛、动作受限、怕加重 | 先安全筛查，再安排动作 | 做今日低风险训练 | 疼痛自检、替代动作、恢复知识 | 康复/纠错型教练，必要时建议线下专业人士 |
| 专项高阶选手 | 标准、周期、PR、恢复、社群身份 | 按专项指标推进周期 | 进入专项训练 | 周期化、动作标准、数据分析 | 排行榜、赛事、专项教练、高阶工具 |

## 5. 新学生端信息架构

建议学生端一级导航收敛为四个：

```text
今日 / 能力 / 教练 / 我的
```

### 5.1 今日

今日是学生端主入口，不只是训练列表。

它应该展示：

- 当前阶段：例如“零基础起步”“平台期诊断”“引体专项进阶”。
- 本周目标：本周只做哪 2-3 件事。
- 今日主按钮：开始训练 / 继续训练 / 做起点诊断 / 做复盘。
- 今日解释：为什么今天这样练。
- 今日风险：疼痛、疲劳、恢复提醒。
- 心理安全提示：如果用户是新手，告诉他今天可以在家/宿舍/户外/健身房角落完成，不需要先去复杂环境。
- 今日反馈：完成度、连续性、下一步。

### 5.2 能力

能力不是普通知识库，而是“动作能力路径”。

它承接：

- 能力树 / 节点路径
- 动作标准
- 节点知识
- 常见错误
- 训练进阶
- 低风险替代动作
- 相关计划和训练任务

能力页的作用是让用户知道：

> 我不是在随机练动作，我是在解锁某个能力。

### 5.3 教练

教练页不要先做成市场，而应按问题组织：

- 新手护航
- 动作纠错
- 平台期突破
- 伤病友好 / 体态恢复
- 专项提升
- 训练搭子 / 陪伴监督

教练的出现时机也要变：

- 用户起点诊断显示高风险或需求明确时出现。
- 用户连续未完成、疼痛反馈、动作不确定、平台期停滞时出现。
- 用户主动进入教练页时，再展示完整教练供给。

### 5.4 我的

我的页作为收纳中心：

- 训练记录
- 全部计划
- 我的动作库
- 我的会员
- 我的好友
- 消息
- 工具箱
- 街健计算器
- 排行榜
- 订单/购物车
- 设置

“我的”不应该继续承载太多首屏训练主线，它更像账户、历史和高级入口的集合。

## 6. 今日页推荐结构

今日页建议按以下顺序：

```text
1. 当前路径卡
   零基础起步 · 第 1 周
   本周目标：建立训练节奏，学会 3 个基础动作

2. 本周只做这 3 件事
   - 完成 2 次基础训练
   - 每餐补一个蛋白质来源
   - 训练前检查肩/腰/膝是否不适

3. 今日主行动
   开始今天训练 / 继续训练 / 先做 10 分钟起步训练

4. 今日为什么
   用一句小白能懂的话解释今天安排，不展示大段理论。

5. 今日学习卡
   只推荐 1-2 个和今天相关的内容。

6. 反馈/风险卡
   疼痛、疲劳、完成度、上次卡点。

7. 升级入口
   动作不确定 -> 视频点评
   练了没效果 -> 平台期诊断
   疼痛/不适 -> 低风险替代 / 找专业人士
```

## 7. 起点诊断

起点诊断是整个整改的关键。它不应只是资料完善，而是判断用户当前最大阻碍。

第一版可以复用现有 onboarding / questionnaire 数据，不急着大改数据库。

建议问题：

1. 你现在训练多久了？
2. 当前最重要目标是什么？
3. 每周能练几次？
4. 每次大概能练多久？
5. 有哪些器械或场地？
6. 最近是否有疼痛或旧伤？
7. 你最大的困扰是什么：不会练、没效果、饮食、坚持、怕受伤、没时间、动作不标准？
8. 你是否害怕去健身房、害怕被别人看到、或不知道怎么使用器械？
9. 你更希望在哪里开始：家里、宿舍、户外、健身房、都可以？
10. 你是否愿意上传动作视频？
11. 你是否愿意找教练或训练搭子？
12. 饮食最难的是外食、蛋白质、热量、社交，还是不知道吃什么？
13. 你喜欢严格计划还是轻量建议？
14. 你更想自己学，还是有人带？

输出不需要复杂：

```text
用户阶段：成人零基础
核心卡点：怕练错 + 时间少 + 不敢进健身房
推荐路径：7 天最低有效起步
本周任务：2 次低暴露训练 + 3 条饮食原则 + 1 次动作自检 + 1 条健身房入门提示
```

## 8. 内容如何转化进平台

内容不是“搜集后放进知识库”，而是进入内容转化流水线。

| 内容来源 | 转化后的平台资产 |
|---|---|
| 权威指南 / 研究共识 | 安全边界、训练原则、饮食规则、阶段判断 |
| 教练/KOL 方法论 | 训练路径、动作提示、常见错误、案例复盘 |
| 用户评论/微信群问题 | 诊断题、FAQ、复盘解释、内容选题 |
| 动作教学视频 | 动作标准、错误识别、进阶/退阶动作 |
| 训练计划/课程 | 周任务、今日任务、能力节点、计划模板 |
| 饮食内容 | 手掌法则、外食指南、蛋白优先、简化执行卡 |
| 伤病/恢复内容 | 筛查清单、禁忌提示、替代动作、转介建议 |
| 社恐/健身房恐惧内容 | 新手健身房脚本、低暴露训练、器械使用第一步、私教避坑清单 |

内容生产流程建议：

```text
收集来源 -> 判断可信度 -> 标记适用阶段 -> 拆成平台资产 -> 绑定路径/节点/任务 -> 教练或专家校审 -> 发布到对应场景
```

第一批不要做大而全。建议先做一个完整内容包：

```text
零基础 7 天起步路径
```

包含：

- 10-12 题起点诊断
- 本周 2 次训练
- 3 条饮食原则
- 5 个基础动作标准
- 疼痛/疲劳自检
- 低暴露开始方案：家里、宿舍、户外、健身房角落都可完成
- 健身房第一次怎么做：避开高峰、选择简单器械、完成后离开也算成功
- 每日打卡反馈
- 第 7 天复盘

## 9. 现有功能如何保留并重组

| 现有功能 | 新定位 | 入口策略 |
|---|---|---|
| 今日训练 | 学生端首页和主线 | 一级入口 `今日` |
| 训练执行 | 今日任务的执行页 / 能力节点挑战 | 从今日和能力节点进入 |
| 知识库 | 节点知识和阶段内容来源 | 不做一级泛入口，先嵌入路径 |
| 动作库 | 动作标准和节点动作库 | 能力节点详情内露出 |
| 找教练/发现 | 卡点升级和支持系统 | 一级入口 `教练`，按问题分类 |
| 私信/视频点评 | 教练支持和纠错工具 | 从教练、节点卡点、训练后反馈进入 |
| 好友/社区 | 陪伴和监督 | 早期做低压力完成度陪伴，后期再做同侪比较 |
| 计划库 | 教练/平台生成路径的底层能力 | 对学生隐藏复杂编辑，前台只看路径 |
| 工具箱 | 进阶辅助工具 | 收到 `我的 / 进阶工具` |
| 街健计算器 | 高阶专项工具 | 专项路径或 `我的 / 进阶工具` |
| 排行榜 | 高阶激励/专项社群 | 新手隐藏，专项阶段解锁 |
| 会员/商城 | 商业化支持 | 不抢训练主线，放在我的或升级场景 |

## 10. 第一阶段应该隐藏/降级的内容

第一阶段建议从新手首屏隐藏或降级：

- 排行榜
- 街健计算器
- 社区数据
- 泛资讯流
- 购物车/商城
- 会员推广大卡
- 复杂动作库操作
- 好友动态
- 工具箱大入口
- 服务商品市场

这些不是不要，而是不要在用户还不知道自己该做什么时出现。

## 11. 分阶段落地计划

### Phase 0：讨论稿和原型校准

目标：确定方向，不动真实业务代码。

产物：

- 本文档 v1
- 能力树原型继续迭代
- 明确底部导航、今日页、教练页、能力页的产品语义

### Phase 1：入口层整改

目标：用最小代码改动让学生端不再散。

建议改动：

- 小程序底部导航调整为 `今日 / 能力 / 教练 / 我的`。
- 今日页首屏改成路径仪表盘。
- 发现页降噪，转成教练支持入口。
- 我的页收纳工具、会员、好友、排行榜、订单等。
- 知识入口暂时从一级入口降为路径/节点内容。

不做：

- 不删除旧页面。
- 不重写训练执行。
- 不重写支付、会员、聊天、教练后台。
- 不大改数据库。

### Phase 2：起点诊断接入

目标：用户一进来知道自己是哪条路径。

建议改动：

- 复用 onboarding 问卷字段。
- 输出阶段、核心卡点、推荐路径。
- 今日页展示当前路径。
- 教练页按路径推荐教练类型。

### Phase 3：零基础 7 天路径

目标：做第一个完整闭环，而不是做全平台。

包含：

- 训练任务
- 饮食任务
- 动作标准
- 疼痛/疲劳筛查
- 新手心理安全提示和低暴露训练选择
- 打卡反馈
- 7 天复盘

### Phase 4：能力树真实接入

目标：把动作库、知识、训练任务连接成能力节点。

建议从基础动作开始：

- 推：墙/跪姿/标准俯卧撑
- 拉：澳洲划船/弹力带辅助引体/引体
- 腿：徒手深蹲/分腿蹲
- 髋：臀桥/髋铰链
- 核心：死虫/平板/卷腹或抗伸展
- 恢复：肩颈/腰背/髋膝踝基础筛查

### Phase 5：教练和内容供给升级

目标：让教练不是列表，而是路径系统里的供给者。

建议：

- 教练按解决问题分类。
- 教练主页展示方法论、擅长路径、案例和内容。
- 教练可以绑定能力节点、课程、动作标准、视频点评服务。
- 平台内容和教练内容共用结构化模板。

## 12. 第一阶段代码改动边界

如果开始真实落地，建议优先只动这些区域：

- `wechat_app/src/components/BottomNav.tsx`
- `wechat_app/src/components/BottomNav.scss`
- 小程序首页 / 今日训练入口
- `wechat_app/src/training/today-training/*`
- 小程序 discovery / coach 入口相关页面
- 小程序 profile / me 菜单收纳
- Web 学生导航可以后置同步

第一阶段不建议动：

- 支付链路
- 教练后台核心工作台
- 训练执行核心逻辑
- 计划生成逻辑
- 数据库结构
- 大量测试文件

## 13. 评估指标

整改后应该看这些指标，而不是只看页面是否更好看：

- 新用户完成起点诊断率
- 新用户第一天开始训练率
- 第 7 天留存 / 完成复盘率
- 首周完成 2 次训练比例
- 新手选择低暴露训练后的完成率
- 健身房恐惧/社恐用户是否愿意进入下一步训练
- 用户是否能复述“我现在在做哪条路径”
- 今日页主按钮点击率
- 知识内容从训练路径进入的点击率
- 卡点用户进入教练支持的转化率
- 工具箱/排行榜是否减少新手误点但保留高阶使用

## 14. 主要风险

### 风险 1：能力树太游戏化，显得不专业

解决：能力树只是表达层，底层仍然用动作标准、训练原则和阶段路径支撑。不要把 UI 做成幼稚游戏。

### 风险 2：内容质量跟不上

解决：先做一个小而完整的 7 天路径，不先做大百科。

### 风险 3：隐藏高级功能后老用户找不到

解决：从 `我的 / 进阶工具` 保留入口，并对高阶用户按阶段露出。

### 风险 4：教练供给和路径不匹配

解决：先按问题给教练打标签，不急着做复杂推荐算法。

### 风险 5：伤病/恢复表达有风险

解决：所有相关内容使用筛查、低风险动作、转介建议，不做医疗承诺。

### 风险 6：过度强调社群和排名会放大新手焦虑

解决：新手阶段只展示低压力完成度、匿名鼓励和个人进步，不展示身材对比、强排名和高阶数据。

## 15. 需要继续和用户确认的问题

下一轮建议重点讨论这些问题：

1. 一级导航用 `今日 / 能力 / 教练 / 我的`，还是 `训练 / 学习 / 教练 / 我的`？
2. 第一条验证路径选哪个：`零基础 7 天起步`、`减脂塑形起步`、`体态恢复`，还是 `引体进阶`？
3. “能力树”要作为品牌核心概念，还是只作为内部组织方式？
4. 教练入口是否应该保留一级，还是先放到今日/能力里的卡点升级？
5. 新手首屏要不要完全隐藏排行榜和街健工具？
6. 内容供给先由平台原创，还是先和现有教练/KOL 共创？
7. 儿童/青少年是否作为近期目标，还是先只作为未来分层预留？
8. 新手心理安全要做到什么程度：只提供居家替代方案，还是明确做“第一次去健身房”引导？

## 16. v1 建议

我的建议是：

第一步不要急着做“完整能力树系统”，先用能力树的思想重组入口。

最小有效改版应是：

```text
今日页变成路径首页
能力页承接动作标准和知识
教练页按问题提供支持
我的页收纳历史和高级功能
```

然后用 `零基础 7 天起步路径` 做第一个完整闭环。只要这条路径跑通，CoachLink 就不再像一堆功能，而会开始像一个能带用户前进的系统。
