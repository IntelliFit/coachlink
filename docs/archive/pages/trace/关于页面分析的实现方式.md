# Trace 埋点实现流程速览

- **公共工具**：`TRACE_ENV`、`ALLOW_DEV_TRACE`、`hasServiceRoleKey`、`safeText`、`safeProps`、`shouldSkipTrace` 集中在 [src/app/api/trace/trace-common.ts](src/app/api/trace/trace-common.ts#L1-L41)，统一做环境判断（未开 `TRACE_ALLOW_DEV=1` 且非生产/本地则跳过）、文本裁剪和 service role key 检查。
- **API 全局自动埋点**：API 中间件在每次命中时记录 `api_hit` 事件并异步写入 `admin_trace_events`，同时尊重跳过规则与 service key 检查，位置见 [src/app/api/middleware/api-trace.ts](src/app/api/middleware/api-trace.ts#L1-L43)。
- **自定义事件采集 POST /api/trace**：接收单条或批量（最多 50 条）事件，校验/裁剪字段，填充会话用户、UA、Referrer、环境与方法后写入 `admin_trace_events`；事件字段包含 `path`（即 to_path）、`from_path`、`duration_ms`，支持可选共享密钥 `TRACE_SHARED_SECRET`（或已登录用户）授权，逻辑见 [src/app/api/trace/route.ts](src/app/api/trace/route.ts#L22-L141)。
- **事件停留补充 PUT /api/trace**：按 `trace_id` 更新 `leave_at` 及可选 `duration_ms`，同样复用跳过与授权规则，位置在 [src/app/api/trace/route.ts](src/app/api/trace/route.ts#L143-L214)。
- **关键环境变量**：`NEXT_SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_SERVICE_ROLE_KEY`（写库必需），`TRACE_ALLOW_DEV`（设置为 "1" 才会在非生产/本地环境写入），`TRACE_ENABLE_API_TRACE`（设置为 "1" 才会记录后端 API 自动埋点，默认关闭），`TRACE_SHARED_SECRET`（可选共享密钥），`TRACE_ENV`/`NEXT_PUBLIC_APP_ENV`/`APP_ENV`/`NODE_ENV`（决定埋点环境值）。

## 业务行为分析实现 (User Behavior Analytics)

除上述系统级/页面级 Trace 外，系统还实现了一套专注于**用户业务行为**的分析系统，用于追踪产品核心价值的使用情况（如：完成训练、创建计划、使用AI等）。

### 1. 架构概览

*   **数据流向**：Frontend (`useAnalytics`) → API (`/api/trace/behavior`) → Database (`user_behavior_events`)
*   **存储表**：`user_behavior_events` (与 `admin_trace_events` 隔离，专注于业务逻辑)
*   **可视化**：后台 `Admin > Analytics` 页面 (Dashboard / Features / Retention)

### 2. 核心组件

*   **前端 Hook**: `src/hooks/useAnalytics.ts`
    *   提供 `trackEvent(eventName, eventCategory, eventData)` 方法。
    *   底层调用 `AnalyticsService` 单例 ([src/lib/analytics.ts](src/lib/analytics.ts))。
*   **后端 API**: `src/app/api/trace/behavior/route.ts`
    *   验证用户 Session。
    *   自动补充 `user_type`, `user_id`, `page_path`。
    *   写入 Supabase `user_behavior_events` 表。
*   **数据库**:
    *   表 `user_behavior_events`: 存储原始事件流 (JSONB `event_data`)。
    *   视图 `feature_usage_stats`: 预计算功能的每日/每周使用量。
    *   RPC `get_retention_data`: 动态计算用户留存率 (Cohort Analysis)。

### 3. 已埋点核心事件清单

目前系统已在以下关键业务节点完成埋点上报：

#### 学员端 (Student) - 核心价值交付
| 事件名 (`event_name`) | 分类 (`event_category`) | 触发时机 | 关键参数 (`event_data`) |
| :--- | :--- | :--- | :--- |
| `student_set_complete` | training | 完成一组训练时 | `weight`, `reps`, `rpe`, `is_pr` |
| `student_pr_record` | training | 打破个人记录时 | `type` (manual/auto), `improvement` |
| `student_video_upload` | training | 上传动作视频时 | `action_id`, `execution_id` |
| `student_training_start` | training | 开始一次训练 | `plan_id` |
| `student_training_complete` | training | 完成整场训练 | `total_sets`, `duration` |

#### 教练端 (Coach) - 生产力与管理
| 事件名 (`event_name`) | 分类 (`event_category`) | 触发时机 | 关键参数 (`event_data`) |
| :--- | :--- | :--- | :--- |
| `coach_plan_create` | coach | 创建新的训练计划模版 | `days_count`, `tags_count`, `suitable_for` |
| `coach_action_upsert` | coach_content | 创建或更新动作 | `is_create`, `has_video`, `type` |
| `coach_ai_plan_generate` | coach | 使用AI生成计划 | `is_bulk`, `student_id`, `success_count` |
| `coach_view_student_detail` | coach | 查看学员详细档案 | `student_id` |
| `coach_manual_payment` | business | 确认线下收款/续费 | `count`, `amount` |

| `coach_product_create` | business | 上架新产品 | `tier`, `type`, `price` |

### 4. 数据计算与分析

*   **实时性**：数据写入后立即在大屏可见（基于直接的 SQL 查询）。
*   **留存计算**：基于 RPC 函数 `get_retention_data`，通过对比 `users` 表的注册时间与 `user_behavior_events` 的活跃时间来计算 N-Day Retention。
*   **功能渗透率**：通过统计特定 event_name 的去重用户数除以总活跃用户数计算。
