## 1. 业务场景与价值

### 1.1 为什么需要智能导入？

**痛点**：
- 教练从 Excel/文档/聊天记录复制训练计划，需要手动逐个添加动作（耗时 10-30 分钟）
- 学员想导入自己的训练计划，但平台要求结构化输入，门槛高
- 动作库中已有相似动作，但手动创建时容易重复，导致动作库混乱

**解决方案**：
- 用户粘贴自由格式文本 → AI 自动解析 → 生成结构化模板（耗时 30-60 秒）
- 自动匹配现有动作库，避免重复创建
- 支持多种文本格式（简洁/详细/Excel 导出等）

### 1.2 业务价值

| 指标 | 手动创建 | 智能导入 | 提升 |
|------|---------|---------|------|
| **创建时间** | 10-30 分钟 | 30-60 秒 | **20-60 倍** |
| **动作重复率** | 高（容易创建重复动作） | 低（自动匹配） | **显著降低** |
| **用户门槛** | 高（需要理解结构化格式） | 低（粘贴文本即可） | **大幅降低** |
| **错误率** | 中（手动输入易错） | 低（AI 解析 + 用户确认） | **降低** |

## 2. 功能概述

### 2.1 核心功能

智能导入计划是一个**两阶段 AI 解析**功能：

1. **阶段 1：动作解析** - 从文本中提取所有动作，匹配现有动作库
2. **阶段 2：模板解析** - 基于已确认的动作，解析完整的周/天训练结构

### 2.2 用户交互流程

```
┌─────────────────┐
│  1. 粘贴文本     │
└────────┬────────┘
         ↓
┌─────────────────┐
│  2. 确认动作     │ ← 用户可编辑动作名称、属性、是否使用已有动作
└────────┬────────┘
         ↓
┌─────────────────┐
│  3. 预览模板     │ ← 显示解析出的周/天结构、组次、强度等
└────────┬────────┘
         ↓
┌─────────────────┐
│  4. 导入完成     │ → 自动填充到模板编辑器
└─────────────────┘
```

### 2.3 适用角色

- **教练端**：`/dashboard/plan-lib/create` → 创建模板
- **学员端**：`/me/plan-lib/create` → 创建自己的计划

### 3.3 AI 模型配置

**当前使用**：DeepSeek Chat (`deepseek-chat`)

**配置参数**：
```typescript
{
  model: "deepseek-chat",
  max_tokens: 6000,        // 防止长计划被截断
  temperature: 0.2,        // 保证输出稳定性
  response_format: { type: "json_object" }  // 强制 JSON 输出
}
```

**选择理由**：
- ✅ 成本效益高（比 GPT-4 便宜 10-20 倍）
- ✅ 中文理解能力强
- ✅ 支持 JSON 格式输出，解析稳定
- ✅ API 响应速度快（通常 2-5 秒）

## 4. 核心流程详解

### 4.1 阶段 1：动作解析 (`parse-actions`)

**目标**：从文本中提取所有动作，并与现有动作库进行匹配

**输入**：
```typescript
{
  text: "W1D1\n负重引体 5RM 3×3 组休 3分\n锤式弯举 3组8次\n..."
}
```

**处理流程**：

```
1. 文本预处理
   ├─ splitPlanGlobalPreface() → 分离全局说明（如热身方法）
   ├─ normalizeTextForActionExtraction() → 标准化文本
   │  └─ "负重引体5RM" → "负重引体 5RM" (插入空格)
   │  └─ "然后" → 换行 (拆分复合动作)
   │
2. AI 提取动作列表
   ├─ 调用 DeepSeek API
   ├─ Prompt: "从文本中提取所有动作名称..."
   └─ 返回: { actions: [{ name, matchedExistingId, ... }] }
   │
3. 后处理
   ├─ sanitizeActionName() → 清洗动作名（移除强度/组次标记）
   ├─ isLikelyNonActionName() → 过滤非动作内容
   ├─ findBestExistingActionMatch() → 匹配现有动作库（Dice 系数）
   ├─ inferStrengthAttrs() → 推断动作属性（组数/次数/强度/休息时间）
   └─ 合并同义动作（避免重复新建）
   │
4. 返回结果
   └─ { actions: [{ name, matchedExistingId, needsAutoCompute, ... }] }
```

**输出示例**：
```json
{
  "success": true,
  "data": {
    "actions": [
      {
        "name": "负重引体",
        "matchedExistingId": "825b9538-badb-428c-a154-dff420ae095f",
        "needsAutoCompute": true,
        "includesBodyWeight": true,
        "attrs": ["组数", "次数", "强度", "休息时间"],
        "isNew": false
      },
      {
        "name": "锤式弯举",
        "matchedExistingId": null,
        "needsAutoCompute": true,
        "includesBodyWeight": false,
        "attrs": ["组数", "次数", "强度", "休息时间"],
        "isNew": true
      }
    ]
  }
}
```

### 4.2 阶段 2：模板解析 (`parse-template`)

**目标**：基于已确认的动作库，解析完整的周/天训练结构

**输入**：
```typescript
{
  text: "W1D1\n负重引体 5RM 3×3 组休 3分\n...",
  actions: [
    { id: "xxx", name: "负重引体", ... },
    { id: "yyy", name: "锤式弯举", ... }
  ]
}
```

**处理流程**：

```
1. 提取全局说明
   ├─ splitPlanGlobalPreface() → 提取热身/执行说明
   └─ 保存到 globalDescription 字段
   │
2. 按周拆分文本
   ├─ splitPlanByWeekSections() → 识别 "W1D1"、"第X周" 等标记
   └─ 支持中文数字（一、二、三...）
   │
3. 逐周并行解析
   ├─ Promise.all() → 并行调用 DeepSeek（提升性能）
   ├─ 每段文本独立解析
   └─ Prompt: "将训练计划解析为结构化周训练模板..."
   │
4. 强度配置处理
   ├─ 优先级：绝对重量 > 百分比 > RM 值 > null
   ├─ "112.5kg (75%)" → 优先使用固定重量
   └─ "5RM" → { type: "rm", value: 5 }
   │
5. 次数推断规则
   ├─ 如果原文未明确写次数（如只有 "12RM" 没有 "×5次"）
   └─ 则 reps: null（避免将 RM 值误当作次数）
   │
6. 周内天数标准化
   ├─ normalizeWeekDays() → 确保 dayOfWeek 连续且不重复
   ├─ 自动补齐休息日（根据"每周训练X天"推断）
   └─ 保持输入顺序
   │
7. 合并所有周的结果
   └─ 按 weekIndex 排序，返回完整模板
```

**输出示例**：
```json
{
  "success": true,
  "data": {
    "weeks": 4,
    "globalDescription": "热身遵循温宁热身法：全身热身+对应部位热身...",
    "trainingDays": [
      {
        "weekIndex": 1,
        "dayOfWeek": 1,
        "type": "training",
        "actions": [
          {
            "actionId": "825b9538-badb-428c-a154-dff420ae095f",
            "sets": 3,
            "reps": 3,
            "restSeconds": 180,
            "intensityConfig": {
              "relativeIntensity": { "type": "rm", "value": 5 }
            },
            "note": ""
          }
        ],
        "dayNote": ""
      },
      {
        "weekIndex": 1,
        "dayOfWeek": 2,
        "type": "rest",
        "actions": [],
        "dayNote": "休息1天"
      }
    ]
  }
}
```

## 6. 代码实现细节

### 6.1 文本预处理 (`planImportText.ts`)

**核心函数**：

#### `normalizeTextForActionExtraction(text: string)`

**作用**：在动作名和强度标记之间插入空格，避免 AI 将强度误当作动作名的一部分

**示例**：
```typescript
输入: "负重引体5RM 3×3"
输出: "负重引体 5RM 3×3"

输入: "自重引体力竭然后双手悬垂力竭"
输出: "自重引体力竭\n双手悬垂力竭"  // "然后" 拆分为换行
```

#### `sanitizeActionName(name: string)`

**作用**：清洗动作名，移除强度/组次/休息等描述

**示例**：
```typescript
输入: "负重引体5RM"
输出: "负重引体"

输入: "锤式弯举10RM 三组 RPE9"
输出: "锤式弯举"

输入: "10公斤引体"
输出: "负重引体"  // 前导重量转换为"负重"前缀
```

#### `findBestExistingActionMatch(name: string, existingActions: Array<{id, name}>)`

**作用**：使用 Dice 系数匹配算法，找到最相似的已有动作

**算法**：
```typescript
// Dice 系数 = 2 * |bigrams(A) ∩ bigrams(B)| / (|bigrams(A)| + |bigrams(B)|)
// 例如："引体向上" 和 "引体" 的相似度
// bigrams("引体向上") = ["引体", "体向", "向上"]
// bigrams("引体") = ["引体"]
// Dice = 2 * 1 / (3 + 1) = 0.5

// 阈值：
// - 短名称（≤2字符）：0.85
// - 长名称：0.78
```

**示例**：
```typescript
输入: "锤式" (用户输入)
已有动作: ["锤式弯举", "普通弯举"]
匹配结果: "锤式弯举" (相似度 0.9，超过阈值 0.78)
```

#### `splitPlanGlobalPreface(text: string)`

**作用**：分离全局说明（如热身方法）和主计划正文

**逻辑**：
- 查找第一个周/天标记（"W1D1"、"第X周"等）
- 标记之前的内容 → `globalDescription`
- 标记之后的内容 → `bodyText`

**示例**：
```typescript
输入: "热身部分\n总体遵循温宁热身法...\n\n第一周 (W1)\nW1D1\n..."
输出: {
  globalDescription: "热身部分\n总体遵循温宁热身法...",
  bodyText: "第一周 (W1)\nW1D1\n..."
}
```

### 6.2 AI Prompt 设计

#### 阶段 1 Prompt（动作提取）

**核心规则**：
1. 提取动作名称（去重）
2. 识别是否需要"自动计算重量"（基于 RM/百分比/重量描述）
3. 判断是否"包含自重"（引体、臂屈伸、俯卧撑等）

### 7.1 错误处理机制

#### AI 解析失败处理

**问题**：DeepSeek API 可能返回非 JSON 格式、JSON 格式错误、内容被截断

**解决方案**：
```typescript
// parseJsonResponse() 函数（src/lib/deepseek.ts）
export function parseJsonResponse<T>(text: string, debugLabel = "deepseek"): T {
  // 1. 清理 markdown 代码块标记
  const cleaned = text
    .replace(/```json\n?/g, "")
    .replace(/```\n?/g, "")
    .trim();
  
  try {
    return JSON.parse(cleaned);
  } catch (err) {
    // 2. 兜底：截取首尾大括号尝试解析
    const first = cleaned.indexOf("{");
    const last = cleaned.lastIndexOf("}");
    if (first !== -1 && last !== -1 && last > first) {
      const fallback = cleaned.slice(first, last + 1);
      try {
        return JSON.parse(fallback);
      } catch (err2) {
        // 3. 最终失败，抛出错误
        throw err;
      }
    }
    throw err;
  }
}
```

```typescript
// normalizeTextForActionExtraction() 函数
export function normalizeTextForActionExtraction(text: string): string {
  if (!text) return "";
  
  // 1. 处理制表符和全角空格
  let t = text.replace(/\t/g, " ").replace(/\u3000/g, " ");
  
  // 2. 保守的正则匹配（避免过度替换）
  t = t.replace(
    /([\u4e00-\u9fffA-Za-z])(\d+(?:\.\d+)?\s*(?:RM|rm|RPE|rpe|%|％|kg|公斤|lbs?|LBs?))/g,
    "$1 $2"
  );
  
  return t;
}
```

## 10. 常见问题与排查

### 10.1 解析失败

**问题**：AI 返回非 JSON 格式或 JSON 格式错误

**排查步骤**：
1. 检查 `src/lib/deepseek.ts` 中的 `parseJsonResponse` 函数
2. 查看服务器日志：`[deepseek] JSON parse failed: ...`
3. 检查 `response_format: { type: "json_object" }` 是否生效

**解决方案**：
- 确保 Prompt 中明确要求 JSON 格式
- `parseJsonResponse` 已有兜底逻辑（截取首尾大括号）

### 10.2 动作匹配失败

**问题**：明明有相似动作，但 AI 没有匹配到

**排查步骤**：
1. 检查动作名是否在已有动作库中
2. 检查 `findBestExistingActionMatch` 的 Dice 系数阈值
3. 查看 AI 返回的 `matchedExistingId` 是否为 null

**解决方案**：
- 降低匹配阈值（但可能增加误匹配）
- 使用动作别名库（升级 4）
- 用户手动在确认阶段切换

### 10.3 强度解析错误

**问题**：`"112.5kg (75%)"` 被解析为百分比而非固定重量

**排查步骤**：
1. 检查 Prompt 中的强度识别优先级规则
2. 查看解析结果中的 `intensityConfig` 字段

**解决方案**：
- Prompt 中已明确：**最高优先级是绝对重量**
- 如果仍出错，检查代码中的强度处理逻辑（`parse-template/route.ts` 第 254-291 行）

### 10.4 全局说明未提取

**问题**：热身方法没有被提取为 `globalDescription`

**排查步骤**：
1. 检查文本是否在第一个 `W1D1` 标记之前
2. 检查 `splitPlanGlobalPreface` 函数是否正确识别周/天标记

**解决方案**：
- 确保全局说明在第一个 `W1D1` / `第X周` 之前
- 如果格式不标准，可以手动在模板编辑器中填写

### 10.5 性能问题

**问题**：8 周以上计划解析时间过长（>30 秒）

**排查步骤**：
1. 检查是否按周并行解析（`Promise.all`）
2. 检查 API 响应时间（DeepSeek 通常 2-5 秒/次）
3. 检查是否有网络超时

**解决方案**：
- 已实现按周并行解析
- 如果仍慢，考虑增加进度提示（"正在解析第X周..."）
- 考虑分批处理（每批 4 周）
