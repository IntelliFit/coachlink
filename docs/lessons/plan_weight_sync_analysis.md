# 教练端计划编辑与数据流架构分析

## 1. 核心架构：三层数据模型详解

针对您提出的三个概念，系统内部对应的数据库结构如下：

| 概念名称              | 对应数据库表                   | 说明                                                                                                                                      | 状态特性                                                                                    |
| :-------------------- | :----------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **1. 教练制定的计划** | **`coach_plan_instances`**     | 这是计划的**母版**。当教练在编辑器中点击“保存”时，直接修改的就是这张表中的 `training_days` 字段。                                         | **源头 (Source)**<br>随时可变，教练拥有完全控制权。                                         |
| **2. 学员看到的计划** | **视情况而定**                 | **未开始时**：直接读取 `coach_plan_instances` (与教练完全同步)。<br>**进行中时**：读取 `plan_instance_executions` 中的快照 (**不同步**)。 | **混合态**<br>学员点击“开始训练”的一瞬间，数据从表1复制到表3，此后学员看到的就是表3的数据。 |
| **3. 执行记录**       | **`plan_instance_executions`** | 存储具体的执行数据（实际重量、视频、RPE等）。包含 `status` 字段 ('in_progress' 或 'completed')。                                          | **快照 (Snapshot)**<br>一旦生成，就与母版断开连接。 'completed' 状态下即为历史档案。        |

---

## 2. 为什么觉得“不同步”？

您提到的核心矛盾点在于：**“学员的计划理应和教练的编辑页面是时刻同步的”**。

目前的系统实现中，存在一个**“快照断层”**：

1. **场景：学员还未点击“开始”**
   - **同步状态**：✅ **完全同步**。
   - 学员看到的卡片直接渲染自
     `coach_plan_instances`。教练一改，学员刷新页面就能看到。

2. **场景：学员点击了“开始”（或者仅仅点进去预览生成了待办记录）**
   - **同步状态**：❌ **断开连接**。
   - 系统为了记录学员填写的实际重量，必须创建一个 `plan_instance_executions`
     记录。
   - **关键点**：这个记录不仅仅包含用户填写的空位，还**复制**了当时计划里的推荐重量（例如
     50kg）。
   - 此时，针对**这一天**的训练，学员端看到的数据源变成了
     `plan_instance_executions`。
   - 如果教练随后把母版改成了 60kg，因为系统没有去刷新已经在进行中的
     `plan_instance_executions`，学员看到的依然是 50kg。

## 3. 您的两个核心疑问解答

### Q1: 教练编辑器的计划存在哪里？

**A**: 存在 `coach_plan_instances`
表中。编辑器中的“自动计算重量”是在前端通过读取问卷计算，然后把算出来的结果（如
85kg）直接存进这个表里。

### Q2: 为什么 PR 进步不触发教练端更新？

**A**:
因为教练编辑器在计算重量时，**只读取了问卷表**（Questionnaire），而没有去读取
**PR 历史表**（Personal Records）。这是一个逻辑缺陷，导致即便 PR
表里有新纪录，编辑器也“看不见”。

---

## 4. 总结

- **理想状态**：教练修改母版 ->
  所有未完成的学员视图（包括进行中的）全部同步更新。
- **当前现状**：教练修改母版 ->
  只有“未开始”的训练日会更新；“进行中”的训练日因为读取的是旧快照，所以不会更新。

您理解得非常正确：**学员的计划（在未完成变成历史档案前）理应保持同步**。目前的“快照机制”导致了体验上的割裂。
